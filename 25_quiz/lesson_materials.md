  > **Преподаватель:** «Где же лежат данные сессии? Запомните: куки — маленькие. Передавать в куках весь профиль пользователя не только медленно (куки летают с каждым HTTP-запросом), но и небезопасно. Браузер хранит лишь сессионный ключ. * **Раунд 3 (Вопрос 4 - Шаблоны):**

Символ `<` заменяется на `&lt;`, а `>` на `&gt;`. Браузер видит эти спецсимволы и выводит их как обычный текст, не интерпретируя как HTML-тег. Это критически важно для защиты от XSS (Cross-Site Scripting). Это называется Lazy Evaluation (ленивые вычисления). Django накапливает фильтры и строит один сложный SQL-запрос. Запрос отправляется только в момент обращения к элементам (в данном случае, при взятии первого элемента через `[0]`). Будет выполнен ровно один запрос с `LIMIT 1`. Правильный ответ — В.»
* **Раунд 5 (Вопрос 3 - SQL-инъекция):**
  > **Преподаватель:** «Почему вариант В опасен? В нем мы используем f-строку `f"... '{user_input}'"`. Если пользователь введет `admin' --`, наш запрос превратится в `SELECT * FROM book WHERE title = 'admin' --'`. Два дефиса в SQL означают комментарий, который отбросит всю последующую логику авторизации или проверок. Вариант Б безопасен, так как плейсхолдер `%s` передается СУБД отдельно от текста запроса, и СУБД экранирует его сама. Никогда не используйте форматирование строк для SQL-запросов!»

#### Скрипт автоматизации подсчета результатов
Скрипт `score_calculator.py` помогает быстро выявить победителя с учетом тай-брейка.

```python
# score_calculator.py
# Скрипт для автоматизации подсчета результатов веб-квиза на ЛФМШ "Квант"
# Совместим с Python 3.12+

import json
from typing import Dict, List, Tuple

# Структура данных для хранения результатов команд
# Ключ - название команды
# Значение - словарь с баллами по раундам (1-5) и тай-брейку (tb)
teams_data = {
    "Сверхпроводники": {"R1": 4, "R2": 3, "R3": 5, "R4": 4, "R5": 4, "TB": 2},
    "Синтаксический Сахар": {"R1": 5, "R2": 4, "R3": 4, "R4": 3, "R5": 5, "TB": 1},
    "Декораторы Кванта": {"R1": 3, "R2": 5, "R3": 5, "R4": 5, "R5": 3, "TB": 3},
    "Багфиксеры": {"R1": 4, "R2": 4, "R3": 3, "R4": 4, "R5": 4, "TB": 2}
}

def calculate_results(data: Dict[str, Dict[str, int]]) -> List[Tuple[str, int, int]]:
    """
    Рассчитывает сумму баллов для каждой команды.
    Возвращает отсортированный список кортежей: (Название команды, Сумма основных раундов, Балл тай-брейка).
    Сортировка идет сначала по сумме основных раундов (по убыванию),
    затем по баллам тай-брейка (по убыванию).
    """
    results = []
    for team, scores in data.items():
        # Сумма баллов по основным раундам 1-5
        main_score = sum(scores[r] for r in ["R1", "R2", "R3", "R4", "R5"])
        tb_score = scores.get("TB", 0)
        results.append((team, main_score, tb_score))
    
    # Сортировка: основной балл приоритетнее, тай-брейк - вспомогательный
    results.sort(key=lambda x: (x[1], x[2]), reverse=True)
    return results

def print_leaderboard(leaderboard: List[Tuple[str, int, int]]):
    print("=" * 60)
    print(f"{'ТАБЛИЦА ЛИДЕРОВ КВИЗА ПО ВЕБ-РАЗРАБОТКЕ':^60}")
    print("=" * 60)
    print(f"{'Место':<6} | {'Название команды':<25} | {'Осн. раунды':<12} | {'Тай-брейк':<10}")
    print("-" * 60)
    
    for idx, (team, main, tb) in enumerate(leaderboard, start=1):
        # Выделяем победителя
        medal = "🏆" if idx == 1 else "🥈" if idx == 2 else "🥉" if idx == 3 else f" {idx}."
        print(f"{medal:<6} | {team:<25} | {main:<12} | {tb:<10}")
    
    print("=" * 60)

if __name__ == "__main__":
    leaderboard = calculate_results(teams_data)
    print_leaderboard(leaderboard)
```

**Объяснение работы кода:**
* Строка 10: Словарь `teams_data` содержит исходные баллы, внесенные жюри.
* Строка 19: Функция `calculate_results` осуществляет агрегацию данных. Она использует генератор списков для суммирования баллов раундов с R1 по R5.
* Строка 29: Применяется метод `.sort()` с использованием лямбда-функции `key=lambda x: (x[1], x[2])`. Это стандартный паттерн в Python для многокритериальной сортировки: сначала элементы сравниваются по индексу `1` (основной балл), а при равенстве — по индексу `2` (балл тай-брейка). Параметр `reverse=True` обеспечивает сортировку от лучшего к худшему.
* Строка 33: Функция `print_leaderboard` выводит форматированную ASCII-таблицу с использованием спецификаторов выравнивания (`:<6`, `:<25`).

### 7. Интерактивные упражнения и задачи для квиза
Для командного выполнения во время занятия предлагаются следующие 6 задач-головоломок.

#### Задача 1 (Базовый уровень): CSS Селекторная битва
* **Условие:** Напишите самый короткий CSS-селектор, который выберет только ссылки `<a>` с классом `.active`, находящиеся внутри элемента списка `<li>`, который является непосредственным потомком списка `<ul>` с классом `.menu`.
* **Входные данные (HTML):**
  ```html
  <ul class="menu">
    <li><a class="active" href="#">Выбери меня!</a></li>
    <li><div><a class="active" href="#">Не меня</a></div></li>
  </ul>
  ```
* **Ожидаемый ответ:** `ul.menu > li > a.active` или `.menu > li > .active`
* **Подсказка:** Обратите внимание на требование «непосредственный потомок». Для этого используется дочерний селектор `>`.
* **Решение:** `.menu > li > a.active` (21 символ) или `.menu > li > .active` (18 символов).
* **Объяснение:** Селектор `.menu > li` гарантирует, что мы выбираем `li` только первого уровня вложенности (прямой потомок `ul.menu`), а `> .active` или `> a.active` находит саму активную ссылку, исключая ссылку во втором пункте, обернутую в `div`.

#### Задача 2 (Базовый уровень): Ленивое булево сокращение
* **Условие:** В Python булевы операторы `and` и `or` являются ленивыми (короткозамкнутыми). Что вернет выражение в Django-шаблоне при рендеринге: `{{ value1 or value2 }}` и аналогично в Python-коде view: `result = x or y`, если `x = []`, а `y = [1, 2, 3]`?
* **Входные данные:** `x = []` (пустой список), `y = [1, 2, 3]` (непустой список).
* **Ожидаемый вывод:** `[1, 2, 3]`
* **Подсказка:** Пустой список `[]` приводится к булевому типу `False`. Оператор `or` возвращает первый истинный операнд или последний операнд, если все ложны.
* **Решение:** Выражение вернет сам объект `[1, 2, 3]`.
* **Объяснение:** В Python оператор `or` не возвращает строго `True`/`False`. Он оценивает первый операнд `x`. Так как `bool([])` равен `False`, интерпретатор переходит к оценке `y`. Поскольку это последний операнд, оператор возвращает его значение целиком, то есть список `[1, 2, 3]`.

#### Задача 3 (Базовый уровень): HTTP-конструктор
* **Условие:** Соберите из фрагментов корректный стартовый заголовок HTTP-запроса от клиента, который хочет отправить данные формы (метод POST) на адрес `/submit-form/` по протоколу HTTP/1.1.
* **Фрагменты:**
  1. `HTTP/1.1`
  2. `/submit-form/`
  3. `POST`
* **Ожидаемый ответ:** `POST /submit-form/ HTTP/1.1`
* **Подсказка:** Структура стартовой строки HTTP-запроса: `[МЕТОД] [URI] [ВЕРСИЯ_ПРОТОКОЛА]`.
* **Решение:** `POST /submit-form/ HTTP/1.1`
* **Объяснение:** Согласно спецификации HTTP, первая строка запроса обязана содержать метод (глагол), затем путь к ресурсу (URI) и версию протокола, разделенные одиночными пробелами.

#### Задача 4 (Средний уровень): Детектив ORM: Охота на N+1
* **Условие:** Ниже приведен код представления, выводящего список комментариев и имена авторов к ним. Найдите уязвимость производительности (N+1) и исправьте ее с помощью методов оптимизации Django QuerySet.
* **Входной код:**
  ```python
  # views.py
  def comments_list(request):
      comments = Comment.objects.filter(is_spam=False)
      # В шаблоне: {% for c in comments %}{{ c.author.username }}{% endfor %}
      return render(request, 'comments.html', {'comments': comments})
  ```
* **Ожидаемый ответ (оптимизированный QuerySet):** `Comment.objects.filter(is_spam=False).select_related('author')`
* **Подсказка:** Связь комментария с автором — это `ForeignKey` (один-ко-многим). Для оптимизации прямых связей используйте жадную загрузку через SQL JOIN.
* **Решение:**
  ```python
  comments = Comment.objects.filter(is_spam=False).select_related('author')
  ```
* **Объяснение:** Без `select_related('author')` Django сначала сделает 1 запрос для получения всех комментариев. Затем для каждого из N комментариев при обращении к `c.author` во время рендеринга шаблона будет выполняться отдельный SQL-запрос `SELECT ... FROM user WHERE id = ...`. Добавление `select_related` делает один сложный запрос со SQL `INNER JOIN` или `LEFT OUTER JOIN`, загружая данные авторов сразу.

#### Задача 5 (Средний уровень): Лабиринт Middleware
* **Условие:** В проекте настроены три кастомных Middleware. Каждое из них выводит в консоль свое имя при обработке запроса (request) и ответа (response). В каком порядке выведутся строки в консоли при обработке одного входящего запроса?
* **Конфигурация:**
  ```python
  MIDDLEWARE = [
      'middleware.FirstMiddleware',
      'middleware.SecondMiddleware',
      'middleware.ThirdMiddleware',
  ]
  ```
* **Ожидаемый вывод:**
  ```text
  First Request
  Second Request
  Third Request
  Third Response
  Second Response
  First Response
  ```
* **Подсказка:** Вспомните структуру луковицы (onion architecture), по которой работают промежуточные слои в Django.
* **Решение:** Запрос идет сверху вниз по списку настроек, а ответ поднимается снизу вверх.
* **Объяснение:** Каждый запрос проходит через `FirstMiddleware` -> `SecondMiddleware` -> `ThirdMiddleware`, доходит до view, генерируется ответ, который затем возвращается обратно: `Third` -> `Second` -> `First`.

#### Задача 6 (Сложный уровень): Симулятор CSRF-токена
* **Условие:** Реализуйте на чистом Python функцию `verify_csrf(request_token, cookie_token)`, имитирующую упрощенную работу защиты Django от межсайтовой подделки запросов (Double Submit Cookie). Функция должна возвращать `True`, если токены совпадают, и `False` в противном случае. Усложнение: в Django токены маскируются с помощью соли для защиты от атак типа BREACH. Напишите версию проверки, предполагая, что токены передаются в простом незамаскированном виде, но с защитой от атак по времени (timing attacks) с помощью безопасного сравнения.
* **Входные данные:** Две строки (токен из формы и токен из куки).
* **Ожидаемый вывод:** `True` или `False`.
* **Подсказка:** Для безопасного сравнения строк во избежание утечек по времени используйте стандартную библиотеку `secrets.compare_digest`.
* **Решение:**
  ```python
  import secrets

  def verify_csrf(request_token: str, cookie_token: str) -> bool:
      if not request_token or not cookie_token:
          return False
      # Безопасное сравнение строк за константное время
      return secrets.compare_digest(request_token, cookie_token)
  ```
* **Объяснение:** Обычный оператор `==` сравнивает строки посимвольно и завершает работу сразу при первом несовпадении. Это позволяет злоумышленнику по времени отклика сервера угадать токен символ за символом (timing attack). Функция `secrets.compare_digest` сравнивает строки за одинаковое время независимо от того, в каком месте произошло несовпадение.

### 9. Часто задаваемые вопросы (FAQ)
1. **В: Почему CSS-селектор `#id` всегда сильнее, чем класс `.class`?**
   * *О:* Так определено спецификацией W3C. Идентификаторы уникальны для страницы, поэтому браузер отдает им больший приоритет. В числовом выражении вес ID равен `(1, 0, 0)`, а класса — `(0, 1, 0)`.
2. **В: Что делает директива `box-sizing: border-box`?**
   * *О:* Она заставляет браузер включать `padding` и `border` в общую ширину (`width`) и высоту (`height`) элемента, облегчая расчеты адаптивной сетки.
3. **В: Зачем нужны методы HTTP `PUT` и `PATCH`, если есть `POST`?**
   * *О:* Они семантически разделяют операции: `PUT` заменяет ресурс целиком, `PATCH` обновляет только часть полей, а `POST` создает новый ресурс.
4. **В: В чем разница между Cookies и Session?**
   * *О:* Cookies хранятся на стороне клиента (в браузере) в виде текстовых пар ключ-значение. Session хранится на сервере, а клиент получает только уникальный ID сессии в куках для идентификации.
5. **В: Почему Django использует паттерн MVT вместо MVC?**
   * *О:* В Django View выполняет роль контроллера (Controller), а Template — представления (View). Названия отличаются, но суть разделения ответственности сохраняется.
6. **В: Что такое контекстный процессор в Django?**
   * *О:* Это Python-функция, которая принимает объект запроса и возвращает словарь данных. Этот словарь автоматически подмешивается в контекст рендеринга всех шаблонов.
7. **В: Как `select_related` решает проблему N+1 запросов?**
   * *О:* Он делает SQL JOIN в одном запросе к базе данных, получая данные связанного объекта сразу, вместо выполнения дополнительных одиночных запросов в цикле.
8. **В: Чем `select_related` отличается от `prefetch_related`?**
   * *О:* `select_related` делает JOIN на уровне SQL (подходит для `ForeignKey` и `OneToOne`). `prefetch_related` делает дополнительный SQL-запрос и связывает объекты на уровне Python (для `ManyToManyField` и обратных связей).
9. **В: Как работает `CsrfViewMiddleware`?**
   * *О:* Оно проверяет, чтобы каждый POST-запрос содержал токен, совпадающий с токеном из куки пользователя. Это гарантирует, что запрос отправлен с вашего оригинального сайта, а не со стороннего вредоносного ресурса.
10. **В: Что такое CORS и зачем он нужен?**
    * *О:* CORS (Cross-Origin Resource Sharing) — механизм безопасности браузера, управляющий доступом скриптов с одного домена к ресурсам другого домена. Без его настройки браузер заблокирует чтение API-ответов на фронтенде.
11. **В: Зачем нужен Gunicorn, если у Django есть `runserver`?**
    * *О:* `runserver` медленный, однопоточный и создан только для разработки. Gunicorn — это WSGI-сервер промышленного уровня, запускающий несколько рабочих процессов (workers) для обработки множества параллельных запросов.

### 10. Методические заметки для преподавателя

#### Трудные концепции и аналогии
* **Специфичность CSS:** Используйте аналогию с воинскими званиями. Тег — это рядовой, класс — лейтенант, ID — генерал, а `!important` — приказ министра обороны. Звания определяют, чья команда будет выполнена при конфликте приказов.
* **Проблема N+1:** Представьте, что вам нужно принести 10 книг из библиотеки. Вместо того чтобы сходить один раз и принести стопку (это `select_related`), вы идете за первой книгой, возвращаетесь, потом идете за второй, возвращаетесь, и так 10 раз. Это крайне неэффективно.
* **CSRF (Double Submit Cookie):** Аналогия с клубом закрытого типа. При входе вам дают парный браслет (один на руку, другой крепят на куртку). Охрана на каждом выходе сверяет их соответствие. Если кто-то пытается угнать вашу куртку (подделать запрос), браслеты не совпадут, и злоумышленника не выпустят.

#### Дифференциация обучения
