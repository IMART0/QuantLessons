> *"Middleware — это функции-обертки. Каждое Middleware получает объект запроса и ссылку на следующий обработчик `next_handler`.

### Демонстрация 1: Парсинг JSON-лекции лагеря и расчет времени ее окончания
**Файл:** `demo_json_datetime.py`  
**Цель:** Показать безопасный парсинг JSON-данных о лекции OpenTalk и вычисление времени окончания мероприятия с использованием `timedelta`.

```python
import json
from datetime import datetime, timedelta

# Пример JSON-строки, пришедшей на сервер сайта лагеря Квант
raw_event_json = '{"title": "OpenTalk по квантовой физике", "start_time": "2026-06-26 15:00:00", "duration_minutes": 90}'

def process_kvant_event(json_str: str) -> None:
    try:
        # 1. Десериализуем (парсим) строку в словарь Python
        event_dict = json.loads(json_str)
        print("1. Успешно распарсили JSON в словарь:", event_dict)
        
        # 2. Безопасно извлекаем время начала и парсим его в datetime
        start_str = event_dict["start_time"]
        start_dt = datetime.strptime(start_str, "%Y-%m-%d %H:%M:%S")
        print("2. Объект начала лекции:", start_dt)
        
        # 3. Рассчитываем время окончания лекции с помощью timedelta
        duration = timedelta(minutes=event_dict["duration_minutes"])
        end_dt = start_dt + duration
        print("3. Время окончания лекции:", end_dt)
        
        # 4. Превращаем результат обратно в JSON для отправки на фронтенд
        response_dict = {
            "title": event_dict["title"],
            "formatted_start": start_dt.strftime("%d.%m.%Y в %H:%M"),
            "formatted_end": end_dt.strftime("%H:%M"),
            "status": "ready"
        }
        response_json = json.dumps(response_dict, ensure_ascii=False)
        print("4. JSON-ответ для сайта:", response_json)
        
    except json.JSONDecodeError as e:
        print(f"Ошибка: Некорректный формат JSON! {e}")
    except KeyError as e:
        print(f"Ошибка: В данных отсутствует обязательное поле {e}!")
    except ValueError as e:
        print(f"Ошибка: Неверный формат даты в JSON! {e}")

# Запуск тестов демонстрации
print("--- Тест 1: Корректный запрос ---")
process_kvant_event(raw_event_json)

print("\n--- Тест 2: Ошибка в JSON синтаксисе ---")
process_kvant_event('{"title": "Сломанная лекция", "start_time": "2026-06-26 15:00:00"') # нет закрывающей скобки
```

**Построчное объяснение демонстрации 1:**
*   `import json`: Импортируем стандартный модуль Python для сериализации и десериализации данных в формат JSON.
*   `from datetime import datetime, timedelta`: Импортируем класс `datetime` (хранение даты и времени) и `timedelta` (представление временных промежутков).
*   `event_dict = json.loads(json_str)`: Преобразуем текстовую строку в словарь Python. Если строка содержит синтаксическую ошибку, бросается `json.JSONDecodeError`.
*   `start_dt = datetime.strptime(start_str, "%Y-%m-%d %H:%M:%S")`: Преобразуем текстовое представление даты из словаря в объект `datetime`. `%Y` — 4-значный год, `%m` — месяц, `%d` — день, `%H` — час (24-часовой формат), `%M` — минуты, `%S` — секунды. Если формат строки не совпадет с шаблоном, бросается `ValueError`.
*   `duration = timedelta(minutes=event_dict["duration_minutes"])`: Создаем объект интервала времени продолжительностью в 90 минут.
*   `end_dt = start_dt + duration`: Складываем объект `datetime` и `timedelta`. Результатом операции сложения является новый объект `datetime`.
*   `end_dt.strftime("%H:%M")`: Метод `strftime` форматирует объект даты-времени обратно в строку по указанному шаблону (только часы и минуты).
*   `json.dumps(response_dict, ensure_ascii=False)`: Сериализуем словарь обратно в JSON-строку. Флаг `ensure_ascii=False` необходим для сохранения русских букв в исходном кириллическом виде, предотвращая их кодирование в последовательности вида `\u0430`.

### Демонстрация 2: Декоратор регистрации маршрутов и простейший роутер
**Файл:** `demo_simple_router.py`  
**Цель:** Объяснить концепцию хранения функций-обработчиков (Views) в глобальном словаре-реестре и регистрацию через декоратор.

```python
# Глобальный реестр маршрутов сайта лагеря
CAMP_ROUTES = {}

def web_route(url_path: str):
    """Декоратор, регистрирующий функцию-представление в реестре CAMP_ROUTES."""
    def decorator(func):
        # Сохраняем ссылку на функцию по адресу URL
        CAMP_ROUTES[url_path] = func
        # Возвращаем исходную функцию неизмененной
        return func
    return decorator

# Регистрация страниц сайта Кванта с помощью декоратора
@web_route("/")
def home_view():
    return "Главная страница сайта ЛФМШ 'Квант'"

@web_route("/about/")
def about_view():
    return "Информация о физико-математической школе 'Квант' 2026"

# Функция-симулятор веб-сервера
def handle_browser_request(path: str) -> str:
    print(f"Получен запрос к адресу: {path}")
    # Проверяем, зарегистрирован ли путь в реестре
    view_function = CAMP_ROUTES.get(path)
    
    if view_function:
        # Вызываем найденную функцию
        return f"Ответ 200 OK: {view_function()}"
    else:
        return "Ответ 404 Not Found: Страница не найдена!"

# Тестируем симуляцию запросов
print(handle_browser_request("/"))
print(handle_browser_request("/about/"))
print(handle_browser_request("/non-existent/"))
```

**Построчное объяснение демонстрации 2:**
*   `CAMP_ROUTES = {}`: Инициализируем пустой словарь. Ключами будут пути URL, а значениями — сами функции Python.
*   `def web_route(url_path: str)`: Объявляем декоратор, принимающий строковый параметр `url_path`.
*   `def decorator(func)`: Внутренняя функция-обертка, которая принимает декорируемую функцию `func`.
*   `CAMP_ROUTES[url_path] = func`: Ключевой момент. В Python функции являются объектами первого класса. Мы можем сохранять ссылки на них в словари и вызывать позже.
*   `return func`: Возвращаем функцию обратно, чтобы не нарушать её работу в других частях программы.
*   `@web_route("/")`: Применяем декоратор. Как только интерпретатор доходит до определения функции `home_view`, он автоматически регистрирует её в словаре `CAMP_ROUTES` под ключом `"/"`.
*   `view_function = CAMP_ROUTES.get(path)`: Безопасно ищем функцию-обработчик по запрошенному пути. Если путь не зарегистрирован, вернется `None`.
*   `view_function()`: Вызываем функцию, на которую ссылается переменная `view_function`.

### Демонстрация 3: Безопасное хранение данных в памяти (In-Memory DB) с глубоким копированием
**Файл:** `demo_in_memory_db.py`  
**Цель:** Проиллюстрировать проблему изменения данных в памяти по ссылке и показать правильное решение через `copy.deepcopy()`.

```python
import copy

# Имитация хранилища бэкенда в оперативной памяти
MOCK_DATABASE = {
    "users": {
        1: {"id": 1, "name": "Анна", "role": "преподаватель"},
        2: {"id": 2, "name": "Иван", "role": "школьник"}
    }
}

# Плохая функция: без копирования
def get_user_bad(user_id: int) -> dict | None:
    return MOCK_DATABASE["users"].get(user_id)

# Хорошая функция: с глубоким копированием
def get_user_good(user_id: int) -> dict | None:
    user_data = MOCK_DATABASE["users"].get(user_id)
    if user_data:
        return copy.deepcopy(user_data)
    return None

# Демонстрация проблемы передачи по ссылке
print("--- Опасный метод (без deepcopy) ---")
user1 = get_user_bad(1)
print("Получили пользователя:", user1)
# Студент меняет роль в полученном словаре во внешнем коде
user1["role"] = "директор"
print("Изменили внешнюю переменную. Проверяем базу данных:")
print("Данные в БД:", MOCK_DATABASE["users"][1]) # Роль в БД изменилась сама!

# Демонстрация безопасного метода
print("\n--- Безопасный метод (с deepcopy) ---")
user2 = get_user_good(2)
print("Получили пользователя:", user2)
user2["role"] = "преподаватель"
print("Изменили внешнюю переменную. Проверяем базу данных:")
print("Данные в БД:", MOCK_DATABASE["users"][2]) # Данные в БД остались нетронутыми!
```

**Построчное объяснение демонстрации 3:**
*   `import copy`: Импортируем модуль `copy`, предоставляющий средства для поверхностного и глубокого копирования объектов.
*   `MOCK_DATABASE`: Глобальный вложенный словарь, представляющий собой базу данных в оперативной памяти.
*   `get_user_bad`: Возвращает прямую ссылку на словарь пользователя из базы данных. Любые изменения возвращенного словаря мутируют состояние базы.
*   `copy.deepcopy(user_data)`: Создает полностью независимую копию словаря `user_data`, рекурсивно копируя все вложенные структуры. Изменение копии никак не повлияет на оригинал в `MOCK_DATABASE`.

### Задача 1 (Basic): JSON-парсер расписания смены
**Формулировка:**  
Напишите функцию `parse_camp_schedule(json_data: str) -> list[dict]`, которая принимает JSON-строку с расписанием мероприятий в лагере и преобразует её в список словарей.  
Функция должна проверять корректность входных данных:
1.  Если строка не является валидным JSON, функция должна вызвать исключение `ValueError` с текстом `"Invalid JSON format"`.
2.  Для каждого мероприятия в списке должна быть проведена валидация наличия обязательных полей: `"title"` (название), `"speaker"` (имя спикера), `"start"` (время начала) и `"duration"` (продолжительность в минутах). Если хотя бы одно поле отсутствует, функция должна выбросить `KeyError` с указанием названия отсутствующего поля.

**Входные данные:**
```python
# Пример 1: Корректный JSON
valid_json = '[{"title": "OpenTalk: AI в физике", "speaker": "Дмитрий Яковлев", "start": "2026-06-26 14:00", "duration": 60}]'

# Пример 2: Отсутствует поле "speaker"

# Пример 3: Синтаксическая ошибка в JSON
corrupted_json = '[{"title": "Лекция по робототехнике" duration: 90}]'
```

**Ожидаемый результат:**
*   Для `valid_json` ➡️ Возвращает список: `[{"title": "OpenTalk: AI в физике", "speaker": "Дмитрий Яковлев", "start": "2026-06-26 14:00", "duration": 60}]`.
*   Для `broken_fields_json` ➡️ Бросает исключение `KeyError: 'speaker'`.
*   Для `corrupted_json` ➡️ Бросает исключение `ValueError: Invalid JSON format`.

**Подсказки:**
*   Используйте блок `try...except json.JSONDecodeError` для перехвата ошибок парсинга и последующего возбуждения `ValueError`.
*   Для проверки наличия обязательных полей обходите распарсенный список циклом `for` и проверяйте присутствие каждого поля через оператор `not in`.

**Решение:**
```python
import json

def parse_camp_schedule(json_data: str) -> list[dict]:
    try:
        # Парсим JSON-строку
        schedule = json.loads(json_data)
    except json.JSONDecodeError as e:
        # Если JSON поврежден, возбуждаем ValueError
        raise ValueError("Invalid JSON format") from e
        
    required_keys = ["title", "speaker", "start", "duration"]
    
    # Если на входе не список, это некорректная структура расписания
    if not isinstance(schedule, list):
        raise ValueError("Schedule must be a list of events")
        
    for event in schedule:
        for key in required_keys:
            if key not in event:
                raise KeyError(key)
                
    return schedule
```

**Построчное объяснение решения:**
*   `schedule = json.loads(json_data)`: Пытаемся преобразовать входящую строку в Python-структуру.
*   `raise ValueError("Invalid JSON format") from e`: Возбуждаем собственное исключение `ValueError`, если библиотека `json` не смогла обработать строку из-за ошибок синтаксиса.
*   `if not isinstance(schedule, list)`: Проверяем, что верхний уровень JSON представляет собой массив (в Python — список).
*   `for event in schedule`: Пробегаем по каждому мероприятию расписания.
*   `if key not in event`: Ищем отсутствие любого обязательного поля в словаре мероприятия.
*   `raise KeyError(key)`: Если поле не найдено, выбрасываем исключение `KeyError` с именем этого поля.

*   Напишите вспомогательную функцию-ключ для сортировки, которая преобразует строку даты в объект `datetime` с помощью `datetime.strptime()`.

```python
from datetime import datetime

def sort_camp_news(news_list: list[dict]) -> list[dict]:
    fmt = "%d.%m.%Y %H:%M"
    
    # Внутренняя функция-ключ для извлечения даты в виде объекта datetime
    def get_news_date(news_item: dict) -> datetime:
        return datetime.strptime(news_item["published_at"], fmt)
        
    # Сортируем список по убыванию даты
```

*   `sorted(..., key=get_news_date, reverse=True)`: Сортируем список новостей. Параметр `reverse=True` указывает на сортировку в обратном порядке (от большего/свежего к меньшему/старому).

    ```python
    [
        {"title": "Мастер-класс по робототехнике", "speaker": "Игорь Петров"},
        {"title": "Презентация проектов Кванта", "speaker": "игорь петров"}
    ]
    ```

**Подсказки:**
*   Используйте метод `.lower()` как для искомого имени спикера, так и для имени спикера в мероприятии.
*   Для безопасного извлечения имени используйте метод словаря `.get("speaker")`, который возвращает `None` при отсутствии ключа, вместо вызова по прямому индексу `["speaker"]`.

```python
def filter_events_by_speaker(events: list[dict], speaker_name: str) -> list[dict]:
    # Приводим искомый запрос к нижнему регистру
    query = speaker_name.lower()
    filtered_events = []
    
    for event in events:
        # Безопасно получаем имя спикера. Если его нет, подставляем пустую строку
        current_speaker = event.get("speaker")
        
        if current_speaker is not None:
            # Приводим имя спикера к нижнему регистру и проверяем вхождение запроса
            if query in current_speaker.lower():
                filtered_events.append(event)
                
    return filtered_events
```

*   `if current_speaker is not None`: Проверяем, что спикер у лекции вообще задан.
*   `if query in current_speaker.lower()`: Проверяем, содержится ли наш поисковый запрос (например, `"игорь"`) в имени спикера (например, `"игорь петров"`).

### Задача 4 (Medium): Хранилище участников лагеря с CRUD (User Storage)
**Формулировка:**  
Для управления личными кабинетами участников смены «Квант» напишите класс `UserStorage`, имитирующий работу таблицы базы данных в оперативной памяти.  
Класс должен сохранять состояние между вызовами и поддерживать CRUD-операции. Данные пользователей должны храниться во внутреннем словаре `_data` в формате `{user_id: user_dict}`.  
Каждый пользователь описывается словарем со следующими полями: `"username"`, `"email"`, `"role"` (например, `'student'`, `'teacher'`).

Реализуйте следующие методы класса:
1.  `create(user_data: dict) -> int`: Генерирует автоинкрементный уникальный `id` (начиная с 1), вставляет копию словаря `user_data` с добавлением сгенерированного `"id"` во внутренний словарь `_data` и возвращает этот `id`.  
    *Важно: метод не должен изменять исходный словарь `user_data`, переданный в качестве аргумента.*
2.  `read(user_id: int) -> dict | None`: Возвращает копию словаря пользователя с указанным `user_id`. Если такого пользователя нет, возвращает `None`.
3.  `update(user_id: int, updates: dict) -> bool`: Обновляет поля существующего пользователя в БД значениями из словаря `updates` (частичное обновление). Изменять поле `"id"` запрещено. Если обновление прошло успешно, возвращает `True`, если пользователь не найден — `False`.
4.  `delete(user_id: int) -> bool`: Удаляет пользователя из хранилища по его `id`. Возвращает `True` при успехе, иначе `False`.

**Входные данные & Тест:**
```python
storage = UserStorage()
uid1 = storage.create({"username": "alex", "email": "alex@kvant.ru", "role": "student"})
uid2 = storage.create({"username": "elena", "email": "elena@kvant.ru", "role": "teacher"})

print(storage.read(uid1)) 
# Ожидается: {"id": 1, "username": "alex", "email": "alex@kvant.ru", "role": "student"}

storage.update(uid1, {"email": "new_alex@kvant.ru"})
print(storage.read(uid1)) 
# Ожидается: {"id": 1, "username": "alex", "email": "new_alex@kvant.ru", "role": "student"}

storage.delete(uid2)
print(storage.read(uid2)) 
# Ожидается: None
```

**Подсказки:**
*   Используйте `copy.deepcopy()` в методах `create`, `read` и `update`. Это гарантирует полную изоляцию внутреннего состояния БД от внешних манипуляций со словарями.
*   Для автоинкремента заведите счетчик `self._next_id = 1` в конструкторе класса.
*   При обновлении очищайте переданный словарь `updates` от ключа `"id"`, если он там присутствует, с помощью метода `.pop("id", None)`.

**Решение:**
```python
import copy

class UserStorage:
    def __init__(self):
        # Внутренний словарь для хранения данных
        self._data = {}
        # Переменная автоинкремента ID
        self._next_id = 1

    def create(self, user_data: dict) -> int:
        user_id = self._next_id
        
        # Создаем глубокую копию пользовательских данных
        new_user = copy.deepcopy(user_data)
        # Добавляем первичный ключ ID
        new_user["id"] = user_id
        
        # Сохраняем во внутреннее хранилище
        self._data[user_id] = new_user
        
        # Увеличиваем счетчик для следующего пользователя
        self._next_id += 1
        return user_id

    def read(self, user_id: int) -> dict | None:
        user = self._data.get(user_id)
        if user is None:
            return None
        # Возвращаем копию, чтобы избежать мутации данных вне класса
        return copy.deepcopy(user)

    def update(self, user_id: int, updates: dict) -> bool:
        if user_id not in self._data:
            return False
            
        # Защищаем БД от изменения первичного ключа id
        clean_updates = copy.deepcopy(updates)
        clean_updates.pop("id", None)
        
        # Обновляем поля пользователя
        self._data[user_id].update(clean_updates)
        return True

    def delete(self, user_id: int) -> bool:
        if user_id not in self._data:
            return False
            
        # Удаляем ключ из словаря
        del self._data[user_id]
        return True
```

**Построчное объяснение решения:**
*   `self._data = {}`: Инициализация пустого словаря при создании экземпляра хранилища.
*   `new_user = copy.deepcopy(user_data)`: Копируем данные. Если этого не сделать, внешний код сможет изменить почту пользователя в БД без вызова метода `update`.
*   `new_user["id"] = user_id`: Присваиваем сгенерированный уникальный ID.
*   `self._next_id += 1`: Увеличиваем счетчик, чтобы гарантировать уникальность следующего ID.
*   `self._data.get(user_id)`: Безопасно извлекаем словарь пользователя. Возвращает `None`, если ID отсутствует.
*   `clean_updates.pop("id", None)`: Вырезаем ключ `"id"` из переданного словаря изменений. Если ключа нет, `.pop()` завершится без ошибок благодаря значению по умолчанию `None`.
*   `self._data[user_id].update(clean_updates)`: Используем встроенный метод словаря `.update()`, который перезаписывает переданные ключи и сохраняет те, которых не было во входящем словаре `clean_updates` (реализация патча).
*   `del self._data[user_id]`: Удаляем пользователя по ключу.

### Задача 5 (Medium): Простейший симулятор URL-роутера для сайта
**Формулировка:**  
В Django пути обрабатываются маршрутизатором (URL Conf). Напишите класс `CampSiteRouter`, который будет сопоставлять URL-адреса страниц сайта «Квант» и HTTP-методы с функциями-представлениями (Views). Роутер должен поддерживать как статические пути, так и динамические пути, содержащие один целочисленный параметр вида `<int:parameter_name>`.

Класс должен содержать следующие методы:
1.  `register(path: str, method: str = "GET")`: Декоратор для регистрации функции-обработчика. Примеры путей: `"/news/"`, `"/event/<int:event_id>/"`.
2.  `resolve(path: str, method: str = "GET") -> tuple[callable, dict]`: Принимает путь запроса и HTTP-метод.
    *   Выполняет сопоставление путей. При поиске динамический параметр `<int:parameter_name>` должен подходить под любое целое число в реальном URL.
    *   При совпадении возвращает кортеж из `(функция-обработчик, словарь_распарсенных_параметров)`. Например, для пути `"/event/15/"` вернет `(view_function, {"event_id": 15})`.
    *   Если путь совпадает, но HTTP-метод не совпадает, генерирует исключение `PermissionError("Method Not Allowed")`.
    *   Если путь не найден в списке зарегистрированных маршрутов вообще, генерирует исключение `KeyError("Route Not Found")`.

*Подсказка: Для сопоставления путей избавьтесь от крайних слэшей, разбейте строки по символу `/` на сегменты и сравнивайте списки сегментов поэлементно.*

**Входные данные & Тест:**
```python
router = CampSiteRouter()

@router.register("/news/", "GET")
def get_news_list():
    return "Список новостей смены"

@router.register("/event/<int:event_id>/", "GET")
def get_event_detail(event_id):
    return f"Детали мероприятия №{event_id}"

# Тестируем сопоставление
handler, params = router.resolve("/event/42/", "GET")
print(handler(**params)) 
# Ожидается: "Детали мероприятия №42"

try:
    router.resolve("/event/42/", "POST")
except PermissionError as e:
    print(e) 
    # Ожидается: "Method Not Allowed"
```

**Решение:**
```python
class CampSiteRouter:
    def __init__(self):
        # Храним маршруты в виде списка кортежей: (список_сегментов, метод, функция)
        self.routes = []

    def register(self, path: str, method: str = "GET"):
        # Очищаем путь от слэшей по краям и разбиваем по '/'
        # Фильтруем пустые элементы
        path_parts = [part for part in path.strip("/").split("/") if part]
        
        def decorator(func):
            self.routes.append((path_parts, method.upper(), func))
            return func
        return decorator

    def resolve(self, path: str, method: str = "GET") -> tuple[callable, dict]:
        method = method.upper()
        # Разбиваем входящий путь запроса на сегменты
        request_parts = [part for part in path.strip("/").split("/") if part]
        
        path_matched = False
        
        for route_parts, route_method, handler in self.routes:
            # Если количество сегментов не совпадает, маршрут не подходит
            if len(route_parts) != len(request_parts):
                continue
                
            params = {}
            match = True
            
            # Посегментное сравнение шаблона и реального запроса
            for r_part, req_part in zip(route_parts, request_parts):
                # Проверяем, является ли сегмент динамическим числовым параметром
                if r_part.startswith("<int:") and r_part.endswith(">"):
                    # Вырезаем имя параметра, например, 'event_id' из '<int:event_id>'
                    param_name = r_part[5:-1]
                    try:
                        # Пробуем привести сегмент к целому числу
                        params[param_name] = int(req_part)
                    except ValueError:
                        match = False
                        break
                # Для статических сегментов проверяем полное строковое совпадение
                elif r_part != req_part:
                    match = False
                    break
            
            if match:
                path_matched = True
                # Если совпал путь, проверяем HTTP-метод
                if route_method == method:
                    return handler, params
                    
        if path_matched:
            raise PermissionError("Method Not Allowed")
            
        raise KeyError("Route Not Found")
```

**Построчное объяснение решения:**
*   `path_parts = [part for part in path.strip("/").split("/") if part]`: Метод `strip("/")` удаляет ведущие и закрывающие слэши (превращает `"/news/"` в `"news"`). Метод `split("/")` разбивает путь на сегменты. Условие `if part` отсекает лишние пустые сегменты при двойных слэшах.
*   `self.routes.append(...)`: Добавляем в реестр кортеж, содержащий шаблон пути в виде списка, метод в верхнем регистре и саму функцию-обработчик.
*   `len(route_parts) != len(request_parts)`: Быстрая проверка на несоответствие длины. Пути `"/news/"` и `"/news/12/"` имеют разное число сегментов (1 и 2 соответственно) и не могут совпасть.
*   `zip(route_parts, request_parts)`: Итерируемся по парам сегментов.
*   `r_part.startswith("<int:")`: Определяем шаблон динамического числового параметра.
*   `param_name = r_part[5:-1]`: Срезом вытаскиваем имя переменной. Индекс `5` обрезает префикс `<int:`, а `-1` убирает закрывающую скобку `>`.
*   `params[param_name] = int(req_part)`: Пробуем привести сегмент пути запроса к числу. Если там не число (например, `"/event/abcd/"`), сработает `ValueError`, флаг совпадения `match` сбросится в `False` и цикл прервется.
*   `raise PermissionError("Method Not Allowed")`: Если структура пути совпала, но в реестре не нашлось совпадения по методу запроса.

### Задача 6 (Hard): Конвейер обработки запросов с Middleware для сайта лагеря
**Формулировка:**  
Объедините предыдущие наработки и создайте класс-симулятор веб-приложения `WebApplication`, который управляет обработкой HTTP-запросов на сайте летней школы «Квант».  
Класс должен включать экземпляр роутера `CampSiteRouter` (из задачи 5) и список `middlewares` (функций-посредников).

**Как устроены Middleware (посредники):**  
Каждое Middleware — это функция со следующей сигнатурой:  
`def middleware_func(request: dict, next_handler: callable) -> dict`
*   `request` — словарь запроса с ключами: `"path"` (путь), `"method"` (HTTP-метод), `"headers"` (словарь заголовков), `"body"` (тело запроса в виде словаря или строки).
*   `next_handler` — функция, которую нужно вызвать для передачи запроса на обработку следующему звену в конвейере.
*   Посредник может изменить `request`, выполнить действия до и после вызова `next_handler(request)`.
*   Посредник может прервать обработку и вернуть ответ досрочно, не вызывая `next_handler` (например, при ошибке авторизации).

Ответ веб-приложения всегда должен быть словарем вида: `{"status_code": int, "headers": dict, "body": str | dict}`.

**Вам необходимо реализовать:**
1.  Класс `WebApplication` с методами:
    *   `add_middleware(middleware_func)`: Добавляет функцию-посредник в конвейер.
    *   `handle_request(request: dict) -> dict`: Запускает цепочку вызовов Middleware, на конце которой находится ядро приложения (сопоставление пути через роутер и вызов View).  
        Метод должен безопасно перехватывать ошибки роутера и возвращать стандартные ответы:
        *   При `KeyError` (путь не найден) ➡️ Возвращать ответ со статусом `404` и телом `{"error": "Not Found"}`.
        *   При `PermissionError` (метод не поддерживается) ➡️ Возвращать ответ со статусом `405` и телом `{"error": "Method Not Allowed"}`.
2.  Два Middleware-посредника:
    *   `logging_middleware(request, next_handler)`: Выводит в консоль строку вида `"[REQ] GET /news/ Received"` перед вызовом обработчика и строчку `"[RES] Status 200"` после получения ответа от следующего звена.
    *   `auth_middleware(request, next_handler)`: Проверяет наличие заголовка `"Authorization"` в `request["headers"]`. Если заголовок равен `"Bearer kvant_secret_key"`, запрос передается дальше. Иначе обработка прерывается, и сразу возвращается ответ со статусом `401` и телом `{"error": "Unauthorized"}`.

**Входные данные & Интеграционный тест:**

**Решение:**
```python
class WebApplication:
    def __init__(self):
        # Инициализируем собственный роутер
        self.router = CampSiteRouter()
        # Список зарегистрированных посредников
        self.middlewares = []

    def add_middleware(self, middleware_func: callable):
        self.middlewares.append(middleware_func)

    def handle_request(self, request: dict) -> dict:
        # Финальный обработчик ядра приложения
        def core_handler(req: dict) -> dict:
            try:
                # Находим View и извлекаем параметры URL
                handler, path_params = self.router.resolve(req["path"], req["method"])
                # Вызываем View, распаковывая параметры в именованные аргументы
                response = handler(**path_params)
                
                # Если View вернула обычную строку, оборачиваем в стандартный HTTP-ответ
                if isinstance(response, str):
                    return {
                        "status_code": 200,
                        "headers": {},
                        "body": response
                    }
                return response
                
            except KeyError:
                return {
                    "status_code": 404,
                    "headers": {},
                    "body": {"error": "Not Found"}
                }
            except PermissionError:
                return {
                    "status_code": 405,
                    "headers": {},
                    "body": {"error": "Method Not Allowed"}
                }
            except Exception as e:
                return {
                    "status_code": 500,
                    "headers": {},
                    "body": {"error": f"Internal Server Error: {str(e)}"}
                }

        # Рекурсивная сборка цепочки вызовов Middleware
        def build_chain(index: int):
            # Если дошли до конца списка, возвращаем финальное ядро
            if index == len(self.middlewares):
                return core_handler
                
            current_middleware = self.middlewares[index]
            # Возвращаем лямбду, связывающую текущий middleware со следующим звеном
            return lambda req: current_middleware(req, build_chain(index + 1))

        # Собираем конвейер, начиная с первого (индекс 0) middleware
        pipeline = build_chain(0)
        # Запускаем конвейер
        return pipeline(request)

# Реализация конкретных Middleware
def logging_middleware(request: dict, next_handler: callable) -> dict:
    print(f"[REQ] {request['method']} {request['path']} Received")
    response = next_handler(request)
    print(f"[RES] Status {response['status_code']}")
    return response

def auth_middleware(request: dict, next_handler: callable) -> dict:
    headers = request.get("headers", {})
    auth_header = headers.get("Authorization")
    
    if auth_header == "Bearer kvant_secret_key":
        # Пропускаем запрос дальше по цепочке
        return next_handler(request)
        
    # Прерываем цепочку и досрочно возвращаем ответ 401 Unauthorized
    return {
        "status_code": 401,
        "headers": {},
        "body": {"error": "Unauthorized"}
    }
```

**Построчное объяснение решения:**
*   `def core_handler(req: dict)`: Внутренняя функция-замыкание, которая представляет собой ядро системы. Вызывается только после прохождения всех слоев Middleware.
*   `handler(**path_params)`: Распаковка словаря в аргументы. Если `path_params` равен `{"user_id": 1}`, то запись преобразуется в `handler(user_id=1)`.
*   `except KeyError` / `except PermissionError`: Перехватываем исключения роутера, чтобы сформировать корректные HTTP-ответы со статусами 404 и 405.
*   `build_chain(index)`: Рекурсивный сборщик конвейера.
*   `lambda req: current_middleware(req, build_chain(index + 1))`: Возвращаем безымянную функцию, которая при вызове выполнит текущий Middleware, передав ему в качестве второго параметра `next_handler` функцию следующего Middleware (или `core_handler`).
*   `pipeline = build_chain(0)`: Точка входа в собранный конвейер.
*   `auth_middleware`: Если токен неверен, метод `next_handler` не вызывается. Происходит досрочный возврат. Цепочка обработки прерывается.

## 9. Часто задаваемые вопросы (FAQ)

### 1. В чем разница между JSON-строкой и словарем в Python?
JSON — это текстовый формат передачи данных. Он представляет собой обычную строку. Словарь в Python (`dict`) — это структура данных в оперативной памяти компьютера (хэш-таблица). Мы парсим JSON в словарь для удобной работы с ключами в коде Python и сериализуем словарь обратно в JSON-строку для отправки по сети.

### 2. Почему в JSON нельзя использовать одинарные кавычки?
Стандарт JSON строго требует использования двойных кавычек (`"`) для обозначения строковых значений и ключей объектов. Использование одинарных кавычек (`'`) приведет к ошибке `json.JSONDecodeError` на этапе парсинга.

### 3. Зачем оборачивать `json.loads` в блок `try-except`?
Браузер или стороннее приложение могут прислать некорректно сформированную строку (например, обрезанную при сбое связи). Если не обработать исключение `json.JSONDecodeError`, программа аварийно завершится, что в реальном веб-приложении приведет к падению сервера.

### 4. Что такое `timedelta` и для чего он используется?
`timedelta` — это класс из модуля `datetime`, представляющий длительность (разницу между двумя моментами времени). С его помощью можно прибавлять или вычитать часы, минуты и дни из объектов `datetime` (например, вычислять время окончания лекции).

### 5. Почему в InMemoryDB так важно использовать `copy.deepcopy()`?
В Python словари передаются по ссылке. Если мы запишем переданный в метод `create` словарь напрямую во внутреннюю переменную класса базы данных, то при изменении полей этого словаря во внешнем коде данные изменятся и внутри базы данных. Глубокое копирование копирует все вложенные элементы и полностью изолирует базу данных от внешнего вмешательства.

### 6. Зачем в Python проверять булевы переменные как `is True` вместо `== True`?
Оператор `is` проверяет идентичность объектов в памяти (ссылаются ли они на одну ячейку), а `==` сравнивает значения. Булевы константы `True` и `False` являются синглтонами в Python (существуют в единственном экземпляре). Проверка `is True` работает быстрее и соответствует правилам стиля PEP 8.

### 7. Что делает синтаксис `**path_params` при вызове функции?
Это синтаксис распаковки словаря в именованные аргументы (kwargs). Если `path_params` равен `{"event_id": 5}`, то вызов `handler(**path_params)` эквивалентен вызову `handler(event_id=5)`. Это позволяет передавать динамические параметры из URL прямо в аргументы функции.

### 8. Как работает цепочка Middleware?
Каждый посредник (Middleware) получает объект запроса и ссылку на следующий обработчик `next_handler`. Вызывая `next_handler(request)`, посредник передает управление дальше по цепочке. Если Middleware обнаруживает ошибку (например, неверный токен), оно не вызывает `next_handler`, а сразу возвращает ответ, прерывая цепочку.

### 9. В чем разница между методами `strip` и `split` при парсинге URL?
Метод `.strip("/")` удаляет слэши на концах строки (превращает `"/news/"` в `"news"`), чтобы избежать появления пустых элементов в начале и конце списка. Метод `.split("/")` нарезает очищенную строку по символу `/` на список отдельных сегментов.

### 10. Как обработать ситуацию, когда во View возникает непредвиденная ошибка?
В классе `WebApplication` в методе `core_handler` мы обернули вызов View в общий блок `try...except Exception as e:`. Если в кодовой базе View произойдет деление на ноль или другая ошибка, приложение перехватит её и вернет стандартный ответ со статусом `500 Internal Server Error`, предотвратив падение всего веб-сервера.

## 10. Методические заметки

### Сложные концепции и их объяснение (Аналогии)
*   **Декораторы регистрации путей (URL-Routing):**
    *   *Сложность:* Школьникам 7-10 классов трудно понять, как декоратор `@router.register` привязывает путь к функции без явного вызова функции в коде.
    *   *Аналогия:* Представьте школьный рассыльщик писем. Декоратор — это почтальон, который вешает на кабинеты таблички. Когда мы вешаем табличку `@router.register("/chemistry/")` на кабинет химии, мы говорим почтальону: *"Если придет письмо на адрес /chemistry/, неси его сюда"*. Саму химию (вызов функции) мы в этот момент не проводим, мы просто настраиваем маршруты на будущее.
*   **Конвейер Middleware (Посредники):**
    *   *Сложность:* Рекурсивная сборка цепочки функций через `lambda` и передача `next_handler` вызывает трудности восприятия.
    *   *Аналогия:* Представьте проходную в лагере «Квант». Запрос — это вожатый, который хочет войти. Первый кордон (Middleware 1) — измерение температуры. Если температура в норме, дежурный передает его следующему сотруднику (`next_handler`). Второй кордон (Middleware 2) — проверка пропуска. Если пропуск есть, его пускают на территорию (View). Если на каком-то этапе проверка провалена, вожатого разворачивают обратно (прерывание запроса).
