### Демонстрация 1: Работа с JSON и Datetime
**Цель:** Показать безопасный парсинг JSON с обработкой ошибок и вычисление разницы во времени.

```python
import json
from datetime import datetime, timedelta

# Пример JSON-строки, пришедшей от клиента
raw_payload = '{"session_start": "2026-06-26 12:00:00", "duration_minutes": 90}'

def process_session(json_data: str) -> None:
    try:
        # Шаг 1: Десериализация (парсинг строки в словарь)
        data = json.loads(json_data)
        print("1. Данные успешно распарсены:", data)
        
        # Шаг 2: Извлечение и парсинг даты
        start_str = data["session_start"]
        # strptime: преобразуем строку в datetime по шаблону
        start_time = datetime.strptime(start_str, "%Y-%m-%d %H:%M:%S")
        print("2. Объект datetime начала сессии:", start_time)
        
        # Шаг 3: Арифметика дат с использованием timedelta
        duration = timedelta(minutes=data["duration_minutes"])
        end_time = start_time + duration
        print("3. Время окончания сессии:", end_time)
        
        # Шаг 4: Сериализация обратно в строку для ответа
        # strframe: форматируем объект datetime в строку
        response_data = {
            "status": "scheduled",
            "ends_at": end_time.strftime("%d.%m.%Y в %H:%M")
        }
        json_response = json.dumps(response_data, ensure_ascii=False)
        print("4. JSON-ответ для клиента:", json_response)
        
    except json.JSONDecodeError as e:
        print(f"Ошибка: Некорректный формат JSON! {e}")
    except KeyError as e:
        print(f"Ошибка: Отсутствует обязательное поле {e}!")
    except ValueError as e:
        print(f"Ошибка: Неверный формат даты! {e}")

# Тест демонстрации
process_session(raw_payload)
# Тест с ошибкой JSON
process_session('{"session_start": "2026-06-26 12:00:00",')
```

**Объяснение кода по строкам:**
*   `import json`: импортируем встроенный модуль для работы с JSON.
*   `from datetime import datetime, timedelta`: импортируем класс работы с датой/временем и класс для работы с временными интервалами.
*   `try...except`: критически важная конструкция. В вебе мы обязаны ловить все возможные исключения парсинга, иначе любая опечатка пользователя уронит весь сервер.
*   `json.loads(json_data)`: преобразует строку JSON в стандартный словарь Python.
*   `datetime.strptime(...)`: первый аргумент — строка с датой, второй — строка формата. `%Y` — 4-значный год, `%m` — месяц, `%d` — день, `%H`, `%M`, `%S` — часы, минуты, секунды соответственно.
*   `timedelta(minutes=...)`: создает временной сдвиг. Поддерживает аргументы `days`, `seconds`, `microseconds`, `milliseconds`, `minutes`, `hours`, `weeks`.
*   `start_time + duration`: операция сложения объекта `datetime` и `timedelta` возвращает новый объект `datetime`.
*   `end_time.strftime(...)`: форматирует дату в красивый человекочитаемый вид (например, `26.06.2026 в 13:30`).
*   `json.dumps(...)`: преобразует словарь обратно в строку JSON. Параметр `ensure_ascii=False` отключает принудительное экранирование кириллицы (чтобы текст оставался на русском, а не в кодировке `\u0430...`).

### Демонстрация 2: Как устроен декоратор маршрутов (Роутер)
**Цель:** Объяснить концепцию регистрации функций в глобальном реестре (как это делает Django/Flask).

```python
# Глобальный реестр маршрутов (карта URL -> функции)
ROUTES_REGISTRY = {}

def route(path: str):
    """Декоратор, который регистрирует функцию-представление в глобальной карте."""
    def decorator(func):
        ROUTES_REGISTRY[path] = func
        return func
    return decorator

# Пример использования декоратора
@route("/home")
def home_page():
    return "<h1>Добро пожаловать на главную страницу!</h1>"

@route("/about")
def about_page():
    return "<h1>О проекте Квант</h1>"

# Симуляция работы роутера при запросе от браузера
def simulate_request(url: str) -> str:
    print(f"\nЗапрос на URL: {url}")
    # Поиск обработчика в реестре
    handler = ROUTES_REGISTRY.get(url)
    if handler:
        # Вызов найденной функции
        return handler()
    return "404 Not Found: Страница не существует"

# Проверка работоспособности
print(simulate_request("/home"))
print(simulate_request("/about"))
print(simulate_request("/contacts"))
```

**Объяснение кода по строкам:**
*   `ROUTES_REGISTRY = {}`: обычный словарь, где ключом будет строка URL-адреса, а значением — сама ссылка на функцию Python.
*   `def route(path: str)`: декоратор, принимающий параметры. Он возвращает классический декоратор `decorator(func)`.
*   `ROUTES_REGISTRY[path] = func`: ключевой момент. Мы сохраняем переданную функцию `func` в наш словарь по ключу `path`. Функция в Python — это объект первого класса (first-class citizen), её можно сохранить в переменную, список или словарь.
*   `return func`: возвращаем исходную функцию без изменений, чтобы её можно было использовать и обычным образом.
*   `@route("/home")`: синтаксический сахар. При определении функции Python автоматически передает её в `route("/home")`.
*   `ROUTES_REGISTRY.get(url)`: безопасный поиск по словарю. Если ключ существует, вернется объект-функция, если нет — `None`.
*   `handler()`: круглые скобки вызывают функцию, на которую ссылается переменная `handler`.

### Задача 1 (Basic): Фильтрация и группировка JSON-профилей
**Формулировка:**
Напишите функцию `process_user_data(raw_json_list: list[str]) -> dict`, которая принимает список строк. Каждая строка — это JSON-документ с профилем пользователя.
Функция должна:
1. Распарсить каждую строку. Если строка содержит невалидный JSON, пропустить её и напечатать в консоль `"Warning: Invalid JSON skipped"`.
2. Отфильтровать пользователей: оставить только тех, у кого поле `"is_active"` равно `True`, а возраст `"age"` строго больше `16`.
3. Сгруппировать имена отфильтрованных пользователей по городам. Ключом результирующего словаря должен быть город (`"city"`), а значением — список имен пользователей (`"name"`), отсортированный по алфавиту.
4. Если у пользователя отсутствует поле `"city"`, соотнести его с городом `"Unknown"`. Если отсутствует поле `"name"`, `"age"` или `"is_active"`, пропустить профиль как поврежденный.

**Пример входных данных:**
```python
input_data = [
    '{"name": "Алексей", "age": 20, "city": "Москва", "is_active": true}',
    '{"name": "Иван", "age": 15, "city": "Москва", "is_active": true}',
    '{"name": "Ольга", "age": 25, "is_active": true}',  # Нет города
    '{"name": "Сергей", "age": 30, "city": "Казань", "is_active": false}',  # Неактивен
    '{"name": "Диана", "age": 18, "city": "Казань", "is_active": true}',
    '{"name": "Анна", "age": 19, "city": "Москва", "is_active": true}',
    'invalid json string here',
    '{"name": "Петр", "city": "Москва", "is_active": true}'  # Нет возраста
]
```

**Ожидаемый результат:**
```python
{
    "Москва": ["Алексей", "Анна"],
    "Unknown": ["Ольга"],
    "Казань": ["Диана"]
}
```

**Подсказки:**
*   Используйте `json.JSONDecodeError` для отлова ошибок парсинга.
*   Для группировки можно использовать обычный словарь и проверять `if city not in result: result[city] = []`.
*   Не забудьте в конце отсортировать списки имен (метод `.sort()` или функция `sorted()`).

**Решение:**
```python
import json

def process_user_data(raw_json_list: list[str]) -> dict:
    result = {}
    
    for item in raw_json_list:
        try:
            # 1. Парсинг
            user = json.loads(item)
        except json.JSONDecodeError:
            print("Warning: Invalid JSON skipped")
            continue
            
        # Проверка наличия обязательных полей
        if "name" not in user or "age" not in user or "is_active" not in user:
            continue
            
        # 2. Фильтрация
        if user["is_active"] is True and user["age"] > 16:
            # Определение города
            city = user.get("city", "Unknown")
            name = user["name"]
            
            # 3. Группировка
            if city not in result:
                result[city] = []
            result[city].append(name)
            
    # Сортировка имен в каждом городе
    for city in result:
        result[city].sort()
        
    return result
```

**Построчное объяснение решения:**
*   `result = {}`: инициализируем пустой словарь для группировки.
*   `for item in raw_json_list:`: обходим циклом входной список строк.
*   `try...except json.JSONDecodeError:`: оборачиваем вызов `json.loads` в обработчик исключений на случай невалидных строк. При ошибке выводим предупреждение и переходим к следующей итерации через `continue`.
*   `if "name" not in user or ...`: проверяем, что все ключевые поля присутствуют. Если какого-то поля нет, этот профиль некорректен, пропускаем его.
*   `if user["is_active"] is True and user["age"] > 16:`: проверяем условия фильтрации. Обратите внимание, что проверяется именно логическое `True`.
*   `city = user.get("city", "Unknown")`: используем метод `.get()`, чтобы безопасно извлечь город. Если ключа `"city"` нет, вернется дефолтное значение `"Unknown"`.
*   `result[city].append(name)`: добавляем имя в список для соответствующего города.
*   `for city in result: result[city].sort()`: после прохода по всем пользователям, сортируем списки имен по алфавиту встроенным методом `sort()`.

### Задача 2 (Basic): Пересечение бронирований отеля (Datetime)
**Формулировка:**
Для системы бронирования коворкинга напишите функцию `check_reservation_overlap(existing_reservations: list[dict], new_reservation: dict) -> tuple[bool, int]`.
Каждая бронь описывается словарем:
*   `"id"`: целое число (идентификатор брони).
*   `"room_id"`: строка (название переговорной).
*   `"start"`: строка в формате `"YYYY-MM-DD HH:MM"` (начало бронирования).
*   `"end"`: строка в формате `"YYYY-MM-DD HH:MM"` (конец бронирования).

Функция должна проверить, пересекается ли новая бронь `new_reservation` с любой из существующих в списке `existing_reservations` *для той же комнаты* (`room_id`).
**Важное правило:** Интервалы пересекаются, если они перекрываются хотя бы на одну минуту. Временной стык (одна бронь кончается в `14:00`, а следующая начинается ровно в `14:00`) **не является пересечением**.
Функция должна возвращать кортеж `(True, ID_пересекающей_брони)`, если обнаружен конфликт, или `(False, -1)`, если конфликт отсутствует.
Также, если новая бронь успешна (нет конфликта), функция должна рассчитать её длительность в полных часах (округлить вниз) и вывести в консоль строкой вида `"Успешно забронировано на N ч."`

**Пример входных данных:**
```python
existing = [
    {"id": 1, "room_id": "Альтаир", "start": "2026-06-26 10:00", "end": "2026-06-26 12:00"},
    {"id": 2, "room_id": "Вега", "start": "2026-06-26 12:00", "end": "2026-06-26 14:00"},
    {"id": 3, "room_id": "Альтаир", "start": "2026-06-26 13:00", "end": "2026-06-26 15:00"}
]

# Случай А (пересекается с id=1)
new_a = {"room_id": "Альтаир", "start": "2026-06-26 11:30", "end": "2026-06-26 12:30"}

# Случай Б (стык с id=2 на другой комнате — всё ок)
new_b = {"room_id": "Вега", "start": "2026-06-26 14:00", "end": "2026-06-26 16:30"}
```

**Ожидаемый результат:**
*   Для `new_a`: `(True, 1)`
*   Для `new_b`: `(False, -1)` (В консоли: `"Успешно забронировано на 2 ч."`)

**Подсказки:**
*   Переведите все даты-строки в объекты `datetime` с помощью `datetime.strptime(date_str, "%Y-%m-%d %H:%M")`.
*   Два временных интервала `[S1, E1]` и `[S2, E2]` пересекаются тогда и только тогда, когда `S1 < E2` и `S2 < E1`.
*   Разность дат `end - start` возвращает объект `timedelta`. Количество полных часов можно получить, переведя разность в секунды и поделив: `int(delta.total_seconds() // 3600)`.

**Решение:**
```python
from datetime import datetime

def check_reservation_overlap(existing_reservations: list[dict], new_reservation: dict) -> tuple[bool, int]:
    fmt = "%Y-%m-%d %H:%M"
    
    # Парсим даты новой брони
    new_start = datetime.strptime(new_reservation["start"], fmt)
    new_end = datetime.strptime(new_reservation["end"], fmt)
    new_room = new_reservation["room_id"]
    
    # Проверяем на конфликты
    for res in existing_reservations:
        if res["room_id"] != new_room:
            continue
            
        res_start = datetime.strptime(res["start"], fmt)
        res_end = datetime.strptime(res["end"], fmt)
        
        # Условие пересечения интервалов (без стыков)
        if new_start < res_end and res_start < new_end:
            return True, res["id"]
            
    # Если пересечений нет, рассчитываем длительность
    duration = new_end - new_start
    hours = int(duration.total_seconds() // 3600)
    print(f"Успешно забронировано на {hours} ч.")
    
    return False, -1
```

**Построчное объяснение решения:**
*   `fmt = "%Y-%m-%d %H:%M"`: определяем общую константу формата времени.
*   `datetime.strptime(...)`: преобразуем текстовые даты начала и окончания новой брони в объекты `datetime`.
*   `for res in existing_reservations:`: проходим циклом по всем имеющимся бронированиям.
*   `if res["room_id"] != new_room: continue`: если комната другая, то конфликт невозможен. Пропускаем проверку этой брони.
*   `new_start < res_end and res_start < new_end`: это элегантная математическая формула проверки пересечения отрезков. Отрезки пересекаются, если начало первого строго раньше конца второго, И начало второго строго раньше конца первого. За счет строгого сравнения `<` стыки (равенство) не засчитываются как пересечение.
*   `duration = new_end - new_start`: вычитание объектов `datetime` дает объект `timedelta`.
*   `duration.total_seconds() // 3600`: переводим разницу времени в секунды, делим нацело на `3600` (секунд в часе), получая целое число полных часов, и оборачиваем в `int`.

### Задача 3 (Basic): Валидатор HTTP-запросов (Validation)
**Формулировка:**
Реализуйте функцию `validate_registration_request(payload: dict) -> dict`, которая проверяет корректность данных в запросе на регистрацию пользователя.
Правила валидации:
1.  **Обязательные поля**: В словаре `payload` должны быть ключи `"username"`, `"email"`, `"age"`, `"password"`. Если какого-то поля нет, в словаре ошибок должна быть запись `"<поле>": "Missing field"`. Если есть отсутствующие поля, дальнейшую валидацию их значений проводить не нужно.
2.  **username**: Строка. Длина от 3 до 15 символов включительно. Должна состоять только из латинских букв и цифр (используйте метод `.isalnum()`). При нарушении ошибка: `"Username must be alphanumeric, 3-15 chars"`.
3.  **email**: Строка. Должна содержать ровно один символ `@`. После символа `@` обязательно должна быть хотя бы одна точка `.`. При нарушении ошибка: `"Invalid email format"`.
4.  **age**: Должно быть целым числом от 14 до 100 включительно. Если пришла строка (например, `"25"`), функция должна попытаться сконвертировать её в `int`. Если конвертация не удалась или число выходит за рамки диапазона, ошибка: `"Age must be an integer between 14 and 100"`.
5.  **password**: Строка. Длина не менее 8 символов. Должен содержать хотя бы одну заглавную букву (`.isupper()`), одну строчную букву (`.islower()`) и хотя бы одну цифру (`.isdigit()`). При нарушении ошибка: `"Password must be at least 8 chars, contain upper, lower and digit"`.

Функция должна возвращать словарь:
*   `"is_valid"`: `True` (если ошибок нет) или `False` (если есть хотя бы одна ошибка).
*   `"errors"`: Словарь, содержащий сообщения об ошибках. Ключи словаря — имена некорректных полей, значения — тексты ошибок (см. выше).

**Пример входных данных:**
```python
payload_ok = {
    "username": "kvant2026",
    "email": "student@kvant.ru",
    "age": "17",  # строка, но конвертируемая
    "password": "SecurePassword1"
}

payload_err = {
    "username": "ya",          # слишком короткий
    "email": "bad_email@com",  # нет точки после собаки
    "age": "seventeen",        # не конвертируется
    # password отсутствует вообще
}
```

**Ожидаемый результат:**
*   Для `payload_ok`: `{"is_valid": True, "errors": {}}`
*   Для `payload_err`:
    ```python
    {
        "is_valid": False,
        "errors": {
            "username": "Username must be alphanumeric, 3-15 chars",
            "email": "Invalid email format",
            "age": "Age must be an integer between 14 and 100",
            "password": "Missing field"
        }
    }
    ```

**Решение:**
```python
def validate_registration_request(payload: dict) -> dict:
    errors = {}
    required_fields = ["username", "email", "age", "password"]
    
    # 1. Проверяем наличие полей
    for field in required_fields:
        if field not in payload:
            errors[field] = "Missing field"
            
    # Если какое-то поле отсутствует, валидировать его значение нет смысла
    # 2. Валидация username
    if "username" not in errors:
        username = payload["username"]
        if not (isinstance(username, str) and 3 <= len(username) <= 15 and username.isalnum()):
            errors["username"] = "Username must be alphanumeric, 3-15 chars"
            
    # 3. Валидация email
    if "email" not in errors:
        email = payload["email"]
        if isinstance(email, str) and email.count("@") == 1:
            parts = email.split("@")
            # Точка должна быть во второй части (после @)
            if "." not in parts[1]:
                errors["email"] = "Invalid email format"
        else:
            errors["email"] = "Invalid email format"
            
    # 4. Валидация age
    if "age" not in errors:
        age_raw = payload["age"]
        try:
            age = int(age_raw)
            if not (14 <= age <= 100):
                errors["age"] = "Age must be an integer between 14 and 100"
        except (ValueError, TypeError):
            errors["age"] = "Age must be an integer between 14 and 100"
            
    # 5. Валидация password
    if "password" not in errors:
        password = payload["password"]
        if isinstance(password, str) and len(password) >= 8:
            has_upper = any(c.isupper() for c in password)
            has_lower = any(c.islower() for c in password)
            has_digit = any(c.isdigit() for c in password)
            if not (has_upper and has_lower and has_digit):
                errors["password"] = "Password must be at least 8 chars, contain upper, lower and digit"
        else:
            errors["password"] = "Password must be at least 8 chars, contain upper, lower and digit"
            
    return {
        "is_valid": len(errors) == 0,
        "errors": errors
    }
```

**Построчное объяснение решения:**
*   `errors = {}`: словарь для сбора ошибок. Если по итогу он пустой, запрос валиден.
*   `for field in required_fields:`: сначала ищем отсутствующие поля, занося ошибку `"Missing field"`.
*   `if "username" not in errors:`: проверяем значение только в том случае, если поле вообще было передано (его нет в списке ошибок отсутствия).
*   `username.isalnum()`: проверяет, состоит ли строка только из букв и цифр.
*   `email.split("@")`: разбиваем email на две части. Индекс `1` указывает на доменную часть после собаки. Мы проверяем, что в ней есть хотя бы одна точка.
*   `try...except (ValueError, TypeError)`: важный блок для приведения типов. Если пришла строка `"17"`, `int("17")` выполнится успешно. Если пришло `"seventeen"` или `None`, выбросится исключение, которое мы перехватим и превратим в понятную ошибку валидации.
*   `any(c.isupper() for c in password)`: генераторное выражение. Проверяет, есть ли во всей строке пароля хотя бы один символ в верхнем регистре. Аналогично для строчных букв и цифр.

### Задача 4 (Medium): Маршрутизатор URL с параметрами (Routing Mock)
**Формулировка:**
В Django пути сопоставляются с помощью шаблонов. Напишите класс `SimpleRouter`, который будет привязывать URL-адреса и HTTP-методы к функциям-обработчикам (Views), извлекая динамические целочисленные параметры.
Класс должен реализовывать:
1.  Метод `register(path: str, method: str = "GET")`: Декоратор для регистрации обработчика. Путь может быть статическим (например, `/api/users/`) или динамическим с целочисленным параметром (например, `/api/users/<int:user_id>/`).
2.  Метод `resolve(path: str, method: str = "GET") -> tuple[callable, dict]`: Принимает путь и HTTP-метод запроса.
    *   Ищет совпадение. При сравнении путей динамический параметр `<int:parameter_name>` должен подходить под любое целое число в реальном URL.
    *   При совпадении возвращает кортеж из `(функция-обработчик, словарь_распарсенных_параметров)`. Например, для зарегистрированного `/api/users/<int:user_id>/` и запроса `/api/users/42/` вернет `(handler_func, {"user_id": 42})`.
    *   Если путь совпадает, но HTTP-метод не совпадает, генерирует исключение `PermissionError("Method Not Allowed")`.
    *   Если подходящего пути не найдено вообще, генерирует исключение `KeyError("Route Not Found")`.

*Подсказка: Для простоты сопоставления путей разбивайте строки путей по символу `/` и сравнивайте части поэлементно.*

**Пример использования:**
```python
router = SimpleRouter()

@router.register("/users/", "GET")
def get_users():
    return "list of users"

@router.register("/users/<int:user_id>/", "GET")
def get_user_detail(user_id):
    return f"info about user {user_id}"
```

**Решение:**
```python
class SimpleRouter:
    def __init__(self):
        # Храним маршруты в виде списка кортежей: (разбитый_путь, метод, функция)
        # Пример: (['users', '<int:user_id>'], 'GET', get_user_detail)
        self.routes = []

    def register(self, path: str, method: str = "GET"):
        # Очищаем путь от крайних слэшей и разбиваем на сегменты
        path_parts = [p for p in path.strip("/").split("/") if p]
        
        def decorator(func):
            self.routes.append((path_parts, method.upper(), func))
            return func
        return decorator

    def resolve(self, path: str, method: str = "GET") -> tuple[callable, dict]:
        method = method.upper()
        # Разбираем входящий путь запроса
        request_parts = [p for p in path.strip("/").split("/") if p]
        
        path_matched = False
        
        for route_parts, route_method, handler in self.routes:
            # Сравниваем длину сегментов пути
            if len(route_parts) != len(request_parts):
                continue
                
            params = {}
            match = True
            
            # Посегментное сравнение
            for r_part, req_part in zip(route_parts, request_parts):
                if r_part.startswith("<int:") and r_part.endswith(">"):
                    # Извлекаем имя переменной, например 'user_id' из '<int:user_id>'
                    param_name = r_part[5:-1]
                    try:
                        # Пытаемся привести сегмент запроса к int
                        params[param_name] = int(req_part)
                    except ValueError:
                        match = False
                        break
                elif r_part != req_part:
                    match = False
                    break
            
            if match:
                path_matched = True
                if route_method == method:
                    return handler, params
                
        # Если путь совпал, но метод не подошел
        if path_matched:
            raise PermissionError("Method Not Allowed")
            
        raise KeyError("Route Not Found")
```

**Построчное объяснение решения:**
*   `[p for p in path.strip("/").split("/") if p]`: разбивает пути на логические сегменты, убирая лишние слэши. Путь `/users/42/` превратится в список `['users', '42']`.
*   `self.routes.append(...)`: сохраняет в список структуру маршрута для последующего линейного поиска.
*   `def resolve(...)`: выполняет поиск по сохраненным маршрутам.
*   `len(route_parts) != len(request_parts)`: если количество сегментов пути в шаблоне и запросе не совпадает (например, `/users/` и `/users/42/10/`), то этот маршрут сразу не подходит.
*   `zip(route_parts, request_parts)`: объединяет сегменты шаблона и запроса в пары для поэлементного сравнения.
*   `r_part.startswith("<int:")`: проверяем, является ли сегмент динамическим параметром типа `int`.
*   `param_name = r_part[5:-1]`: срезом отрезаем `<int:` (5 символов) и закрывающую угловую скобку `>`. Получаем чистое имя переменной.
*   `params[param_name] = int(req_part)`: конвертируем динамическую часть URL в число и сохраняем в словарь параметров. Если там не число (например, строка `abc` вместо ID), выбрасывается `ValueError`, совпадение аннулируется (`match = False`).
*   `elif r_part != req_part`: если сегмент статический (обычное слово), они должны совпадать символ в символ.
*   `raise PermissionError(...)`: если мы нашли совпадение по структуре пути (`path_matched = True`), но ни один обработчик не совпал по HTTP-методу, мы выбрасываем ошибку несоответствия метода.
*   `raise KeyError(...)`: если совпадений по пути не найдено вообще, выбрасываем ошибку маршрута (будущая ошибка 404).

### Задача 5 (Medium): База данных в памяти (In-Memory Database CRUD)
**Формулировка:**
Напишите класс `InMemoryDB`, который будет имитировать СУБД, хранящую документы (словари) в оперативной памяти.
База данных должна поддерживать разделение на коллекции (аналог таблиц). Данные хранятся в структуре:
`{ "название_коллекции": { id_документа: {данные_документа} } }`.
Каждый документ при сохранении получает автоинкрементный целочисленный ключ `id`.

Реализуйте следующие методы:
1.  `insert(collection: str, document: dict) -> int`: Вставляет копию словаря `document` в указанную коллекцию, добавляет в документ поле `"id"` (уникальное число, начиная с 1 для каждой коллекции) и возвращает этот `id`. Важно: метод не должен изменять исходный словарь, переданный в аргументы (используйте `copy.deepcopy()`).
2.  `get(collection: str, doc_id: int) -> dict | None`: Возвращает копию документа с указанным `id` из коллекции. Если документа нет, возвращает `None`.
3.  `update(collection: str, doc_id: int, updates: dict) -> bool`: Обновляет поля существующего документа значениями из словаря `updates`. Обновление должно быть частичным (существующие поля, не упомянутые в `updates`, должны сохраниться). Нельзя менять поле `"id"`. Возвращает `True` при успешном обновлении, `False` — если документ не найден.
4.  `delete(collection: str, doc_id: int) -> bool`: Удаляет документ с указанным `id`. Возвращает `True` при успешном удалении, иначе `False`.
5.  `find(collection: str, query: dict) -> list[dict]`: Принимает словарь-запрос (например, `{"role": "admin", "status": "active"}`). Возвращает список копий всех документов коллекции, в которых значения всех полей совпадают с полями в `query`. Если коллекция пуста или совпадений нет, возвращает пустой список.

**Пример использования:**
```python
db = InMemoryDB()
id1 = db.insert("users", {"name": "Ivan", "role": "admin"})
id2 = db.insert("users", {"name": "Petr", "role": "user"})

print(db.find("users", {"role": "admin"})) 
# Ожидается: [{"id": 1, "name": "Ivan", "role": "admin"}]
```

**Решение:**
```python
import copy

class InMemoryDB:
    def __init__(self):
        # Структура: { collection_name: { doc_id: document_dict } }
        self._data = {}
        # Индексы для автоинкремента id по каждой коллекции: { collection_name: next_id }
        self._counters = {}

    def insert(self, collection: str, document: dict) -> int:
        if collection not in self._data:
            self._data[collection] = {}
            self._counters[collection] = 1
            
        doc_id = self._counters[collection]
        
        # Делаем глубокую копию, чтобы избежать мутации данных извне
        doc_copy = copy.deepcopy(document)
        doc_copy["id"] = doc_id
        
        # Сохраняем в коллекцию
        self._data[collection][doc_id] = doc_copy
        
        # Увеличиваем счетчик для следующих записей
        self._counters[collection] += 1
        return doc_id

    def get(self, collection: str, doc_id: int) -> dict | None:
        col = self._data.get(collection)
        if not col or doc_id not in col:
            return None
        return copy.deepcopy(col[doc_id])

    def update(self, collection: str, doc_id: int, updates: dict) -> bool:
        col = self._data.get(collection)
        if not col or doc_id not in col:
            return False
            
        # Удаляем "id" из обновлений, если его передали, чтобы не сломать первичный ключ
        updates_clean = copy.deepcopy(updates)
        updates_clean.pop("id", None)
        
        # Обновляем документ в БД
        col[doc_id].update(updates_clean)
        return True

    def delete(self, collection: str, doc_id: int) -> bool:
        col = self._data.get(collection)
        if not col or doc_id not in col:
            return False
            
        del col[doc_id]
        return True

    def find(self, collection: str, query: dict) -> list[dict]:
        col = self._data.get(collection)
        if not col:
            return []
            
        matched_docs = []
        for doc in col.values():
            match = True
            for key, val in query.items():
                if doc.get(key) != val:
                    match = False
                    break
            if match:
                matched_docs.append(copy.deepcopy(doc))
                
        return matched_docs
```

**Построчное объяснение решения:**
*   `import copy`: необходим для `copy.deepcopy()`. Если мы сохраним переданный словарь напрямую, то изменения словаря в коде студента после вставки изменят и данные внутри БД (так как передача идет по ссылке). Это недопустимо для СУБД.
*   `self._data = {}`: словарь, хранящий все таблицы-коллекции.
*   `self._counters = {}`: хранит текущее максимальное значение ID для автоинкремента отдельно для каждой коллекции.
*   `doc_copy["id"] = doc_id`: присваиваем уникальный целочисленный ключ записи.
*   `col[doc_id].update(updates_clean)`: метод `update()` у словаря обновляет существующие ключи и добавляет новые.
*   `updates_clean.pop("id", None)`: вырезает ключ `"id"` из словаря изменений, чтобы клиент не мог принудительно изменить ID документа в базе данных.
*   `del col[doc_id]`: удаляет ключ из словаря коллекции, тем самым стирая запись из БД.
*   `doc.get(key) != val`: проверяет соответствие каждого условия фильтрации. Если хотя бы одно условие фильтра не совпало, отбрасываем документ.

### Задача 6 (Hard): Конвейер обработки запросов (Middleware & Web App Mock)
**Формулировка:**
Объедините все предыдущие наработки и создайте класс-симулятор веб-приложения `WebApplication`.
Класс должен содержать экземпляр маршрутизатора `SimpleRouter` (из задачи 4) и список `middleware` (функций-посредников).

**Как устроены Middleware (посредники):**
Каждое middleware — это функция со следующей сигнатурой:
`def middleware_func(request: dict, next_handler: callable) -> dict`
*   `request` — словарь запроса, содержащий ключи: `"path"` (строка), `"method"` (строка `"GET"`/`"POST"` и т.д.), `"headers"` (словарь заголовков), `"body"` (словарь или строка данных).
*   `next_handler` — функция, которую нужно вызвать, чтобы передать запрос дальше по конвейеру.
*   Middleware может изменить `request`, проанализировать его, вызвать `next_handler(request)` и вернуть его результат.
*   Также middleware может **прервать выполнение** и вернуть ответ досрочно (например, если не пройден тест авторизации), вообще не вызывая `next_handler`.

Ответ приложения — словарь вида: `{"status_code": int, "headers": dict, "body": str | dict}`.

**Вам нужно реализовать:**
1.  Класс `WebApplication` с методами:
    *   `__init__()`: инициализирует роутер и пустой список middleware.
    *   `add_middleware(middleware_func)`: регистрирует новый посредник в приложении.
    *   `handle_request(request: dict) -> dict`: запускает цепочку выполнения middleware, на конце которой стоит вызов обработчика из роутера. Метод должен корректно перехватывать ошибки `PermissionError` (возвращать ответ со статусом `455 Method Not Allowed`) и `KeyError` (возвращать статус `404 Not Found`).
2.  Две функции middleware:
    *   `logging_middleware(request, next_handler)`: печатает в консоль строчку вида `"[LOG] <Method> <Path> Received"` перед выполнением обработчика и возвращает результат работы следующего звена.
    *   `auth_middleware(request, next_handler)`: проверяет наличие заголовка `"Authorization"` в `request["headers"]`. Если заголовок равен `"Bearer supersecret"`, то пропускает запрос дальше. Иначе прерывает выполнение и сразу возвращает ответ: `{"status_code": 401, "headers": {}, "body": {"error": "Unauthorized"}}`.

**Пример интеграционного теста:**
```python
# Инициализация БД
db = InMemoryDB()
db.insert("items", {"name": "Ноутбук Квант", "price": 50000})

# Инициализация Веб-приложения
app = WebApplication()
app.add_middleware(logging_middleware)
app.add_middleware(auth_middleware)

# Регистрация роута
@app.router.register("/api/items/<int:item_id>/", "GET")
def get_item_api(item_id):
    item = db.get("items", item_id)
    if not item:
        return {"status_code": 404, "headers": {}, "body": {"error": "Item not found"}}
    return {"status_code": 200, "headers": {"Content-Type": "application/json"}, "body": item}
```

**Решение:**
```python
class WebApplication:
    def __init__(self):
        self.router = SimpleRouter()
        self.middlewares = []

    def add_middleware(self, middleware_func: callable):
        # Добавляем middleware в список
        self.middlewares.append(middleware_func)

    def handle_request(self, request: dict) -> dict:
        # Инкапсулируем логику роутера в виде финального обработчика
        def core_handler(req):
            try:
                # Находим обработчик и параметры пути через роутер
                handler, path_params = self.router.resolve(req["path"], req["method"])
                # Вызываем представление, передавая распакованные параметры пути
                response_body = handler(**path_params)
                
                # Если вью вернула сырой ответ в виде dict, оборачиваем в стандартный HTTP-ответ
                if isinstance(response_body, dict) and "status_code" in response_body:
                    return response_body
                    
                return {
                    "status_code": 200,
                    "headers": {},
                    "body": response_body
                }
            except KeyError:
                return {
                    "status_code": 404,
                    "headers": {},
                    "body": {"error": "Not Found"}
                }
            except PermissionError:
                return {
                    "status_code": 405,
                    "headers": {},
                    "body": {"error": "Method Not Allowed"}
                }
            except Exception as e:
                return {
                    "status_code": 500,
                    "headers": {},
                    "body": {"error": f"Internal Server Error: {str(e)}"}
                }

        # Строим цепочку вызовов middleware
        # Каждый middleware должен вызывать следующий за ним элемент
        def build_chain(index):
            if index == len(self.middlewares):
                return core_handler
            
            current_middleware = self.middlewares[index]
            
            # Возвращаем функцию, которая при вызове выполнит текущий middleware
            # передав ему в качестве next_handler следующий шаг цепочки
            return lambda req: current_middleware(req, build_chain(index + 1))

        # Запускаем конвейер с первого middleware
        pipeline = build_chain(0)
        return pipeline(request)

# Реализация конкретных Middleware
def logging_middleware(request: dict, next_handler: callable) -> dict:
    print(f"[LOG] {request['method']} {request['path']} Received")
    response = next_handler(request)
    print(f"[LOG] Response Status: {response['status_code']}")
    return response

def auth_middleware(request: dict, next_handler: callable) -> dict:
    headers = request.get("headers", {})
    auth_header = headers.get("Authorization")
    
    if auth_header == "Bearer supersecret":
        return next_handler(request)
        
    return {
        "status_code": 401,
        "headers": {},
        "body": {"error": "Unauthorized"}
    }
```

**Построчное объяснение решения:**
*   `self.router = SimpleRouter()`: каждый экземпляр приложения имеет собственный изолированный роутер.
*   `def core_handler(req)`: это ядро приложения. Если запрос успешно прошел все проверки middleware, вызывается этот обработчик. Он находит нужный роут и выполняет функцию представления (View).
*   `handler(**path_params)`: используем синтаксис распаковки словаря kwargs `**`. Если `path_params` равен `{"item_id": 1}`, то вызов превратится в `handler(item_id=1)`.
*   `build_chain(index)`: рекурсивная функция сборки цепочки middleware. Это классический паттерн проектирования Middleware в функциональном стиле (подобно Koa.js или Django middleware chain).
*   `lambda req: current_middleware(req, build_chain(index + 1))`: ленивое замыкание. Она связывает текущий посредник со следующим шагом. Если `index` доходит до конца списка middleware, возвращается `core_handler`.
*   `pipeline = build_chain(0)`: генерируем единую функцию-обработчик, содержащую все обертки.
*   `logging_middleware`: перехватывает управление до вызова бизнес-логики (печатает лог получения) и после (печатает лог ответа).
*   `auth_middleware`: проверяет токен безопасности. Если токена нет, возвращается словарь с ошибкой 401. Вызов `next_handler(request)` не происходит — цепочка обрывается.

## 9. Часто задаваемые вопросы (FAQ)

### 1. В чем принципиальная разница между JSON и словарем в Python?
JSON (JavaScript Object Notation) — это строковый формат обмена данными (просто текст). Python-словарь (`dict`) — это структура данных (хэш-таблица) в оперативной памяти компьютера. Мы преобразуем JSON в словарь для удобства работы с данными в коде и обратно в JSON для отправки по сети.

### 2. Почему нельзя использовать одинарные кавычки в JSON?
Спецификация стандарта JSON строго требует использования двойных кавычек (`"`) для строк и ключей. Одинарные кавычки (`'`) вызовут ошибку `json.JSONDecodeError` при парсинге.

### 3. Зачем оборачивать `json.loads` в конструкцию `try-except`?
Клиент может прислать битый JSON (например, оборванный из-за проблем с сетью или с синтаксическими ошибками). Если не обработать исключение `json.JSONDecodeError`, программа аварийно завершит работу, что в реальности приведет к падению веб-сервера.

### 4. Что такое `timedelta` в модуле `datetime`?
`timedelta` — это класс, представляющий разницу во времени (длительность). В то время как `datetime` хранит конкретную точку на временной шкале (например, 26 июня 2026 года, 12:00), `timedelta` хранит интервал (например, 2 часа и 30 минут).

### 5. Почему в формуле пересечения интервалов `S1 < E2 and S2 < E1` мы используем строгое сравнение `<`?
Если использовать нестрогое сравнение `<=`, то стыковые интервалы (когда один заканчивается ровно в момент начала другого, например, 12:00-13:00 и 13:00-14:00) будут считаться пересекающимися. В реальных бронированиях стыки допустимы, поэтому строгое сравнение корректнее.

### 6. Зачем нужна глубокая копия `copy.deepcopy()` в InMemory БД?
В Python словари передаются по ссылке. Если мы запишем переданный в метод `insert` словарь напрямую в нашу базу данных, то при изменении этого словаря вне класса БД (в кодовой базе студента) данные изменятся и внутри нашей базы данных. Глубокое копирование полностью изолирует данные БД от внешнего кода.

### 7. Что означает `**path_params` при вызове функции-обработчика?
Это распаковка словаря в именованные аргументы функции. Если `path_params` равен `{"user_id": 5}`, то запись `handler(**path_params)` эквивалентна вызову `handler(user_id=5)`. Это позволяет динамически передавать параметры из URL прямо в сигнатуру функции.

### 8. Как работает цепочка Middleware?
Каждому middleware передается функция `next_handler`, которая является оберткой над следующим middleware в очереди (или ядром приложения, если middleware закончились). Вызывая `next_handler(request)`, текущий middleware передает управление дальше. Если он не вызывает `next_handler`, а возвращает свой словарь ответа — выполнение прерывается.

### 9. В чем разница между `is` и `==` в Python при проверке `is_active`?
Оператор `==` сравнивает значения объектов, а оператор `is` проверяет идентичность объектов (ссылаются ли они на один и тот же адрес в памяти). При работе с логическими синглтонами `True` и `False` использование `is` считается более надежным и соответствующим стандарту PEP 8.

### 10. Зачем в классе роутера мы приводим входящие HTTP-методы к верхнему регистру?
По стандарту HTTP методы пишутся заглавными буквами (`GET`, `POST`, `PUT`, `DELETE`). Однако клиенты или разработчики могут передать их в нижнем регистре. Приведение к верхнему регистру через `.upper()` предотвращает баги, связанные с регистром.

    *   *Сложность:* Концепция рекурсивного оборачивания функций и передачи `next_handler` часто вызывает ступор.
    *   *Аналогия:* Представьте проходную завода. Запрос — это посетитель. Первый охранник (Middleware 1: Логирование) записывает его имя в журнал и пропускает дальше. Второй охранник (Middleware 2: Авторизация) проверяет его пропуск. Если пропуска нет, он разворачивает посетителя обратно (прерывание запроса). Если всё ок, посетитель доходит до цеха (View-обработчик).

### Адаптация под сильных студентов
