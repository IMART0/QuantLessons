Библиотека vs Фреймворк

Библиотека — это набор инструментов, который вы вызываете из своего кода для решения конкретных задач (например, math, requests).

Фреймворк — это каркас приложения. Он задает структуру проекта и сам вызывает ваш код в нужные моменты (Инверсия управления / IoC).

Принцип Голливуда

«Не звоните нам, мы сами вам позвоним».

Вы пишете функции и классы, а Django решает, когда их запустить при обработке HTTP-запроса.

Что такое Django?

Django — это высокоуровневый веб-фреймворк на Python, который стимулирует быструю разработку и чистый, прагматичный дизайн.

  • «Батарейки в комплекте» (Batteries included): Внутри уже есть админка, СУБД-оркестратор (ORM), авторизация, валидация форм и защита от атак.
  • Безопасность по умолчанию: Django автоматически блокирует CSRF-атаки, SQL-инъекции и XSS.

История

Создан в 2003 году разработчиками новостного сайта для быстрой публикации статей. Назван в честь великого джазового гитариста Джанго Рейнхардта.

Классический веб-паттерн MVC

MVC (Model-View-Controller) разделяет приложение на три независимые части:

1. Model (Модель)

Работа с данными и базой данных. Хранит бизнес-логику и проверяет валидность данных.

2. View (Представление)

Отображение данных пользователю. UI/Интерфейс (HTML/CSS страница).

3. Controller (Контроллер)

Связующее звено. Принимает запросы пользователя, общается с Моделью и передает данные во View.

Паттерн MTV в Django

Django реализует концепцию MVC под названием MTV (Model-Template-View):

  • M - Model (Модель): Структура данных. Описывается как класс на Python и автоматически мапится в таблицы базы данных.
  • T - Template (Шаблон): HTML-код со специальным шаблонизатором Django (DTL). Отвечает за то, как отобразить страницу.
  • V - View (Представление): Python-функция или класс, который принимает HTTP-запрос, извлекает данные и возвращает HTTP-ответ.

Где же Контроллер?

Роль контроллера берет на себя сам Django Framework (маршрутизатор URL и ядро фреймворка), который сопоставляет URL-адрес с конкретным View.

Соответствие паттернов MVC и MTV

MVC Паттерн MTV в Django Роль в веб-приложении
Model Model (models.py) Бизнес-логика, структура таблиц БД, валидация.
View Template (шаблоны) HTML/CSS код с плейсхолдерами для динамических данных.
Controller View + URLconf (views.py) Обработка запроса, вызов нужных моделей, сборка шаблона.

Инициализация проекта Django

Для начала работы создаем изолированное окружение и устанавливаем Django:

# 1. Создаем виртуальное окружение
python -m venv venv

# 2. Активируем окружение (Windows)
venv\Scripts\activate

# 3. Устанавливаем Django
pip install django

# 4. Создаем структуру проекта в текущей папке
django-admin startproject mysite .

Зачем нужна точка "." в конце startproject?

БЕЗ точки в конце:

Команда django-admin startproject mysite создаст внешнюю папку mysite/, а внутри неё еще одну mysite/ с настройками. Получится лишний уровень вложенности.

my_project_dir/
└── mysite/          # Лишняя папка!
    ├── manage.py
    └── mysite/
        └── settings.py

С точкой в конце:

Команда django-admin startproject mysite . развернет файлы настроек во внутреннюю папку, а управляющий скрипт положит сразу в корень текущей рабочей директории.

my_project_dir/     # Наша рабочая папка
├── manage.py        # Удобно запускать!
└── mysite/
    └── settings.py

Анатомия созданного проекта

mysite/             # Корень проекта
├── manage.py       # Управляющий скрипт
└── mysite/         # Пакет конфигурации
    ├── __init__.py # Маркер пакета Python
    ├── settings.py # Файл настроек
    ├── urls.py     # Главный маршрутизатор
    ├── asgi.py     # Точка входа для ASGI
    └── wsgi.py     # Точка входа для WSGI
  • manage.py: Наш основной интерфейс командной строки для работы с проектом.
  • settings.py: Все настройки проекта (БД, язык, часовой пояс, секретные ключи).
  • urls.py: «Карта» сайта, определяющая, какая функция View обрабатывает конкретный URL.
  • wsgi.py/asgi.py: Конфигурация для веб-серверов.

Что такое manage.py?

manage.py — это автоматически генерируемый скрипт обёртка, который связывает командную строку с библиотеками Django.

Важное правило: этот файл никогда не редактируется вручную разработчиком! Мы используем его исключительно для запуска команд.

Основные команды запускаются через терминал:

python manage.py <название_команды> [опции]

Запуск сервера разработчика

Django поставляется со встроенным веб-сервером для разработки. Не используйте его на живых сайтах (production)!

# Запуск на хосте 127.0.0.1 и порту 8000
python manage.py runserver

Сервер автоматически перезагружается при изменении файлов (Auto-reload).

Локальный адрес (Loopback)

Адрес 127.0.0.1 (или localhost) означает "себя самого". К этому серверу по умолчанию может подключиться только компьютер, на котором он запущен.

Настройка портов и хостов

Мы можем переопределить адрес и порт запуска:

# Изменение порта на 8080
python manage.py runserver 8080

# Изменение IP-адреса и порта (например, 127.0.0.1:9000)
python manage.py runserver 127.0.0.1:9000

# Запуск на ВСЕХ сетевых интерфейсах (0.0.0.0) на порту 8000
python manage.py runserver 0.0.0.0:8000

Зачем нужен 0.0.0.0? Это позволяет другим устройствам (телефонам, планшетам) в той же Wi-Fi сети заходить на ваш сайт по IP-адресу вашего компьютера.

Файл конфигурации settings.py

В этом файле хранятся глобальные настройки проекта в виде стандартных переменных Python.

  • BASE_DIR: Путь к корневой директории проекта. Вычисляется динамически с помощью библиотеки pathlib.
  • SECRET_KEY: Уникальный секретный ключ для шифрования (сессий, паролей, токенов). Должен оставаться в секрете!
from pathlib import Path

# Корень проекта
BASE_DIR = Path(__file__).resolve().parent.parent

# Секретный ключ (генерируется при старте)
SECRET_KEY = 'django-insecure-...'

Режим DEBUG и ALLOWED_HOSTS

DEBUG = True / False

  • При True Django подробно показывает трассировку ошибок прямо в браузере при сбоях (удобно при разработке).
  • На живых серверах это должно быть False, иначе взломщики увидят структуру вашего кода и пароли к БД!

ALLOWED_HOSTS

  • Список строк, содержащих имена хостов/доменов, которые этот Django-сайт может обслуживать.
  • При DEBUG = True по умолчанию разрешены localhost и 127.0.0.1.
  • При DEBUG = False этот список обязательно должен содержать ваш реальный домен.

Приложения и Базы Данных

INSTALLED_APPS

Список всех включенных приложений (модулей) в проекте. Django по умолчанию подключает системные приложения:

INSTALLED_APPS = [
    'django.contrib.admin',      # Админка
    'django.contrib.auth',       # Авторизация
    'django.contrib.contenttypes',
    'django.contrib.sessions',   # Сессии
    'django.contrib.messages',
    'django.contrib.staticfiles',# Статика
]

DATABASES

Словарь с настройками подключений к базам данных. По умолчанию настроена легкая встроенная СУБД SQLite:

DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.sqlite3',
        'NAME': BASE_DIR / 'db.sqlite3',
    }
}

Локализация и шаблонизатор

Язык и часовой пояс

# Код языка интерфейса админки
LANGUAGE_CODE = 'ru-ru'

# Временная зона для хранения дат
TIME_ZONE = 'Europe/Moscow'

# Использовать интернационализацию
USE_I18N = True

# Использовать временные зоны
USE_TZ = True

TEMPLATES

Список настроек для рендеринга шаблонов. Указывает, где Django искать HTML файлы и какой шаблонизатор использовать (по умолчанию DTL — Django Templates Language).

Другие полезные команды manage.py

  • python manage.py check — Проверяет проект на наличие распространенных ошибок конфигурации, не запуская сервер.
  • python manage.py migrate — Применяет миграции к базе данных (создает таблицы для встроенных приложений Django). Запустите её при первом старте проекта, чтобы убрать предупреждение в терминале.
  • python manage.py shell — Запускает интерактивную консоль Python, в которой уже настроено окружение Django. Позволяет быстро тестировать код и запросы к БД.

Резюме урока

  • Django — мощный MVC-фреймворк, реализующий архитектуру MTV.
  • Модель — БД, Темплейт — HTML, Вью — Python-логика.
  • Проект создается через django-admin startproject <имя> . (точка важна!).
  • manage.py — пульт управления проектом, мы не меняем его код.
  • settings.py — главный конфиг; следите за DEBUG и ALLOWED_HOSTS!
  • Для локальной сети запускаем сервер как runserver 0.0.0.0:8000.

Переходим к практике и разбору структуры проекта!
