Загрузка файлов в Django

Проект: Сайт летней школы Квант  |  Время: 80 минут

Статические файлы vs Медиа-файлы

Статические файлы (Static)

Ресурсы, создаваемые разработчиком на этапе написания кода сайта:

  • CSS-стили оформления сайта «Квант».
  • JS-скрипты интерактивных элементов.
  • Логотипы и фоновые изображения лагеря.
  • Шрифты интерфейса.
Хранятся в репозитории проекта. Обычно доступны только для чтения со стороны пользователей.

Медиа-файлы (Media)

Файлы, которые загружают пользователи или администраторы в процессе работы сайта:

  • Обложки новостей лагеря (мероприятия, фото).
  • Скачиваемые бланки заявлений от родителей.
  • Списки участников (CSV), загружаемые кураторами.
  • Файлы с решениями олимпиадных задач.
Загружаются динамически во время работы сайта, не хранятся в Git. Требуют строгого контроля безопасности!

Настройки медиа-файлов: settings.py

Для корректного сохранения файлов и доступа к ним, в конфигурационном файле проекта необходимо объявить две ключевые переменные:

import os
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent.parent

# 1. Абсолютный путь на диске, куда Django будет сохранять загруженные файлы
MEDIA_ROOT = os.path.join(BASE_DIR, 'media')

# 2. Базовый URL-адрес для доступа к загруженным файлам через браузер
MEDIA_URL = '/media/'
Важно: Никогда не помещайте директорию media внутрь папки со статикой или внутрь кода приложения. Она должна располагаться отдельно в корне проекта.

Раздача медиа-файлов в режиме разработки

В режиме разработки (DEBUG = True) встроенный сервер Django должен уметь отдавать медиа-файлы из директории MEDIA_ROOT по адресу MEDIA_URL. Для этого редактируется корневой urls.py:

from django.conf import settings
from django.conf.urls.static import static
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('news.urls')),  # Маршруты новостей сайта Кванта
]

# Раздаем медиа-файлы только во время локальной разработки
if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
В промышленной эксплуатации (production, DEBUG = False) раздачей медиа-файлов должен заниматься быстрый веб-сервер (Nginx, Apache) или облачные хранилища.

Поля моделей: FileField и ImageField

Для хранения файлов в таблицах БД используются специальные типы полей. В самой БД хранится только текстовый относительный путь к файлу.

  • FileField — базовое поле для любых файлов (PDF-бланки заявлений, Excel-списки, архивы с ДЗ).
  • ImageField — наследник FileField, проверяющий, что загружен именно валидный файл изображения. Требует библиотеки Pillow.
from django.db import models

class News(models.Model):
    title = models.CharField(max_length=200, verbose_name="Заголовок")
    content = models.TextField(verbose_name="Текст новости")
    # Поле для обложки новости
    image = models.ImageField(upload_to='news_covers/', null=True, blank=True)
    # Поле для прикрепленного документа (например, регламент олимпиады)
    document = models.FileField(upload_to='news_files/', null=True, blank=True)

Куда сохраняются файлы? Аргумент upload_to

Аргумент upload_to задает подпапку внутри MEDIA_ROOT. Он поддерживает шаблоны дат и функции для переименования файлов.

1. Шаблоны форматирования дат

# Файл сохранится в media/news_covers/2026/07/04/
image = models.ImageField(
    upload_to='news_covers/%Y/%m/%d/'
)

2. Кастомная функция переименования

def get_upload_path(instance, filename):
    ext = filename.split('.')[-1]
    # Генерируем уникальное имя по ID новости
    return f'news_files/news_{instance.id}.{ext}'

document = models.FileField(
    upload_to=get_upload_path
)

HTML-форма для загрузки файлов

Чтобы браузер мог корректно упаковать и отправить двоичные данные файла на сервер, HTML-форма должна соответствовать двум строгим правилам:

  1. Метод передачи данных должен быть исключительно POST.
  2. Атрибут кодирования формы должен быть равен enctype="multipart/form-data".
<form method="POST" enctype="multipart/form-data">
    {% csrf_token %}
    <label for="title">Заголовок новости:</label>
    <input type="text" name="title" id="title">
    
    <label for="image">Обложка новости:</label>
    <input type="file" name="image" id="image">
    
    <button type="submit">Опубликовать</button>
</form>
Если забыть прописать enctype="multipart/form-data", браузер отправит на сервер только текстовое имя файла, а сам файл останется на компьютере пользователя.

Обработка файлов в View: request.FILES

При отправке файлов они попадают не в request.POST, а в специальный словарь-подобный объект request.FILES.

from django.shortcuts import render
from django.http import HttpResponse
from .models import News

def upload_news_cover(request):
    if request.method == 'POST':
        title = request.POST.get('title')
        # Получаем файл по ключу name из input'а
        image_file = request.FILES.get('image') 
        
        if image_file:
            news = News(title=title, image=image_file)
            news.save()
            return HttpResponse(f"Файл {image_file.name} сохранен! URL: {news.image.url}")
            
    return render(request, 'upload_news.html')

Загрузка файлов без моделей (Ручное сохранение)

Иногда нужно загрузить файл и обработать его «на лету» без сохранения в базу (например, CSV-список участников для быстрого разбора и сверки). Чтобы не перегружать оперативную память сервера, читаем его чанками (кусками):

import os
from django.conf import settings

def handle_uploaded_csv(uploaded_file):
    # Путь сохранения временного файла на сервере
    file_path = os.path.join(settings.MEDIA_ROOT, 'temp', uploaded_file.name)
    
    # Запись файла небольшими порциями (chunks) по 64 КБ
    with open(file_path, 'wb+') as destination:
        for chunk in uploaded_file.chunks():
            destination.write(chunk)
Метод chunks() гарантирует, что даже гигантский файл не переполнит память RAM сервера, так как Django считывает его по частям.

Формы Django и файлы

При использовании Django Forms или ModelForms файлы обрабатываются автоматически, если в форму передать оба словаря: request.POST и request.FILES.

from django import forms
from .models import News

# Класс формы на основе модели News
class NewsForm(forms.ModelForm):
    class Meta:
        model = News
        fields = ['title', 'content', 'image', 'document']

# Обработка в представлении (View):
def news_create(request):
    if request.method == 'POST':
        # Важно передать request.FILES вторым аргументом!
        form = NewsForm(request.POST, request.FILES)
        if form.is_valid():
            form.save()
            return redirect('news_list')
    else:
        form = NewsForm()
    return render(request, 'news_form.html', {'form': form})

Безопасность загрузки файлов: Риски

Предоставление пользователям возможности загружать любые файлы — это огромный риск для сервера. Основные угрозы:

  • Удаленное выполнение кода (RCE): Хакер загружает вредоносный скрипт под видом картинки (например, shell.py) и запускает его, обращаясь напрямую по URL.
  • Отказ в обслуживании (DoS): Загрузка файлов огромных размеров (например, 50 ГБ), приводящая к быстрому переполнению диска.
  • Межсайтовый скриптинг (XSS): Загрузка HTML-файла или SVG-картинки со встроенным JS-кодом, крадущим cookies пользователей при просмотре.
Главное правило безопасности: Никогда не доверяйте имени, расширению и контенту файла без жесткой проверки!

Валидация размера файла

Для предотвращения DoS-атак необходимо ограничивать максимальный размер загружаемого файла. В Django это делается с помощью создания кастомного валидатора.

from django.core.exceptions import ValidationError

def validate_file_size(value):
    # Ограничение 2 Мегабайта (2 * 1024 * 1024 байт)
    limit = 2 * 1024 * 1024
    if value.size > limit:
        raise ValidationError('Изображение слишком большое. Максимальный размер: 2 МБ.')

# Подключение в модели News:
class News(models.Model):
    title = models.CharField(max_length=200)
    image = models.ImageField(upload_to='news_covers/', validators=[validate_file_size])

Если загрузить файл больше 2 МБ, Django Form вернет ошибку валидации и не сохранит файл на сервере.

Проверка подлинности типа: MIME-типы

Нельзя верить просто расширению файла (например, .png). Злоумышленник может переименовать файл exploit.py в exploit.png. Проверяется реальный тип содержимого (MIME-тип):

import magic # Требует pip install python-magic
from django.core.exceptions import ValidationError

def validate_is_pdf(file):
    # Считываем первые 2048 байт для определения сигнатуры файла
    header = file.read(2048)
    file.seek(0) # Обязательно сбрасываем указатель чтения обратно в начало!
    
    mime = magic.from_buffer(header, mime=True)
    if mime != 'application/pdf':
        raise ValidationError('Допускаются только PDF-документы.')
Библиотека python-magic анализирует «магические байты» (сигнатуру) в заголовке файла, гарантируя точность определения формата.

Кастомный универсальный валидатор файлов

Пример профессионального класса-валидатора для проверки и размера, и MIME-типа файлов, готового к использованию в моделях проекта:

from django.utils.deconstruct import deconstructible
from django.core.exceptions import ValidationError

@deconstructible
class FileValidator:
    def __init__(self, max_size=None, allowed_mimes=None):
        self.max_size = max_size
        self.allowed_mimes = allowed_mimes

    def __call__(self, file):
        if self.max_size and file.size > self.max_size:
            raise ValidationError(f"Максимальный размер: {self.max_size / (1024*1024)} МБ.")
        
        import magic
        mime = magic.from_buffer(file.read(2048), mime=True)
        file.seek(0)
        if self.allowed_mimes and mime not in self.allowed_mimes:
            raise ValidationError("Неподдерживаемый формат файла.")

Очистка диска: Удаление файлов при удалении моделей

Проблема: По умолчанию при вызове news.delete() Django удаляет только строку из базы данных. Загруженный файл остается на диске навсегда, захламляя сервер.

Сотни удаленных новостей или замененных обложек оставляют гигабайты «мусорных» файлов на диске!

Решение 1: Библиотека django-cleanup

Самый простой и надежный способ — поставить сторонний пакет, который сам отслеживает удаление файлов при удалении или изменении записей:

pip install django-cleanup

Добавить в INSTALLED_APPS в settings.py:

INSTALLED_APPS = [
    ...
    'django_cleanup.apps.CleanupConfig',
]

Резюме и план практического занятия

Основные правила загрузки файлов:

  • Настройки: MEDIA_ROOT и MEDIA_URL.
  • Раздавать файлы через Django только при DEBUG=True.
  • Для HTML-форм указывать enctype="multipart/form-data".
  • Передавать request.FILES в форму вместе с POST.
  • Всегда валидировать размер и тип файлов на бэкенде.

  3. Кастомные функции генерации путей.
  4. Обработку списков (CSV) без привязки к моделям.
  5. Безопасную валидацию MIME-типов.
