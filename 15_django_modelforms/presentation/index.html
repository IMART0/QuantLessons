Повторение кода: Нарушение принципа DRY

Представим, что у нас есть модель задачи Task в БД:

# models.py
class Task(models.Model):
    title = models.CharField(max_length=100)
    description = models.TextField()
    is_completed = models.BooleanField(default=False)

Если писать обычную форму:

# forms.py
class TaskForm(forms.Form):
    title = forms.CharField(max_length=100)
    description = forms.CharField(widget=forms.Textarea)
    is_completed = forms.BooleanField(required=False)
Минусы обычных forms.Form:
  • Дублирование кода: Мы дважды пишем типы полей, ограничения длины и валидаторы.
  • Ручной перенос данных: Приходится вручную вытаскивать данные из cleaned_data и передавать их в модель.
  • Сложность поддержки: Добавили поле в модель? Надо не забыть обновить форму и вьюху.

Решение: Django ModelForm

Django предоставляет специальный класс ModelForm, который автоматически решает все эти проблемы.

ModelForm — это класс формы в Django, который привязан к конкретной модели базы данных. Он сам считывает поля модели и генерирует соответствующие HTML-поля формы с их правилами валидации, а также умеет автоматически сохранять данные в БД.

Преимущества:

  • DRY (Don't Repeat Yourself): Описание структуры данных хранится в одном месте (в модели).
  • Автоматическая валидация: Ограничения модели (например, max_length) проверяются автоматически.
  • Интеграция с БД: Метод save() создаёт или обновляет объект в БД за один вызов.

Базовый синтаксис ModelForm

Чтобы создать форму на основе модели, наследуемся от forms.ModelForm и описываем вложенный класс Meta:

from django import forms
from .models import Task

class TaskForm(forms.ModelForm):
    class Meta:
        model = Task               # С какой моделью работаем
        fields = ['title', 'description', 'is_completed']  # Какие поля выводим в форму
Класс Meta: Это служебный класс, в котором задаются конфигурационные параметры формы. Самыми важными являются model (ссылка на класс модели) и fields (список отображаемых полей).

Опции Meta: Выбор полей (fields)

Вы можете явно указать список отображаемых полей или использовать специальное ключевое слово:

  • fields = ['title', 'description'] — отображаются только перечисленные поля (самый безопасный подход).
  • fields = '__all__' — автоматически отображаются все поля модели.
Опасайтесь fields = '__all__'!
Если вы добавите в модель конфиденциальное или служебное поле (например, is_admin или user_balance), оно автоматически попадет в форму и его сможет изменить злоумышленник (уязвимость Mass Assignment). Используйте явный список!

Опции Meta: Исключение полей (exclude)

Иногда нужно отобразить почти все поля модели, за исключением пары штук. Для этого используется опция exclude:

class TaskForm(forms.ModelForm):
    class Meta:
        model = Task
        exclude = ['is_completed'] # Выведет 'title' и 'description'

Важное правило:

  • В классе Meta обязательно должен присутствовать хотя бы один из параметров: fields или exclude.
  • Нельзя использовать оба параметра одновременно. Рекомендуется отдавать предпочтение fields для явного контроля безопасности.

Как поля модели превращаются в поля форм?

Django автоматически сопоставляет типы полей моделей с типами полей форм и HTML-виджетами:

Поле в Model (БД) Поле в Form Стандартный HTML Widget
CharField(max_length=...) CharField <input type="text">
TextField() CharField <textarea></textarea>
BooleanField() BooleanField <input type="checkbox">
ForeignKey(to=...) ModelChoiceField <select> (выпадающий список)
ManyToManyField(to=...) ModelMultipleChoiceField <select multiple> (множественный выбор)

Кастомизация: Ярлыки (labels) и подсказки (help_texts)

Если вы хотите изменить названия полей (подписи/лейблы) или добавить к ним подсказки на форме без редактирования модели, сделайте это в Meta:

class TaskForm(forms.ModelForm):
    class Meta:
        model = Task
        fields = ['title', 'description']
        labels = {
            'title': 'Название задачи',
            'description': 'Детальное описание',
        }
        help_texts = {
            'title': 'Кратко сформулируйте суть задачи.',
        }

Кастомизация: Сообщения об ошибках

Вы можете переопределить тексты стандартных валидационных ошибок через параметр error_messages:

class TaskForm(forms.ModelForm):
    class Meta:
        model = Task
        fields = ['title']
        error_messages = {
            'title': {
                'required': 'Это поле обязательно для заполнения!',
                'max_length': 'Заголовок не может быть длиннее 100 символов.',
            }
        }
Такой подход позволяет локализовать или детализировать сообщения об ошибках для конечного пользователя, делая интерфейс более дружелюбным.

Кастомизация виджетов: опция widgets

Наиболее частая задача — стилизовать поля (например, добавить Bootstrap-класс form-control или placeholder). Для этого используется опция widgets:

from django import forms

class TaskForm(forms.ModelForm):
    class Meta:
        model = Task
        fields = ['title', 'description']
        widgets = {
            'title': forms.TextInput(attrs={
                'class': 'form-control',
                'placeholder': 'Введите заголовок задачи...'
            }),
            'description': forms.Textarea(attrs={
                'class': 'form-control',
                'rows': 4,
                'placeholder': 'Опишите задачу подробнее...'
            }),
        }

Альтернатива: переопределение полей класса

Если настройки виджетов в Meta недостаточно, вы можете явно объявить поле прямо в классе формы. Это перекроет автоматически сгенерированное поле:

class TaskForm(forms.ModelForm):
    # Явно объявленное поле переопределяет настройки из Meta
    title = forms.CharField(
        max_length=50, # Сузили лимит в форме (в БД остался 100)
        label="Суперзадача",
        widget=forms.TextInput(attrs={'class': 'custom-input'})
    )

    class Meta:
        model = Task
        fields = ['title', 'description']
Внимание: Если вы переопределяете поле вручную, убедитесь, что вы не ослабили ограничения модели (например, указав в форме max_length=200, когда в БД лимит 100). Иначе при сохранении возникнет ошибка базы данных.

Использование в View: Создание объекта

Для создания объекта передаем request.POST в форму для связывания (binding), проверяем валидность и сохраняем:

from django.shortcuts import render, redirect
from .forms import TaskForm

def task_create_view(request):
    if request.method == 'POST':
        form = TaskForm(request.POST) # Связываем форму с данными из POST
        if form.is_valid():
            task = form.save()        # Автоматически сохраняем в БД!
            return redirect('task_list')
    else:
        form = TaskForm()             # Пустая форма для GET-запроса
        
    return render(request, 'task_form.html', {'form': form})
Обратите внимание на form.save(): он сам создаёт экземпляр модели Task, заполняет его валидными данными и делает INSERT в базу данных!

Использование в View: Обновление (Update)

Чтобы отредактировать существующую запись, нужно передать объект в аргумент instance формы:

from django.shortcuts import get_object_or_400
from .models import Task

def task_update_view(request, pk):
    task = get_object_or_404(Task, pk=pk) # Достаем объект из БД
    
    if request.method == 'POST':
        # Передаем и POST-данные, и сам редактируемый объект:
        form = TaskForm(request.POST, instance=task)
        if form.is_valid():
            form.save() # Делает UPDATE в БД вместо INSERT!
            return redirect('task_list')
    else:
        form = TaskForm(instance=task) # Форма предзаполняется данными объекта
        
    return render(request, 'task_form.html', {'form': form})

Паттерн save(commit=False)

Что делать, если в форме нет полей, которые обязательны в модели для записи в БД? (например, автора задачи/текущего юзера или даты публикации).

Вызов form.save() напрямую выдаст ошибку IntegrityError (ошибка целостности БД), так как некоторые поля останутся пустыми.

Решение: вызвать form.save(commit=False).

  • Создает экземпляр модели в оперативной памяти (в Python).
  • НЕ записывает его в базу данных сразу.
  • Позволяет вручную заполнить недостающие атрибуты объекта.
  • После этого вызывается ручной метод .save() на объекте.

Как работает commit=False (Код)

Рассмотрим пример, где задача должна быть связана с вошедшим пользователем:

def task_create_view(request):
    if request.method == 'POST':
        form = TaskForm(request.POST)
        if form.is_valid():
            # 1. Получаем объект модели, но не сохраняем в БД:
            task = form.save(commit=False)
            # 2. Добавляем автора (которого не было в полях формы):
            task.author = request.user
            # 3. Физически сохраняем в базу данных:
            task.save()
            return redirect('task_list')
Этот паттерн чрезвычайно полезен и используется повсеместно для автоматического заполнения полей аудита (создатель, дата, статус по умолчанию).

Сохранение Many-to-Many при commit=False

Когда вы вызываете form.save(commit=False), Django не может сохранить отношения "многие-ко-многим" (M2M) в промежуточную таблицу БД, так как у главного объекта еще нет первичного ключа (id).

# Если у задачи есть теги (ManyToMany связь):
if form.is_valid():
    task = form.save(commit=False)
    task.author = request.user
    task.save()           # Теперь у объекта появился ID в БД
    form.save_m2m()       # Обязательно! Сохраняем связи Many-to-Many
Если в форме есть поля Many-to-Many (например, мультивыбор тегов) и вы используете commit=False, вы обязаны явно вызвать метод form.save_m2m() сразу после сохранения основного объекта! Иначе теги не сохранятся.

Отображение формы в HTML шаблоне

Вывод формы в HTML остался таким же простым, как и для обычных форм. Не забываем про тег csrf_token:

<form method="post">
    {% csrf_token %}
    
    
    {{ form.as_div }}
    
    <button type="submit" class="btn btn-primary">Сохранить</button>
</form>
Новинка Django 5.0+: Метод form.as_div() выводит каждое поле внутри блочного контейнера <div>, что считается более современным стандартом верстки, чем as_p() или as_table().

Итоги урока: Сравнение Form и ModelForm

Используйте forms.Form, если:

  • Форма не связана напрямую с таблицей БД (например: форма обратной связи, калькулятор, отправка email).

Используйте forms.ModelForm, если:

  • Форма предназначена для создания, редактирования или удаления записей в БД (CRUD).
Чек-лист создания:
  1. Создать класс в forms.py наследуя от forms.ModelForm.
  2. В Meta привязать модель и указать список полей fields.
  3. Кастомизировать виджеты, ярлыки, ошибки при необходимости.
  4. Во вьюхе связать форму с POST-данными (и instance при редактировании).
  5. Проверить form.is_valid() и сохранить через form.save().
