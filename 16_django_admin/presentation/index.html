Что такое Django Admin?

Django Admin — встроенное приложение Django (django.contrib.admin), генерирующее готовый веб-интерфейс для администрирования базы данных.

  • Мгновенный CRUD: Создание, чтение, обновление и удаление данных без написания HTML и форм.
  • Экономия времени: Автоматически считывает метаданные ваших моделей.
  • Бэк-офис проекта: Идеально подходит для вожатых и кураторов летней школы Квант.

Преимущества:

  • Встроенная авторизация и роли.
  • История действий пользователей (LogEntry).
  • Гибкая кастомизация под любые задачи.

Создание суперпользователя лагеря

Для входа в панель администратора необходим аккаунт с правами суперпользователя (Superuser). Создаем его через CLI:

python manage.py createsuperuser

Поля ввода в консоли:

  1. Username: Логин (например, kvant_admin).
  2. Email address: Почта (например, admin@kvant.ru).
  3. Password: Пароль (символы при вводе скрываются!).
  4. Password (again): Подтверждение пароля.

Внимание!

Отсутствие символов на экране при вводе пароля — это стандарт безопасности терминала. Не думайте, что консоль зависла, просто вводите пароль и жмите Enter.

Вход в панель администратора

Стандартный маршрут админки изначально настроен в файле urls.py вашего проекта:

# core/urls.py
from django.contrib import admin
from django.urls import path

urlpatterns = [
    path('admin/', admin.site.urls),
]

Алгоритм входа:

  1. Запустите сервер: python manage.py runserver
  2. Откройте ссылку http://127.0.0.1:8000/admin/
  3. Введите учетные данные созданного суперпользователя.
Важно: Всегда применяйте миграции (migrate) перед входом, иначе Django не сможет проверить учетные данные!

Регистрация моделей лагеря

Изначально новые модели не видны в админке. Их необходимо зарегистрировать в файле admin.py приложения:

# camp_site/admin.py
from django.contrib import admin
from .models import Student

# Простая регистрация модели Учеников
admin.site.register(Student)

Результат:

В веб-интерфейсе появляется блок модели Student. Названия строк списка формируются на основе метода __str__(), определенного в классе модели.

Класс ModelAdmin и декоратор @admin.register

Для детальной настройки отображения и поведения модели создают специальный класс настроек, наследуемый от admin.ModelAdmin.

Современный способ связывания модели лагеря и класса настроек — декоратор @admin.register.

# camp_site/admin.py
from django.contrib import admin
from .models import Student

@admin.register(Student)
class StudentAdmin(admin.ModelAdmin):
    # Здесь настраиваются свойства админки
    pass

Настройка списка: list_display

Свойство list_display определяет столбцы таблицы в списке записей. Показываем ФИО, класс, отряд и группу ученика:

@admin.register(Student)
class StudentAdmin(admin.ModelAdmin):
    list_display = ('name', 'grade', 'squad', 'group', 'is_active')
Порядок колонок: Определяется порядком перечисления полей в кортеже.
Сортировка: Все поля таблицы автоматически становятся сортируемыми при клике по заголовку.

Фильтрация данных: list_filter

Свойство list_filter генерирует боковую панель фильтров. Фильтруем учеников лагеря по классу, отряду, учебной группе и активности:

@admin.register(Student)
class StudentAdmin(admin.ModelAdmin):
    list_display = ('name', 'grade', 'squad', 'group')
    list_filter = ('grade', 'squad', 'group', 'is_active')

Умные фильтры:

Django автоматически анализирует тип данных. Для булевых полей генерируется фильтр (Да/Нет/Все), а для отряда — список присутствующих в базе номеров отрядов.

Поиск по записям: search_fields

Свойство search_fields создает поисковую строку. Ищем преподавателей по ФИО и предмету:

@admin.register(Teacher)
class TeacherAdmin(admin.ModelAdmin):
    list_display = ('name', 'subject')
    search_fields = ('name', 'subject')
Поиск по внешним связям (ForeignKey): Если вы ищете слоты расписания по преподавателю, писать просто 'teacher' в поиске нельзя. Используйте двойное подчеркивание для перехода к полю связанной таблицы: search_fields = ('title', 'teacher__name').

Быстрое редактирование: list_editable

Свойство list_editable позволяет вожатым изменять отряд, учебную группу и статус активности учеников прямо из общей таблицы:

@admin.register(Student)
class StudentAdmin(admin.ModelAdmin):
    list_display = ('name', 'grade', 'squad', 'group', 'is_active')
    list_editable = ('squad', 'group', 'is_active')

Два жестких правила:

  1. Редактируемые поля должны быть перечислены в list_display.
  2. Поля в list_editable не могут быть ссылками на форму редактирования (по умолчанию это первое поле).

Кастомные поля и format_html

Методы класса ModelAdmin позволяют выводить вычисляемые данные. Используем format_html для рендеринга тегов HTML:

from django.utils.html import format_html

@admin.register(Student)
class StudentAdmin(admin.ModelAdmin):
    list_display = ('name', 'squad', 'squad_badge')

    @admin.display(description="Цветной значок отряда")
    def squad_badge(self, obj):
        colors = {1: "red", 2: "blue", 3: "green", 4: "yellow", 5: "purple"}
        badge_color = colors.get(obj.squad, "gray")
        return format_html(
            '<span style="background: {}; color: white; padding: 3px 6px;">Отряд {}</span>',
            badge_color, obj.squad
        )

Группировка полей формы: fieldsets

Свойство fieldsets позволяет разделить длинные формы создания на логические секции.

Мы можем скрыть второстепенную информацию (например, биографию и email учителя) под раскрывающийся спойлер.

# camp_site/admin.py
class TeacherAdmin(admin.ModelAdmin):
    fieldsets = (
        ('Основная информация', {
            'fields': ('name', 'subject')
        }),
        ('Контакты и биография', {
            'classes': ('collapse',),
            'fields': ('email', 'bio')
        }),
    )

Связанные модели: Inline-формы

Inlines позволяют управлять связанными моделями (ForeignKey) прямо на странице родительского объекта.

Типы Inline-форм:

  • admin.TabularInline — компактное отображение записей в виде горизонтальной таблицы.
  • admin.StackedInline — отображение в виде крупных вертикальных блоков.

Пример в лагере:

Управление слотами расписания (ScheduleSlot) непосредственно на странице редактирования преподавателя (Teacher).

Реализация ScheduleSlotInline

from django.contrib import admin
from .models import Teacher, ScheduleSlot

# 1. Описываем inline-класс для слотов расписания
class ScheduleSlotInline(admin.TabularInline):
    model = ScheduleSlot
    extra = 1  # Количество пустых строк для добавления новых записей
    fields = ('title', 'room', 'date', 'start_time', 'end_time')

# 2. Регистрируем преподавателя с inline
@admin.register(Teacher)
class TeacherAdmin(admin.ModelAdmin):
    list_display = ('name', 'subject')
    inlines = [ScheduleSlotInline]

Групповые действия: Admin Actions

Действия (Actions) позволяют выполнять одну операцию сразу над множеством записей, отмеченных галочками в списке.

По умолчанию в Django доступно только действие «Удалить выбранные объекты». Мы можем написать свое!

Примеры действий лагеря:

  • Одобрить выбранные мероприятия.
  • Сделать активными выбранных учеников.
  • Снять с публикации предложенные отрядами идеи событий.

Создание действия одобрения мероприятий

# 1. Пишем функцию действия с описанием
@admin.action(description="Одобрить выбранные лагерные мероприятия")
def approve_events(modeladmin, request, queryset):
    # queryset содержит только отмеченные галочками записи Event
    count = queryset.update(status='approved')
    # Отправляем сообщение-уведомление в интерфейс
    modeladmin.message_user(request, f"Успешно одобрено мероприятий: {count}.")

# 2. Подключаем действие к EventAdmin
@admin.register(Event)
class EventAdmin(admin.ModelAdmin):
    list_display = ('title', 'organizer_squad', 'status')
    actions = [approve_events]

Итоги лекции и рекомендации

  • Django Admin — готовый инструмент для внутреннего управления (Back-Office) проектом.
  • Для простых проектов админка полностью заменяет необходимость писать кастомные панели управления.
  • Никогда не давайте обычным пользователям сайта (ученикам лагеря) доступ к админ-панели (флаг is_staff=False).
  • Основные инструменты кастомизации: list_display, list_filter, search_fields, inlines, actions.
