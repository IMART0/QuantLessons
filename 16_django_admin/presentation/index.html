Что такое Django Admin?

Django Admin — это встроенное приложение Django, которое автоматически генерирует профессиональный веб-интерфейс для управления данными вашего сайта.

  • Готовый CRUD: Создание, чтение, обновление и удаление записей без написания HTML и форм.
  • Экономия времени: Автоматически подстраивается под структуру ваших моделей.
  • Безопасность: Встроенная система авторизации, ролей и логирования действий.

Кому это нужно?

Разработчикам для быстрого наполнения БД, тестирования моделей, а также контент-менеджерам и администраторам сайта для управления контентом без доступа к коду.

Шаг 1: Создание суперпользователя

Прежде чем войти в панель администратора, необходимо создать пользователя с максимальными правами (Superuser):

python manage.py createsuperuser

После ввода команды терминал предложит вам ввести:

  1. Username: Имя пользователя (например, admin)
  2. Email address: Почту (можно оставить пустой и нажать Enter)
  3. Password: Пароль (символы при вводе скрываются в целях безопасности)
  4. Password (again): Подтверждение пароля

Шаг 2: Вход в панель администратора

По умолчанию маршрут для админки уже прописан в главном urls.py вашего проекта:

# core/urls.py
from django.contrib import admin
from django.urls import path

urlpatterns = [
    path('admin/', admin.site.urls),
]
  1. Запустите сервер разработки: python manage.py runserver
  2. Перейдите по адресу http://127.0.0.1:8000/admin/
  3. Введите логин и пароль, которые вы указали при создании суперпользователя.
Важно: Не забудьте применить миграции перед запуском, так как таблицы пользователей хранятся в базе данных.

Регистрация моделей (Простой способ)

Чтобы ваша модель появилась в панели администратора, её нужно зарегистрировать в файле admin.py вашего приложения:

# apps/library/admin.py
from django.contrib import admin
from .models import Book

# Регистрируем модель Book
admin.site.register(Book)

Результат: Модель Book появится в интерфейсе админки. Название в списке будет строиться на основе метода __str__(), определенного в модели.

Кастомизация админки: Класс ModelAdmin

Для детальной настройки отображения модели создают специальный класс-представление, наследуемый от admin.ModelAdmin.

Для регистрации класса используется декоратор @admin.register:

# apps/library/admin.py
from django.contrib import admin
from .models import Book

@admin.register(Book)
class BookAdmin(admin.ModelAdmin):
    # Здесь настраиваются все параметры отображения модели
    pass

Использование декоратора считается более современным и чистым стилем по сравнению с admin.site.register(Book, BookAdmin).

Настройка списка записей: list_display

По умолчанию в списке записей выводится только строковое представление объекта (__str__). Свойство list_display позволяет задать конкретные поля модели для отображения в виде таблицы:

@admin.register(Book)
class BookAdmin(admin.ModelAdmin):
    list_display = ('title', 'author', 'price', 'is_available')
Возможности таблицы:
  • Поля автоматически становятся заголовками столбцов.
  • Поля БД поддерживают автоматическую сортировку по клику на заголовок.
  • Первое поле списка по умолчанию становится ссылкой на страницу редактирования записи.

Поиск по записям: search_fields

Атрибут search_fields добавляет поисковую строку на страницу списка записей и определяет, по каким полям будет производиться поиск:

@admin.register(Book)
class BookAdmin(admin.ModelAdmin):
    list_display = ('title', 'author', 'price')
    search_fields = ('title', 'author__name', 'isbn')
Поиск по связанным моделям (ForeignKey): Для поиска по полю внешней связи используется синтаксис с двойным подчеркиванием (__): 'author__name'. Если написать просто 'author', Django выдаст ошибку, пытаясь искать по объекту связи.

Фильтрация данных: list_filter

Атрибут list_filter добавляет правую боковую панель для быстрой фильтрации записей по выбранным полям:

@admin.register(Book)
class BookAdmin(admin.ModelAdmin):
    list_display = ('title', 'author', 'price', 'is_available')
    list_filter = ('is_available', 'genre', 'published_date')

Типы полей, поддерживающие фильтрацию:

  • Boolean: Фильтры "Да" / "Нет" / "Все".
  • ForeignKey / Choices: Автоматический список доступных значений.
  • DateField / DateTimeField: Удобные временные фильтры (Сегодня, Последние 7 дней, Этот месяц, Этот год).

Быстрое редактирование: list_editable

Позволяет редактировать поля записей прямо в общем списке без перехода на детальную страницу. Изменения сохраняются одной кнопкой "Сохранить" внизу страницы.

@admin.register(Book)
class BookAdmin(admin.ModelAdmin):
    list_display = ('title', 'price', 'is_available')
    list_editable = ('price', 'is_available')

Два важных правила:

  1. Поля из list_editable обязательно должны присутствовать в list_display.
  2. Поля из list_editable не могут быть ссылками на детальную страницу (по умолчанию это первое поле из list_display).

Пользовательские и вычисляемые поля

В list_display можно передавать функции или методы класса ModelAdmin. Для вывода форматированного HTML используется функция format_html:

from django.utils.html import format_html

@admin.register(Book)
class BookAdmin(admin.ModelAdmin):
    list_display = ('title', 'colored_status')

    @admin.display(description='Статус наличия')
    def colored_status(self, obj):
        if obj.is_available:
            return format_html('<span style="color: green; font-weight: bold;">В наличии</span>')
        return format_html('<span style="color: red;">Нет на складе</span>')

Декоратор @admin.display задает заголовок колонки (вместо названия метода) и позволяет настраивать сортировку.

Группировка полей формы: fieldsets

Позволяет структурировать форму добавления/редактирования записи, разделяя поля на смысловые блоки и скрывая редко используемые:

@admin.register(Book)
class BookAdmin(admin.ModelAdmin):
    fieldsets = (
        ('Основная информация', {
            'fields': ('title', 'author', 'isbn')
        }),
        ('Экономика и Доступность', {
            'classes': ('collapse',), # Блок будет изначально скрыт
            'fields': ('price', 'is_available'),
        }),
    )

Класс 'collapse' добавляет кнопку "Показать / Скрыть" для соответствующей секции.

Редактирование связанных моделей (Inlines)

Позволяет редактировать дочерние объекты прямо на странице родительского объекта. Например, добавлять книги автора на странице редактирования автора:

# admin.py
class BookInline(admin.TabularInline): # или admin.StackedInline
    model = Book
    extra = 1 # количество пустых полей по умолчанию

@admin.register(Author)
class AuthorAdmin(admin.ModelAdmin):
    inlines = [BookInline]
  • TabularInline: Отображает связанные объекты в виде компактной таблицы.
  • StackedInline: Отображает связанные объекты в виде блоков друг под другом.

Массовые операции: Django Actions

Административные действия (Actions) позволяют выполнить одну и ту же операцию сразу над множеством выбранных галочками записей в списке.

По умолчанию в Django доступно только одно действие — "Удалить выбранные объекты". Однако мы можем писать любые собственные действия!

Примеры действий:

  • Опубликовать все выбранные статьи.
  • Выдать скидку 10% на выделенные товары.
  • Снять с продажи выбранные книги.
  • Сгенерировать PDF-отчет по заказам.

Реализация кастомного действия (Action)

Функция действия принимает три аргумента: modeladmin (текущий класс админки), request (объект запроса) и queryset (выбранные пользователем объекты).

# 1. Объявляем функцию действия с декоратором
@admin.action(description='Снять выбранные книги с продажи')
def make_unavailable(modeladmin, request, queryset):
    updated = queryset.update(is_available=False)
    # Выводим сообщение пользователю в интерфейсе
    modeladmin.message_user(request, f'Успешно обновлено книг: {updated}.')

# 2. Регистрируем действие в классе ModelAdmin
@admin.register(Book)
class BookAdmin(admin.ModelAdmin):
    list_display = ('title', 'is_available')
    actions = [make_unavailable]

Безопасность и права доступа

Django Admin тесно связан со встроенной системой авторизации django.contrib.auth:

  • Пользователи и группы: Права можно выдавать индивидуально или настраивать целые роли (например, "Редакторы", "Модераторы").
  • Типы прав: Для каждой модели создаются права: View (Просмотр), Add (Создание), Change (Редактирование), Delete (Удаление).

Управление правами в коде

Вы можете программно переопределять права доступа в классе ModelAdmin:

def has_delete_permission(self, request, obj=None):
    # Запретить удаление всем, кроме суперпользователей
    return request.user.is_superuser

Резюме и практические рекомендации

  • Панель администратора Django — мощный инструмент для внутреннего управления проектом.
  • Для простых проектов админка может служить готовым интерфейсом управления (back-office).
  • Никогда не давайте обычным пользователям сайта доступ к админ-панели. Для них создавайте обычные публичные Django-формы и представления.
  • Изучите возможности настройки с помощью list_display, list_filter, search_fields, inlines и actions — этого достаточно для 95% задач администрирования.
