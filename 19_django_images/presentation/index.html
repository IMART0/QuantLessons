Практика работы с изображениями

Урок 19: Как настроить загрузку медиафайлов в Django, работать с Pillow, оптимизировать картинки на лету, конвертировать в WebP и делать кастомные валидаторы.

Дата: 4 июля  |  Время: 11:30 - 12:50

Зачем сайту изображения?

Практически любое современное веб-приложение работает с динамическими изображениями:

  • Аватары пользователей: персонализация профилей.
  • Интернет-магазины: фотографии товаров в каталоге.
  • Блоги и новости: обложки и иллюстрации к статьям.
  • Социальные сети: публикации пользователей с галереями.
В отличие от стилей и скриптов, эти изображения загружаются пользователями в процессе работы сайта, а не разработчиками.

Технические вызовы:

  • Где физически хранить файлы на сервере?
  • Как связать файл с записью в базе данных?
  • Как защитить сервер от загрузки вредоносных скриптов под видом картинок?
  • Как сжимать файлы, чтобы сайт не тормозил при загрузке картинок по 15 МБ?

Static vs Media: Принципиальное отличие

В Django файлы разделяются на две независимые категории. Смешивать их — грубейшая ошибка архитектуры.

Критерий Статические файлы (Static) Медиафайлы (Media)
Что это? CSS, JS, иконки сайта, шрифты, фоновые картинки верстки. Аватары, файлы документов, фотографии товаров, чеки.
Кто создает? Разработчик (вместе с кодом проекта). Пользователь (через формы на работающем сайте).
Где хранятся? В папках приложений или общей static/. Под гитом. В специальной папке media/. Никогда не под гитом!
Изменяемость Не меняются во время работы приложения. Постоянно загружаются, удаляются и перезаписываются.

Настройка Media в settings.py

Чтобы Django понимал, куда сохранять загруженные файлы и по каким ссылкам их отдавать, нужно настроить две переменные:

import os
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent.parent

# 1. Физический путь на диске, куда будут сохраняться файлы
MEDIA_ROOT = os.path.join(BASE_DIR, 'media')

# 2. URL-префикс, по которому файлы будут доступны в браузере
MEDIA_URL = '/media/'
Важно: убедитесь, что папка media/ добавлена в ваш файл .gitignore, чтобы пользовательские файлы случайно не улетели в репозиторий GitHub.

Раздача медиафайлов: urls.py

В режиме разработки (когда DEBUG = True) встроенный сервер Django может раздавать медиафайлы. Для этого нужно модифицировать главный urls.py:

from django.contrib import admin
from django.urls import path, include
from django.conf import settings
from django.conf.urls.static import static

urlpatterns = [
    path('admin/', admin.site.urls),
    # ... ваши основные маршруты ...
]

# Раздаем медиафайлы только во время разработки!
if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
Production-подсказка: При DEBUG = False функция static() вернет пустой список. На реальном сервере раздачей картинок занимается быстрый веб-сервер Nginx или облачное хранилище (S3).

Поле модели: ImageField и библиотека Pillow

Для работы с картинками Django предоставляет специальное поле — models.ImageField.

class Profile(models.Model):
    user = models.OneToOneField(
        User, on_delete=models.CASCADE
    )
    avatar = models.ImageField(
        upload_to='avatars/', 
        blank=True, 
        null=True
    )
  • upload_to='avatars/' — файлы будут складываться в MEDIA_ROOT/avatars/.
  • Можно использовать шаблон даты: upload_to='avatars/%Y/%m/%d/'.
Внимание: ImageField не будет работать без библиотеки Pillow!

Pillow — это стандартная библиотека Python для обработки изображений. Если вы попытаетесь применить миграцию с ImageField без неё, Django выдаст ошибку.

pip install Pillow

Как файлы хранятся в базе данных и на диске?

Важно понимать разделение обязанностей между БД и файловой системой:

  • В базе данных хранится обычная строка с относительным путем к файлу (например, "avatars/avatar_123.jpg").
  • На жестком диске лежит сам файл по пути MEDIA_ROOT + "avatars/avatar_123.jpg".

При получении объекта из БД, поле ImageField оборачивается в объект ImageFieldFile, предоставляющий полезные свойства:

profile = Profile.objects.get(id=1)
print(profile.avatar.name)  # 'avatars/avatar_123.jpg'
print(profile.avatar.path)  # Абсолютный путь: '/home/user/project/media/avatars/avatar_123.jpg'
print(profile.avatar.url)   # URL для браузера: '/media/avatars/avatar_123.jpg'
print(profile.avatar.width) # Ширина в пикселях (например, 800)
print(profile.avatar.height)# Высота в пикселях (например, 600)

HTML-форма для загрузки файлов

Для загрузки файлов на сервер HTML-форма должна соответствовать трем жестким правилам:

  1. Метод отправки должен быть только POST.
  2. Обязательно должен присутствовать атрибут enctype="multipart/form-data". Без него файлы просто не передадутся в теле запроса!
  3. Поля выбора файлов имеют тип type="file".
<!-- Шаблон: edit_profile.html -->
<form method="post" enctype="multipart/form-data">
    {% csrf_token %}
    {{ form.as_p }}
    <button type="submit">Сохранить изменения</button>
</form>
Если вы забыли написать enctype="multipart/form-data", то в views.py список файлов придет абсолютно пустым. Это самая частая ошибка новичков!

Обработка файлов во views.py

Обычные текстовые поля формы приходят в словаре request.POST. Файлы же приходят в отдельном словаре request.FILES. Форма должна инициализироваться обоими словарями:

# views.py
def edit_profile(request):
    profile = request.user.profile
    if request.method == 'POST':
        # Передаем request.POST и request.FILES!
        form = ProfileForm(request.POST, request.FILES, instance=profile)
        if form.is_valid():
            form.save()
            return redirect('profile_detail')
    else:
        form = ProfileForm(instance=profile)
    return render(request, 'edit_profile.html', {'form': form})
При вызове form.save() Django автоматически берет файл из временного хранилища, сохраняет его на диск в MEDIA_ROOT/upload_to и записывает путь к нему в базу данных.

Отображение картинок в HTML-шаблонах

При выводе изображений в шаблонах нужно всегда предусматривать случай, когда картинка не загружена (поле пустое/None), иначе сайт выдаст ValueError при обращении к .url.

<!-- Шаблон профиля пользователя -->
<div class="profile-card">
    <h3>{{ profile.user.username }}</h3>
    
    {% if profile.avatar %}
        <!-- Если аватар загружен -->
        <img src="{{ profile.avatar.url }}" alt="Аватар" class="avatar">
    {% else %}
        <!-- Если аватара нет — показываем заглушку из static -->
        <img src="{% static 'images/default-avatar.png' %}" alt="Аватар по умолчанию" class="avatar">
    {% endif %}
</div>
Никогда не пишите <img src="{{ profile.avatar }}">. Поле модели возвращает объект файла. Чтобы получить ссылку для атрибута src, нужно обязательно обратиться к свойству .url!

Проблема: тяжелые оригиналы файлов

Современные смартфоны делают снимки с разрешением 4000х3000 пикселей весом от 8 до 15 МБ.

Что будет, если сохранять их без изменений?

  • Расход места: 1000 пользователей загрузят аватаров на 10 ГБ.
  • Тормоза у клиентов: браузер будет скачивать 10 МБ картинку, чтобы показать кружочек 50x50 пикселей.
  • Перегрузка сети: сервер быстро исчерпает лимит трафика.
Решение: перехватывать загружаемый файл в момент сохранения, пропорционально уменьшать его разрешение (например, до 400х400) и сжимать качество.

В Django для этого переопределяют метод save() модели.

Переопределение метода save(): Теория

Каждая модель Django имеет метод save(), который отвечает за запись данных в БД. Мы можем встроиться в этот процесс:

class Profile(models.Model):
    # ... поля ...
    avatar = models.ImageField(upload_to='avatars/')

    def save(self, *args, **kwargs):
        # 1. Сначала выполняем логику обработки картинки (ресайз/сжатие)
        if self.avatar:
            self.resize_avatar()
            
        # 2. Вызываем оригинальный метод save() родительского класса models.Model
        super().save(*args, **kwargs)
Это гарантирует, что изображение будет сжато при любом сохранении — будь то через форму на сайте, через Django-админку или через API!

Ресайз изображения на лету с Pillow

Код переопределения save() с использованием библиотеки PIL (Pillow):

from django.core.files.base import ContentFile
from PIL import Image
import io

class Profile(models.Model):
    avatar = models.ImageField(upload_to='avatars/')

    def save(self, *args, **kwargs):
        if self.avatar:
            # Открываем изображение из памяти
            img = Image.open(self.avatar)
            
            # Если разрешение больше 300x300, уменьшаем с сохранением пропорций
            if img.width > 300 or img.height > 300:
                img.thumbnail((300, 300))
                
                # Сохраняем измененную картинку во временный буфер в памяти
                buffer = io.BytesIO()
                img.save(buffer, format=img.format)
                
                # Перезаписываем файл в поле модели перед сохранением в БД
                self.avatar.save(self.avatar.name, ContentFile(buffer.getvalue()), save=False)
                
        super().save(*args, **kwargs)

Конвертация в современный формат WebP

WebP сжимает изображения на 30% лучше, чем JPEG, без потери качества. Сконвертируем файл прямо при загрузке:

def save(self, *args, **kwargs):
    if self.avatar:
        img = Image.open(self.avatar)
        
        # Конвертируем в RGB (WebP не поддерживает RGBA в некоторых JPEG-исходниках)
        if img.mode in ('RGBA', 'LA'):
            img = img.convert('RGB')
            
        # Уменьшаем размер
        img.thumbnail((300, 300))
        
        # Меняем расширение файла в имени на .webp
        name_without_ext = os.path.splitext(self.avatar.name)[0]
        webp_name = f"{name_without_ext}.webp"
        
        # Записываем в WebP в буфер памяти
        buffer = io.BytesIO()
        img.save(buffer, format='WEBP', quality=85) # Сжатие 85% качества
        
        self.avatar.save(webp_name, ContentFile(buffer.getvalue()), save=False)
        
    super().save(*args, **kwargs)

Валидаторы для картинок (размер и вес)

Иногда нужно запретить пользователю загружать слишком тяжелые файлы или картинки с неподходящим соотношением сторон еще на этапе проверки формы:

from django import forms
from django.core.exceptions import ValidationError

class ProfileForm(forms.ModelForm):
    class Meta:
        model = Profile
        fields = ['avatar']

    def clean_avatar(self):
        avatar = self.cleaned_data.get('avatar')
        if avatar:
            # 1. Проверяем вес файла (в байтах). Ограничим 2 МБ.
            if avatar.size > 2 * 1024 * 1024:
                raise ValidationError("Размер файла не должен превышать 2 МБ!")
            
            # 2. Проверяем разрешение с помощью Pillow
            img = Image.open(avatar)
            if img.width < 150 or img.height < 150:
                raise ValidationError("Разрешение картинки должно быть не меньше 150x150 px!")
        return avatar

Кастомизация виджета загрузки файлов

Стандартный HTML виджет <input type="file"> выглядит невзрачно. Django по умолчанию использует виджет ClearableFileInput, который выводит текущий файл и галочку «Очистить».

Мы можем стилизовать или заменить виджет в форме:

class ProfileForm(forms.ModelForm):
    class Meta:
        model = Profile
        fields = ['avatar']
        widgets = {
            'avatar': forms.ClearableFileInput(attrs={
                'class': 'form-control-file',
                'accept': 'image/*' # только картинки
            })
        }
Атрибут accept="image/*" открывает у пользователя окно выбора файлов, сразу отфильтрованное по изображениям, что повышает удобство работы!

Для продвинутого UI можно написать кастомный виджет, который рендерит миниатюру картинки прямо рядом с кнопкой выбора файла.

Полный цикл загрузки аватара

Давайте проследим путь картинки от клика пользователя до сохранения в базу:

  1. Пользователь выбирает файл photo.jpg на компьютере и нажимает «Отправить».
  2. Браузер кодирует файл в multipart-формат и отправляет HTTP POST запрос на сервер.
  3. Django принимает запрос, видит multipart-данные, парсит файлы и временно помещает их в память (или временную папку) в виде объекта InMemoryUploadedFile в request.FILES.
  4. Вьюха передает request.FILES['avatar'] в ProfileForm.
  5. Метод form.is_valid() запускает валидаторы (проверяет вес файла и расширение).
  6. При вызове form.save() срабатывает переопределенный save() в модели.
  7. Pillow открывает файл из памяти, уменьшает его, конвертирует в WebP, сохраняет на диск в media/avatars/photo.webp.
  8. В БД записывается путь: "avatars/photo.webp". Пользователю рендерится страница с новым аватаром.

Безопасность: как защитить сервер?

Загрузка файлов пользователями — одна из самых опасных зон веб-приложения. Злоумышленник может попытаться залить вредоносный PHP/Python скрипт под видом картинки.

Атака Pixel Flood (DOS-атака):
Злоумышленник загружает картинку размером 1х1 пиксель, но в заголовке файла указывает разрешение 100 000 х 100 000 пикселей. При попытке открыть её Pillow выделит гигабайты ОЗУ, и сервер упадет.

Меры защиты:

  • Не доверяйте расширениям: проверяйте реальное содержимое файла (Django ImageField делает это автоматически через Pillow, проверяя заголовки картинки).
  • Запрет исполнения скриптов: на боевом сервере в Nginx запретите выполнение любых скриптов (.php, .py, .sh) в папке media/.
  • Ограничивайте размер: проверяйте file.size в валидаторах формы.

Типичные ошибки при работе с изображениями

  • Забыт enctype="multipart/form-data" в HTML-форме: файлы просто не отправляются на сервер, request.FILES остается пустым.
  • Отсутствует проверка на пустой файл в шаблоне: код {{ profile.avatar.url }} вызовет ошибку ValueError: The 'avatar' attribute has no file associated with it., если пользователь не загрузил аватар. Пользуйтесь {% if profile.avatar %}!
  • Попытка хранить файлы в Git: папка media/ должна быть добавлена в .gitignore. Пользовательские файлы уникальны для каждого развернутого сервера.
  • Забытый импорт Pillow: без установленного Pillow проект не запустится, ругаясь на SystemCheckError.

Резюме и план практической работы

  • Для медиафайлов используйте MEDIA_ROOT и MEDIA_URL.
  • Для картинок всегда используйте models.ImageField (требует Pillow).
  • Всегда сжимайте картинки и уменьшайте разрешение в методе save().
  • Используйте современный формат WebP для ускорения загрузки сайта.
  • Проверяйте размер и разрешение файлов в формах через валидаторы.
