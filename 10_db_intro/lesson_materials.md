## 1. Паспорт урока

*   **Тема:** Реляционная модель данных, проектирование схем БД, связи (1:1, 1:N, N:M) и основы языка запросов SQL (SELECT, JOIN, GROUP BY).
*   **Продолжительность:** 1 урок (80 минут).
*   **Цели урока:**
    1.  **Образовательные:** Изучить теоретические основы реляционных баз данных (таблицы, строки, колонки, типы данных, ограничения). Понять назначение первичных (PK) и внешних (FK) ключей. Научиться проектировать связи один-к-одному (1:1), один-ко-многим (1:N) и многие-ко-многим (N:M). Освоить синтаксис SQL для выборки данных (`SELECT`), фильтрации (`WHERE`, `LIKE`, `IS NULL`), сортировки (`ORDER BY`), объединения таблиц (`JOIN`) и группировки с агрегацией (`GROUP BY`, `HAVING`).
    2.  **Развивающие:** Сформировать аналитическое мышление при структурировании информации и проектировании схем данных, развить навыки написания декларативного кода (запросов SQL) и понимание логики работы СУБД.
    3.  **Воспитательные:** Прививать аккуратность в разработке архитектуры данных, понимание важности безопасности и целостности информации на примере ограничений базы данных.
*   **Планируемые результаты обучения (Outcomes):**
    *   **Знать:** Разницу между БД и СУБД, свойства реляционной таблицы, назначение PK и FK, типы связей между таблицами, классификацию команд SQL (DDL, DML, DQL), логический порядок выполнения SQL-запроса.
    *   **Уметь:** Проектировать структуру базы данных для реальных задач, писать SQL-запросы для извлечения данных с фильтрами, связывать таблицы с помощью `INNER JOIN` и `LEFT JOIN`, группировать данные и вычислять агрегированные значения (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`), фильтровать сгруппированные данные через `HAVING`.
    *   **Владеть:** Навыками создания локальной тестовой базы данных SQLite через Python и отладки синтаксических ошибок SQL-запросов.
*   **Требования к подготовке (Prerequisites):**
    *   Базовые навыки работы на компьютере, знание типов данных (целые, дробные числа, строки, булевы значения).
    *   Понимание основных алгоритмических конструкций (условия, циклы) и базовый синтаксис Python для понимания живой демонстрации.

## 5. Методический скрипт преподавателя (Teacher Script)

### Введение и актуализация (Слайд 1-2)
*   **Преподаватель:** «Приветствую вас, ребята! Мы с вами уже изучили основы HTML, CSS, научились запускать Django и выводить красивые страницы с помощью динамических шаблонов. Но откуда берутся данные для этих страниц? Где хранятся списки товаров в интернет-магазинах, профили пользователей ВКонтакте или расписание уроков? 
    Обычно в файлах? Представьте, что у вас есть файл `users.txt`. Если одновременно 500 человек захотят зарегистрироваться, их запросы начнут перезаписывать этот файл одновременно. В итоге файл сломается, а данные сотрутся.
    Поэтому программисты используют **Базы данных** и специальные программы для работы с ними — **СУБД** (Системы управления базами данных). СУБД умеет работать с огромными объемами информации, гарантирует, что при сбое питания данные не пропадут, и умеет мгновенно выдавать нужную строчку из миллионов.»

### Реляционная модель и сущности (Слайды 3-5)
*   **Преподаватель:** «Перейдем к слайду 3. Мы будем изучать самую популярную модель баз данных — **реляционную**. От слова *relation*, то есть "отношение" или, проще говоря, таблица.
    Таблица состоит из:
    - **Строк** (записей). Каждая строка описывает один конкретный объект. Например, одного ученика.
    - **Колонок** (полей). Описывают свойства. У каждого столбца есть строго заданный тип данных: число, текст или дата. В реляционной таблице нельзя вписать текст в колонку для возраста.
    
    Слайд 4. Как СУБД отличает строки друг от друга? Для этого служит **Первичный ключ** (Primary Key, PK). Это один или несколько столбцов, значение в которых гарантированно уникально для каждой строки. Например, ваш СНИЛС или номер паспорта. Но на практике разработчики чаще создают искусственное поле `id` с типом INTEGER, которое автоматически увеличивается на 1 при добавлении новой строки.
    
    Слайд 5. Как же связать таблицы между собой? Например, у нас есть таблица учеников и таблица школьных классов. Мы не хотим писать название класса "10-А физ-мат" прямо в строке каждого ученика, ведь если класс переименуют, нам придется менять тысячи строк.
    Вместо этого мы пишем `id` класса в специальную колонку таблицы учеников. Такая колонка называется **Внешним ключом** (Foreign Key, FK). Она ссылается на первичный ключ другой таблицы.»

### Типы связей (Слайды 6-8)
*   **Преподаватель:** «Существует три основных типа связей между таблицами.
    Слайд 6. Связь **Один ко многим** (1:N). Это когда одна запись первой таблицы связана со многими записями из второй. При этом запись из второй таблицы связана только с одной записью из первой. Например, у одного класса много учеников, но ученик учится в конкретном одном классе. Правило проектирования: Внешний ключ (FK) всегда добавляется в таблицу на сторону "Многие" (то есть в таблицу учеников).
    
    Слайд 7. Связь **Многие ко многим** (N:M). Например, один ученик может ходить в несколько кружков (физика, робототехника), а в каждом кружке занимается много учеников. Мы не можем просто вставить FK в таблицу учеников или кружков, это нарушит структуру. Решение: создается вспомогательная **таблица-связка** (Junction Table). В ней всего две основные колонки: `student_id` (FK на ученика) и `club_id` (FK на кружок). Если Иван записан на 2 кружка, в таблице-связке появятся 2 записи.
    
    Слайд 8. Связь **Один к одному** (1:1). Каждой строке из первой таблицы соответствует ровно одна из второй. Например, у гражданина РФ может быть только один действующий паспорт, а паспорт принадлежит только одному человеку. В этом случае мы ставим FK в любую из двух таблиц и обязательно вешаем на него ограничение уникальности `UNIQUE`.»

### Основы SQL и простые запросы (Слайды 9-12)
*   **Преподаватель:** «Слайд 9. Чтобы общаться с СУБД, используется язык **SQL** (Structured Query Language). Он декларативный. Это значит, что мы пишем "что мы хотим получить", а не "как это вычислить" (в отличие от циклов `for` в Python).
    
    Слайд 10. Самый частый запрос — это получение данных `SELECT`.
    Формула: `SELECT <колонки> FROM <таблица> WHERE <условия>`.
    Мы можем отфильтровать строки. Например, `WHERE age > 15 AND class_id = 1`.
    
    Слайд 11. Что делать, если мы ищем текст не по точному совпадению, а по шаблону? Используем оператор `LIKE`. Например, `last_name LIKE 'Ива%'` найдет всех Ивановых, Иванченко и т.д. Знак `%` означает любое количество любых символов.
    Важно помнить про значение `NULL` — это пустота (отсутствие значения). В базах данных `NULL` нельзя сравнивать через оператор равенства `=`. Запрос `WHERE phone = NULL` вернет ошибку или пустой результат. Правильно писать `WHERE phone IS NULL`.
    
    Слайд 12. Сортировка результатов делается через `ORDER BY`. Можно сортировать по возрастанию (`ASC`) и по убыванию (`DESC`). А ограничить количество выданных строк можно с помощью `LIMIT`. Это полезно, например, чтобы выдать "топ-3 самых дорогих товаров".»

### JOIN, GROUP BY и порядок выполнения (Слайды 13-19)
*   **Преподаватель:** «Слайд 13. Данные разнесены по таблицам. Но как вывести имя ученика вместе с именем его класса? Нам нужно объединить таблицы в одном запросе. Для этого служит оператор `JOIN`.
    
    Слайд 14. **INNER JOIN** (внутреннее объединение). Оно соединяет строки только тогда, когда условие совпадает в обеих таблицах. Если у нас есть новый ученик, которому еще не присвоили класс, он в результат `INNER JOIN` не попадет.
    
    Слайд 15. **LEFT JOIN** (левое внешнее объединение). Оно сохраняет все строки из "левой" (первой) таблицы, даже если для них нет пары в "правой" таблице. У нашего нового ученика без класса в колонке названия класса будет стоять `NULL`.
    
    Слайд 16. **Агрегатные функции** позволяют вычислять математические параметры по группам строк. `COUNT` считает строки, `SUM` складывает значения, `AVG` находит среднее.
    
    Слайд 17. Оператор **GROUP BY** группирует строки. Например, мы хотим узнать не средний возраст по всей школе, а средний возраст *в каждом классе отдельно*. Мы пишем `GROUP BY class_id`. Запомните: если колонка выбрана в `SELECT` и она не обернута в агрегатную функцию (как `COUNT`), она **обязательно** должна быть указана в `GROUP BY`.
    
    Слайд 18. Как отфильтровать сгруппированные данные? Например, оставить только те классы, где учится больше 15 человек. Мы не можем написать это условие в `WHERE`, потому что `WHERE` фильтрует строки до подсчета количества! В таких случаях используется оператор **HAVING**. Запомните: `WHERE` — для исходных строк, `HAVING` — для уже сгруппированных данных.
    
    Слайд 19. Движок базы данных выполняет запрос совсем не в том порядке, в котором мы его пишем. Сначала он определяет таблицы (`FROM`, `JOIN`), затем фильтрует сырые строки (`WHERE`), группирует их (`GROUP BY`), фильтрует группы (`HAVING`), и только в самом конце выбирает нужные колонки (`SELECT`), сортирует (`ORDER BY`) и обрезает результат (`LIMIT`).»

## 6. Демонстрации (Demonstrations)

Преподаватель запускает интерактивную демонстрацию с использованием встроенной в Python библиотеки `sqlite3`. Это позволяет показать работу реляционной СУБД прямо в консоли без установки тяжелого серверного ПО.

### Скрипт демонстрации (`demo_db.py`)
```python
import sqlite3

# 1. Создаем подключение к базе данных в оперативной памяти (in-memory)
conn = sqlite3.connect(':memory:')
cursor = conn.cursor()

# Включаем поддержку внешних ключей в SQLite (по умолчанию отключена)
cursor.execute("PRAGMA foreign_keys = ON;")

# 2. Создаем таблицы классов и учеников (DDL)
print("--- Создание таблиц ---")
cursor.execute("""
CREATE TABLE classes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT UNIQUE NOT NULL
);
""")

cursor.execute("""
CREATE TABLE students (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    first_name TEXT NOT NULL,
    last_name TEXT NOT NULL,
    age INTEGER NOT NULL,
    class_id INTEGER,
    email TEXT,
    FOREIGN KEY (class_id) REFERENCES classes(id)
);
""")

# 3. Вставка данных (DML)
print("--- Вставка тестовых данных ---")
classes_data = [('10-А',), ('10-Б',), ('11-А',)]
cursor.executemany("INSERT INTO classes (name) VALUES (?);", classes_data)

students_data = [
    ('Иван', 'Иванов', 15, 1, 'ivan@kvant.ru'),
    ('Анна', 'Петрова', 16, 2, 'anna@kvant.ru'),
    ('Петр', 'Сидоров', 15, 1, None),
    ('Елена', 'Козлова', 17, 2, 'elena@kvant.ru'),
    ('Сергей', 'Морозов', 16, None, None) # Ученик без класса и без email
]
cursor.executemany("""
    INSERT INTO students (first_name, last_name, age, class_id, email)
    VALUES (?, ?, ?, ?, ?);
""", students_data)
conn.commit()

# 4. Выполнение демонстрационных запросов (DQL)
print("\n--- Запрос 1: Простая выборка с фильтрацией (ученики старше 15 лет) ---")
cursor.execute("SELECT first_name, last_name, age FROM students WHERE age > 15;")
for row in cursor.fetchall():
    print(f"Имя: {row[0]}, Фамилия: {row[1]}, Возраст: {row[2]}")

print("\n--- Запрос 2: Поиск по шаблону (LIKE) и проверка на NULL ---")
cursor.execute("SELECT first_name, last_name FROM students WHERE email IS NULL;")
print("Ученики без почты:")
for row in cursor.fetchall():
    print(f"- {row[0]} {row[1]}")

print("\n--- Запрос 3: INNER JOIN (ученики с их классами) ---")
cursor.execute("""
    SELECT students.first_name, students.last_name, classes.name
    FROM students
    INNER JOIN classes ON students.class_id = classes.id;
""")
for row in cursor.fetchall():
    print(f"Ученик: {row[0]} {row[1]} | Класс: {row[2]}")

print("\n--- Запрос 4: LEFT JOIN (все ученики, включая тех, у кого нет класса) ---")
cursor.execute("""
    SELECT students.first_name, students.last_name, classes.name
    FROM students
    LEFT JOIN classes ON students.class_id = classes.id;
""")
for row in cursor.fetchall():
    class_name = row[2] if row[2] else "Класс не назначен"
    print(f"Ученик: {row[0]} {row[1]} | Класс: {class_name}")

print("\n--- Запрос 5: GROUP BY и агрегация (кол-во учеников и средний возраст по классам) ---")
cursor.execute("""
    SELECT classes.name, COUNT(students.id), AVG(students.age)
    FROM classes
    LEFT JOIN students ON classes.id = students.class_id
    GROUP BY classes.id, classes.name;
""")
for row in cursor.fetchall():
    print(f"Класс: {row[0]} | Учеников: {row[1]} | Средний возраст: {row[2]:.1f}")

# Закрываем соединение
conn.close()
```

### Построчное объяснение демонстрационного скрипта:
*   `line 1`: Импортируем стандартный модуль `sqlite3` для работы с БД SQLite.
*   `line 4`: Инициализируем базу данных в оперативной памяти с помощью специальной строки `:memory:`. База будет уничтожена при завершении работы программы, что идеально для тестов.
*   `line 5`: Создаем объект `cursor` (курсор), который служит для отправки запросов к базе и получения результатов.
*   `line 8`: По умолчанию в SQLite отключена проверка ограничений внешних ключей. Мы включаем её принудительно командой `PRAGMA foreign_keys = ON;`, чтобы СУБД следила за целостностью данных.
*   `line 11-28`: Создаем две таблицы с помощью `CREATE TABLE`. Поле `id` с ключевыми словами `PRIMARY KEY AUTOINCREMENT` будет автоматически генерироваться СУБД. В таблице `students` объявляем внешний ключ `class_id` ссылающийся на `classes(id)`.
*   `line 31-45`: Используем метод `executemany` для безопасной пакетной вставки данных с защитой от SQL-инъекций (через плейсхолдеры `?`).
*   `line 48-77`: Выполняем различные `SELECT` запросы с фильтрацией `WHERE`, проверкой `IS NULL` и объединениями `INNER JOIN` / `LEFT JOIN`, выводя результаты через итерацию по `cursor.fetchall()`.
*   `line 79-88`: Демонстрируем группировку `GROUP BY` по классам совместно с агрегатными функциями `COUNT` и `AVG` для вычисления аналитических показателей.

### Упражнение 1 (Базовое): Простая выборка с фильтрацией (SELECT, WHERE)
*   **Условие:** Напишите SQL-запрос для выбора имен (`first_name`), фамилий (`last_name`) и возраста (`age`) сотрудников из таблицы `employees`, у которых зарплата (`salary`) строго больше 60000 рублей, а должность (`position`) равна 'Программист'.
*   **Входные данные (схема таблицы `employees`):**
    ```sql
    id INTEGER PRIMARY KEY,
    first_name TEXT,
    last_name TEXT,
    age INTEGER,
    position TEXT,
    salary INTEGER
    ```
*   **Ожидаемый результат:** Строки, содержащие имя, фамилию и возраст сотрудников, удовлетворяющих обоим условиям.
*   **Подсказка:** Используйте оператор `AND` для объединения двух условий в секции `WHERE`.
*   **Решение:**
    ```sql
    SELECT first_name, last_name, age 
    FROM employees 
    WHERE salary > 60000 AND position = 'Программист';
    ```
*   **Объяснение:** Запрос извлекает только указанные столбцы `first_name`, `last_name`, `age` из таблицы `employees`. Секция `WHERE` отфильтровывает строки, оставляя только те, где значение в столбце `salary` больше 60000 и в столбце `position` в точности совпадает со строкой 'Программист'.

### Упражнение 2 (Базовое): Поиск по шаблону и пустые значения (LIKE, IS NULL)
*   **Условие:** Напишите SQL-запрос, который находит контакты всех студентов (`students`), у которых не указан адрес электронной почты (`email` равен NULL), а фамилия (`last_name`) заканчивается на 'ов' или 'ова'. Выведите имя (`first_name`) и фамилию (`last_name`).
*   **Входные данные (таблица `students`):**
    ```sql
    id INTEGER PRIMARY KEY,
    first_name TEXT,
    last_name TEXT,
    email TEXT
    ```
*   **Ожидаемый результат:** Список имен и фамилий студентов, соответствующих условию.
*   **Подсказка:** Помните, что `NULL` проверяется с помощью `IS NULL`. Для поиска окончания строки используйте `LIKE '%ов'`. Обязательно группируйте условия `OR` скобками, если объединяете их с `AND`.
*   **Решение:**
    ```sql
    SELECT first_name, last_name 
    FROM students 
    WHERE email IS NULL 
      AND (last_name LIKE '%ов' OR last_name LIKE '%ова');
    ```
*   **Объяснение:** Мы проверяем отсутствие email через `email IS NULL`. Оператор `LIKE '%ов'` означает, что перед 'ов' может идти любая последовательность символов. Скобки важны: приоритет `AND` выше, чем у `OR`. Без скобок запрос вернул бы либо студентов без email с фамилией на 'ов', либо *любых* студентов с фамилией на 'ова' (даже с заполненным email).

### Упражнение 3 (Базовое): Сортировка и ограничение (ORDER BY, LIMIT)

*   **Входные данные (таблица `products`):**
    ```sql
    id INTEGER PRIMARY KEY,
    title TEXT,
    price REAL,
    category_id INTEGER,
    stock INTEGER
    ```
*   **Ожидаемый результат:** Ровно 3 строки с названиями и ценами товаров.
*   **Подсказка:** Сначала отфильтруйте данные, затем сгруппируйте/отсортируйте через `ORDER BY price DESC`, и ограничьте количество строк с помощью `LIMIT`.
*   **Решение:**
    ```sql
    SELECT title, price 
    FROM products 
    WHERE category_id = 12 AND stock > 0
    ORDER BY price DESC
    LIMIT 3;
    ```
*   **Объяснение:** СУБД сначала отсекает товары не из категории 12 или отсутствующие на складе. Затем упорядочивает оставшиеся товары по цене от большей к меньшей (`DESC`). После сортировки `LIMIT 3` оставляет первые три записи (самые дорогие товары).

### Упражнение 4 (Среднее): Проектирование схемы базы данных (DDL, Связи)
*   **Условие:** Спроектируйте базу данных для автосалона. В базе должны быть производители автомобилей (`brands`) и сами автомобили (`cars`). 
    - У бренда есть название и страна основания.
    - У автомобиля есть модель, год выпуска, цена и бренд-производитель (связь 1:N — у машины один бренд, у бренда много машин).
    Напишите SQL-запросы для создания этих двух таблиц с соблюдением целостности связей.
*   **Входные данные:** Описание предметной области.
*   **Ожидаемый результат:** Две SQL-команды `CREATE TABLE` с первичными и внешними ключами.

*   **Решение:**

    CREATE TABLE brands (

    CREATE TABLE cars (

### Упражнение 5 (Среднее): Объединение таблиц (INNER / LEFT JOIN)
*   **Условие:** Есть таблицы `books` (книги) и `genres` (жанры). Напишите SQL-запрос, который возвращает название книги (`title`) и название её жанра (`genre_name`). В результирующей выборке должны остаться абсолютно **все** жанры из базы данных, даже если к этому жанру сейчас не привязана ни одна книга. Результат отсортируйте по названию жанра.
*   **Входные данные (схемы таблиц):**
    `genres` (id [PK], genre_name)  
    `books` (id [PK], title, genre_id [FK])
*   **Ожидаемый результат:** Таблица со столбцами `title` и `genre_name`. Для жанров без книг в столбце `title` должен стоять `NULL`.
*   **Подсказка:** Так как нужно вывести все жанры независимо от наличия книг, используйте `LEFT JOIN`, сделав таблицу `genres` левой (первой в запросе).
*   **Решение:**
    ```sql
    SELECT books.title, genres.genre_name
    FROM genres
    LEFT JOIN books ON genres.id = books.genre_id
    ORDER BY genres.genre_name ASC;
    ```
*   **Объяснение:** Конструкция `FROM genres LEFT JOIN books` берет все строки из таблицы `genres`. Если для жанра находится книга с совпадением `genres.id = books.genre_id`, они объединяются. Если книг такого жанра нет, поля таблицы `books` заполняются значениями `NULL`.

### Упражнение 6 (Сложное): Группировка с фильтрацией по агрегатам (JOIN + GROUP BY + HAVING)
*   **Условие:** Напишите SQL-запрос для анализа успеваемости студентов. База данных содержит таблицы `students` (студенты) и `grades` (оценки). Нам нужно найти студентов, у которых **средний балл** по всем полученным оценкам строго больше **4.5**. Выведите имя (`first_name`), фамилию (`last_name`) студента и его точный средний балл (назовите колонку `average_grade`). Результат отсортируйте по среднему баллу от самого высокого к низшему.
*   **Входные данные (схемы таблиц):**
    `students` (id [PK], first_name, last_name)  
    `grades` (id [PK], student_id [FK], subject TEXT, grade INTEGER)
*   **Ожидаемый результат:** Список студентов со средним баллом > 4.5, отсортированный по убыванию оценки.
*   **Подсказка:** Объедините таблицы по `student_id`. Сгруппируйте результат по идентификатору и имени/фамилии студента. Используйте агрегатную функцию `AVG` и отфильтруйте группы с помощью `HAVING`.
*   **Решение:**
    ```sql
    SELECT students.first_name, students.last_name, AVG(grades.grade) AS average_grade
    FROM students
    INNER JOIN grades ON students.id = grades.student_id
    GROUP BY students.id, students.first_name, students.last_name
    HAVING AVG(grades.grade) > 4.5
    ORDER BY average_grade DESC;
    ```
*   **Объяснение:** 
    1. `INNER JOIN` сопоставляет каждую оценку конкретному студенту.
    2. `GROUP BY students.id...` собирает все оценки каждого студента в отдельные группы.
    3. `AVG(grades.grade)` вычисляет среднее значение оценок внутри каждой группы.
    4. `HAVING AVG(grades.grade) > 4.5` отсекает группы (студентов), у которых среднее арифметическое не превышает 4.5.
    5. `ORDER BY average_grade DESC` выстраивает студентов в рейтинговом порядке от отличников вниз.

## 9. Часто задаваемые вопросы (FAQs)

1.  **В чем разница между Базой Данных и СУБД?**  
    *Ответ:* База данных — это само хранилище файлов с упорядоченной информацией. СУБД (например, PostgreSQL, SQLite) — это программное обеспечение, с помощью которого программист управляет этой базой данных (записывает, считывает, изменяет структуру).
2.  **Может ли быть таблица без первичного ключа (PK)?**  
    *Ответ:* Технически да, СУБД позволит создать такую таблицу. Однако на практике это грубейшая ошибка проектирования. Без PK вы не сможете однозначно идентифицировать конкретную строку, что приведет к дублированию данных и невозможности построить надежные связи.
3.  **В чем разница между суррогатным и естественным первичным ключом?**  
    *Ответ:* Естественный ключ — это реально существующее уникальное поле сущности (например, номер паспорта). Суррогатный ключ — это искусственно созданное поле (обычно числовой `id`), генерируемое базой данных автоматически. Суррогатные ключи надежнее, так как они никогда не меняются в отличие от паспортов, фамилий или телефонов.
4.  **Может ли первичный ключ состоять из нескольких колонок?**  
    *Ответ:* Да, такой ключ называется составным (Composite Key). Он часто применяется в промежуточных таблицах-связках при связи N:M, где уникальность гарантируется сочетанием двух внешних ключей (например, `student_id` + `club_id`).
5.  **Что такое ограничение внешнего ключа (Foreign Key Constraint)?**  
    *Ответ:* Это правило, гарантирующее ссылочную целостность. СУБД не позволит записать в колонку внешнего ключа значение, которого нет в первичных ключах связанной таблицы. Также это правило определяет, что делать при удалении родительской строки (например, выдать ошибку `RESTRICT` или автоматически удалить зависимые строки `CASCADE`).
6.  **Почему `NULL` нельзя сравнивать с помощью обычного знака равенства (`=`)?**  
    *Ответ:* `NULL` означает отсутствие значения (неизвестность). Логика SQL трехзначна: True, False и Unknown. Сравнение `NULL = NULL` или `age = NULL` дает результат Unknown (который СУБД трактует как False). Для проверки пустоты разработаны специальные операторы `IS NULL` и `IS NOT NULL`.
7.  **Что произойдет, если в INNER JOIN условие ON не найдет соответствий?**  
    *Ответ:* Строки, для которых условие связи ложно, просто отбрасываются и не попадают в результирующую таблицу.
8.  **В каких случаях LEFT JOIN предпочтительнее INNER JOIN?**  
    *Ответ:* Когда нам важно сохранить полную информацию из левой таблицы, даже если для некоторых строк нет связанных данных в правой. Например, вывести список всех клиентов и их заказов (включая тех клиентов, кто еще ничего не заказал).
9.  **В чем разница между WHERE и HAVING?**  
    *Ответ:* Ключевое отличие в моменте фильтрации. `WHERE` фильтрует строки до того, как они будут объединены в группы. `HAVING` фильтрует уже сгруппированные результаты, анализируя вычисленные агрегатные функции (например, среднее или сумму).
10. **Можно ли использовать агрегатные функции в секции WHERE?**  
    *Ответ:* Нет, категорически нельзя. Запрос вроде `SELECT * FROM students WHERE age > AVG(age)` вызовет ошибку СУБД. На момент работы `WHERE` среднее значение по таблице еще не вычислено. Для решения таких задач используются вложенные подзапросы (Subqueries).
11. **Что означает ошибка "column must appear in the GROUP BY clause or be used in an aggregate function"?**  
    *Ответ:* Это самая частая ошибка при группировке. Вы попытались вывести детальную колонку (например, `first_name`) вместе с агрегатной функцией (например, `MAX(age)`), сгруппировав только по `class_id`. СУБД не понимает, какое конкретно имя вывести из группы учеников одного класса, и блокирует запрос. Добавьте колонку в `GROUP BY` или оберните её в агрегат.
12. **Чем SQLite отличается от PostgreSQL?**  
    *Ответ:* SQLite — легковесная СУБД, хранящая всю базу в одном локальном файле на диске. Она не требует настройки сервера и идеальна для мобильных приложений, тестов и обучения. PostgreSQL — мощная клиент-серверная СУБД для высоких нагрузок, поддерживающая сложную аналитику и конкурентный доступ тысяч пользователей.
13. **Что такое транзакция в базах данных?**  
    *Ответ:* Транзакция — это группа последовательных операций с БД, которая выполняется как единое целое. Если хотя бы одна операция внутри транзакции завершится ошибкой, СУБД отменит все изменения (сделает Rollback), вернув базу к исходному безопасному состоянию.
14. **Как Django взаимодействует с реляционными базами данных?**  
    *Ответ:* Django использует технологию ORM (Object-Relational Mapping). Она автоматически преобразует классы на языке Python в таблицы БД, а методы Python — в SQL-запросы, избавляя разработчика от необходимости писать SQL-код вручную для стандартных операций.

## 10. Методические заметки (Pedagogical Notes)

### Сложные темы для усвоения и их объяснение:
*   **Связь Многие-ко-многим (N:M) и промежуточная таблица.**  
    *Проблема:* Ученики часто пытаются добавить списки или массивы идентификаторов прямо в ячейку таблицы (например, написать `1, 2, 5` в поле `club_ids`).  
    *Решение:* Объяснить, что реляционная модель требует атомарности данных (в одной ячейке — строго одно значение). Показать, что промежуточная таблица превращает сложную связь N:M в две простые связи 1:N (один ученик — много записей в связке, одна секция — много записей в связке).
*   **Разница между INNER JOIN и LEFT JOIN.**  
    *Проблема:* Путаница, какую таблицу делать левой, а какую правой, и куда пропадают данные.  
    *Аналогия с пазлом:* INNER JOIN — это соединение только тех деталей, которые идеально подошли друг к другу. LEFT JOIN — мы раскладываем на столе все левые детали и прикрепляем к ним подходящие правые. Те левые детали, к которым пара не нашлась, остаются лежать с пустым местом (NULL) на правой стороне.
*   **Логический порядок GROUP BY и HAVING.**  
    *Проблема:* Попытки написать `WHERE COUNT(id) > 2`.  
    *Методика:* Визуализировать конвейер. Сначала мы отсеиваем испорченные детали (`WHERE`), затем раскладываем оставшиеся детали по коробкам (`GROUP BY`), считаем количество деталей в каждой коробке, и в конце выкидываем коробки, где деталей слишком мало (`HAVING`).

### Дифференциация обучения:
*   **Для сильных учеников:**  
    Если ребята быстро справляются с базовыми запросами, предложите им изучить тему ограничений внешних ключей: `ON DELETE CASCADE` (автоматическое удаление дочерних записей при удалении родительской) и `ON DELETE SET NULL`. Дайте задачу на написание вложенного запроса (Subquery), например: «Найти студентов, возраст которых строго больше среднего возраста по всей школе».
*   **Для слабых учеников:**  
    Сфокусируйтесь на визуальном проектировании. Попросите их нарисовать таблицы на листе бумаги или маркерной доске, провести стрелочки от внешних ключей к первичным. В практике написания SQL ограничьте их простыми выборками без JOIN (только SELECT, WHERE, ORDER BY) до тех пор, пока они не поймут логику фильтрации строк.
