Базы данных и СУБД

База данных (БД) — это упорядоченная совокупность структурированных данных, хранящаяся в компьютерной системе.

СУБД (Система управления базами данных) — ПО для создания БД, записи, чтения и обновления данных (например, PostgreSQL, SQLite, MySQL).

Почему не обычные файлы (.json или .txt)?
  • Масштабируемость: БД работают с гигабайтами и терабайтами данных мгновенно.
  • Конкурентный доступ: тысячи пользователей могут одновременно читать и писать данные.
  • Целостность и транзакции: защита от сбоев питания и некорректных записей.

Реляционная модель: Таблицы

Слово relation переводится как «отношение». В математике отношение — это множество кортежей. В базах данных отношение представляется как таблица.

id [PK] first_name last_name age
1 Иван Иванов 15
2 Анна Петрова 16
  • Строка (Запись / Кортеж) — один конкретный объект.
  • Столбец (Поле / Атрибут) — свойство объекта.
  • Тип данных — жестко определяет, какие значения могут быть в столбце (числа, строки, даты).

Первичный ключ (Primary Key)

Первичный ключ (PK) — это уникальный идентификатор строки в таблице. Он гарантирует, что каждая запись уникальна и к ней можно обратиться напрямую.

Свойства Первичного Ключа (PK):
  1. Уникальность: в таблице не может быть двух строк с одинаковым PK.
  2. Непустота: значение PK не может быть NULL (пустым).
  3. Стабильность: PK не должен меняться со временем (например, имя или паспорт могут измениться, поэтому лучше использовать суррогатный ключ: автоинкрементное число id).

Внешний ключ (Foreign Key)

Как связать две таблицы между собой? Использовать Внешний ключ (FK)!

Внешний ключ — это столбец одной таблицы, который содержит значения первичного ключа (PK) другой таблицы. Так создаются связи (relations).

Таблица классов (classes)

id [PK] name
1 10-А
2 10-Б

Таблица учеников (students)

id [PK] name class_id [FK]
1 Иван 1 (ссылается на 10-А)
2 Анна 2 (ссылается на 10-Б)
3 Петр 1 (ссылается на 10-А)

Связь «Один ко многим» (1:N / One-to-Many)

Это самый частый тип связи. Одна запись из первой таблицы может быть связана со многими записями из второй. Но запись из второй связана ровно с одной записью из первой.

Примеры:
  • У одного Класса может быть много Учеников, но ученик учится в одном классе.
  • У одного Автора может быть много Книг, но у книги (упростим) один автор.
  • У одной Категории много Товаров.

Реализация: Внешний ключ (FK) добавляется на сторону «Многие» (в таблицу учеников, книг или товаров).

Связь «Многие ко многим» (N:M / Many-to-Many)

Одна запись из первой таблицы связана со многими из второй, и наоборот.

Пример: Один Ученик может посещать много Кружков. Один Кружок посещают много Учеников.

Реализация: Требуется промежуточная таблица-связка (Junction Table)!

students

id [PK]name
1Иван
2Анна

student_clubs (Связка)

student_id [FK]club_id [FK]
1 (Иван)101 (Физика)
1 (Иван)102 (Шахматы)
2 (Анна)101 (Физика)

clubs

id [PK]title
101Физика
102Шахматы

Связь «Один к одному» (1:1 / One-to-One)

Каждой записи из первой таблицы соответствует строго одна запись из второй таблицы.

Пример: Один Гражданин и его один Паспорт. Один Ученик и один Личный профиль здоровья.

Таблица граждан (citizens)

id [PK] name
1 Иван Иванов

Таблица паспортов (passports)

id [PK] passport_number citizen_id [FK, Unique]
10 4508 123456 1 (Иван)

Реализация: Внешний ключ (FK) помещается в любую из таблиц с ограничением уникальности (UNIQUE).

Введение в SQL

SQL (Structured Query Language) — декларативный язык структурированных запросов. Мы описываем, какой результат хотим получить, а СУБД сама решает, как его извлечь.

Основные подмножества команд SQL:
  • DQL (Data Query Language): получение данных (SELECT) — наш фокус сегодня!
  • DML (Data Manipulation Language): изменение данных (INSERT, UPDATE, DELETE)
  • DDL (Data Definition Language): описание структуры таблиц (CREATE TABLE, ALTER TABLE, DROP TABLE)

Выборка данных: SELECT и WHERE

Базовый синтаксис получения данных:

SELECT column1, column2 FROM table_name WHERE condition;

Выбрать все колонки учеников:

SELECT * FROM students;

Ученики старше 15 лет:

SELECT first_name, last_name 
FROM students 
WHERE age > 15;

В секции WHERE можно использовать операторы: =, != (или <>), <, >, AND, OR, NOT, IN (...).

Поиск по шаблону (LIKE) и проверка на NULL

Фильтрация по тексту (LIKE):

Знак % означает «ноль или более любых символов». _ означает «ровно один символ».

-- Имена, начинающиеся на 'А'
SELECT * FROM students 
WHERE first_name LIKE 'А%';

-- Фамилии, оканчивающиеся на 'ов'
SELECT * FROM students 
WHERE last_name LIKE '%ов';

Работа с пустыми значениями (NULL):

NULL — это отсутствие значения. Его нельзя сравнивать через знак =!

-- Найти учеников без указанного email
SELECT * FROM students 
WHERE email IS NULL;

-- Найти учеников, у которых есть email
SELECT * FROM students 
WHERE email IS NOT NULL;

Сортировка (ORDER BY) и Ограничение (LIMIT)

Иногда нужно отсортировать результаты или взять только верхнюю часть списка.

SELECT first_name, age FROM students
ORDER BY age DESC, first_name ASC
LIMIT 5;
Разбор конструкции:
  • ORDER BY age DESC — сортировка по возрасту по убыванию (от старших к младшим).
  • ..., first_name ASC — если возраст совпадает, сортируем по имени по возрастанию (алфавитный порядок). По умолчанию используется ASC.
  • LIMIT 5 — вернуть ровно 5 строк (например, топ-5 самых старших учеников).

Связывание таблиц: Идея JOIN

В реляционных базах данные распределены по разным таблицам для избежания дублирования. Чтобы получить сводный отчет (например, имя ученика и название его класса), нам нужно объединить эти таблицы на основе первичного и внешнего ключа.

[Таблица students]  INNER JOIN  [Таблица classes]
      (students.class_id = classes.id)

В SQL для этого служит оператор JOIN. Он сопоставляет строки из двух таблиц по заданному условию (обычно после ключевого слова ON).

INNER JOIN (Внутреннее объединение)

INNER JOIN возвращает только те записи, для которых условие связи истинно в обеих таблицах. Если у ученика нет класса, или у класса нет учеников — они не попадут в результат.

SELECT students.name, classes.name AS class_name
FROM students
INNER JOIN classes ON students.class_id = classes.id;
Результат объединения:
students.nameclass_name
Иван10-А
Анна10-Б
Петр10-А

LEFT JOIN (Внешнее левое объединение)

LEFT JOIN возвращает все записи из левой таблицы и подходящие записи из правой. Если соответствия в правой таблице нет, то значения её колонок заполняются как NULL.

-- Предположим, у нас есть ученик Сергей, у которого class_id равен NULL
SELECT students.name, classes.name AS class_name
FROM students
LEFT JOIN classes ON students.class_id = classes.id;
Результат LEFT JOIN:
students.nameclass_name
Иван10-А
Анна10-Б
СергейNULL (нет класса)

Агрегатные функции

Агрегатные функции вычисляют единое результирующее значение по набору строк.

  • COUNT(col) — количество непустых значений
  • SUM(col) — сумма значений
  • AVG(col) — среднее арифметическое
  • MIN(col) / MAX(col) — минимум / максимум
-- Средний возраст всех учеников
SELECT AVG(age) FROM students;

-- Количество учеников в школе
SELECT COUNT(*) FROM students;

-- Максимальный возраст ученика
SELECT MAX(age) FROM students;

Группировка данных: GROUP BY

Оператор GROUP BY разделяет записи таблицы на группы. Агрегатные функции затем применяются отдельно для каждой группы.

-- Посчитать количество учеников в каждом классе
SELECT class_id, COUNT(*) AS students_count
FROM students
GROUP BY class_id;
Важное правило GROUP BY:

Все колонки, которые стоят в SELECT (кроме агрегатных функций), обязательно должны быть перечислены в секции GROUP BY. Иначе СУБД выдаст ошибку целостности!

Фильтрация групп: HAVING vs WHERE

Как отфильтровать группы после расчета агрегатов? Использовать HAVING!

  • WHERE фильтрует исходные строки перед группировкой.
  • HAVING фильтрует группы после выполнения группировки и вычисления функций.
-- Найти классы, в которых средний возраст учеников больше 15 лет
SELECT class_id, AVG(age) AS avg_age
FROM students
GROUP BY class_id
HAVING AVG(age) > 15;

Порядок написания vs выполнения запроса

Порядок написания в коде:

  1. SELECT (выбор колонок)
  2. FROM (таблица)
  3. JOIN (связи)
  4. WHERE (фильтр строк)
  5. GROUP BY (группировка)
  6. HAVING (фильтр групп)
  7. ORDER BY (сортировка)
  8. LIMIT (ограничение)

Порядок выполнения внутри СУБД:

  1. FROM + JOIN (сбор данных)
  2. WHERE (фильтрация строк)
  3. GROUP BY (группировка)
  4. HAVING (фильтрация групп)
  5. SELECT (генерация колонок)
  6. ORDER BY (сортировка)
  7. LIMIT (срез)
