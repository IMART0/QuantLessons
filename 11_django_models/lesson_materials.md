*   **Цели урока:**
    1.  **Образовательные:** Изучить архитектурный слой моделей (`Models`) в Django и основы работы с СУБД (SQLite). Освоить типы полей (`CharField`, `TextField`, `IntegerField`, `DateField`, `ImageField`) и их метапараметры. Понять жизненный цикл миграций (`makemigrations` / `migrate`).     3.  **Воспитательные:** Развивать инженерную дисциплину при работе с версионированием баз данных, аккуратность при проектировании схем данных и написании чистого кода.
*   **Планируемые результаты обучения (Outcomes):**
    *   **Знать:** Концепцию ORM, отличия типов полей Django, разницу между созданием файла миграции и применением миграции, принципы работы базы SQLite, назначение системной таблицы `django_migrations`, назначение CRUD.
    *   **Уметь:** Создавать Django-модели для сущностей «Событие», «Новость» и «Расписание» с корректными типами полей; генерировать и выполнять миграции; запускать `Django shell` и выполнять запросы выборки, фильтрации, изменения и удаления данных с помощью ORM; настраивать отображение объектов через `__str__` и сортировку через `class Meta`.
    *   **Владеть:** Навыками решения типичных проблем при работе с БД (обработка исключений `DoesNotExist`, `MultipleObjectsReturned`, решение конфликтов пропущенных миграций).
*   **Требования к подготовке (Prerequisites):**

    *   Понимание структуры проекта Django и MTV-архитектуры.

### Концепция ORM и Django Models (Слайды 3–10)
*   **Преподаватель:** «Обычно для общения с базами данных используется язык SQL. Но писать SQL-запросы внутри кода на Python — долго, неудобно и небезопасно. Django решает эту проблему с помощью ORM (Слайд 3).
    Слайд 4 демонстрирует главную магию ORM. Она сопоставляет понятия из мира БД с понятиями из мира Python. Таблица в БД превращается в класс Python, колонка — в поле этого класса, а строка таблицы с конкретными данными — в объект этого класса.
    Давайте посмотрим на Слайд 6. Мы объявляем класс `News`, который наследуется от `models.Model`. Запомните: без наследования от `models.Model` Django не поймет, что этот класс нужно превратить в таблицу в нашей базе данных.
    На Слайдах 7, 8 и 9 описаны основные типы полей. Обратите внимание на `max_length` у `CharField`. СУБД SQLite должна заранее знать, сколько памяти зарезервировать под строку на диске, поэтому ограничение длины обязательно. Для длинных текстов, где лимит не нужен, мы берем `TextField`.

Запомните, ребята: сама картинка физически загружается в папку на диске (которую мы укажем в параметре `upload_to`), а в базу данных записывается только путь к этому файлу. Для работы `ImageField` нам обязательно нужно установить библиотеку Pillow. Если при запуске сервера вы увидите ошибку, связанную с изображениями, первым делом пишите в консоли `pip install Pillow`.»

### Механизм миграций (Слайды 15–18)
*   **Преподаватель:** «Ребята, сейчас я произнесу фразу, которую вы должны запомнить на всю жизнь: **изменение кода в файле `models.py` не меняет базу данных автоматически!**
    Если вы просто напишете класс модели и обновите сайт, Django выдаст ошибку `OperationalError: no such table`. База данных на диске еще ничего не знает о ваших классах. Чтобы синхронизировать код и БД, используются миграции (Слайд 15).
    Миграция — это файл на Python, содержащий подробную инструкцию по изменению таблиц.
    Этот процесс состоит из двух шагов:
    Шаг 1: Мы запускаем команду `python manage.py makemigrations` (Слайд 16). Django сравнивает наши классы с текущей структурой БД и генерирует файл-чертеж в папке `migrations` (например, `0001_initial.py`). База данных на этом шаге еще НЕ изменилась.
    Шаг 2: Мы запускаем команду `python manage.py migrate` (Слайд 17). Django берет файл-чертеж, переводит его инструкции в SQL-код и физически создает таблицы в файле `db.sqlite3`.
    *Вопрос к классу:* Как Django понимает, что миграция уже была применена и её не нужно запускать второй раз?
    *Ответ:* В базе данных есть системная таблица `django_migrations`, в которую записывается имя каждого примененного файла. Если имя файла там есть, Django его пропускает.»

### CRUD операции в Django Shell (Слайды 19–27)
*   **Преподаватель:** «Теперь давайте научимся управлять нашими данными. Запустим интерактивную консоль Django с помощью команды `python manage.py shell` (Слайд 19).
    *Внимание:* обычный вызов `python` в консоли выдаст ошибку при импорте моделей, так как он не инициализирует настройки Django. Консоль `manage.py shell` делает это автоматически.
    Давайте разберем операции CRUD (Create, Read, Update, Delete).
    **Create (Создание)** — Слайд 20. Первый способ: создаем объект в памяти `event = Event(...)` и затем пишем `event.save()`. До вызова `.save()` данных в БД нет. Второй способ: `Event.objects.create(...)`. Запись создается в БД мгновенно и сразу возвращает нам объект с заполненным `id`.
    **Read (Чтение)** — Слайды 21–23. Чтобы прочитать данные, мы используем менеджер `objects`.
    `News.objects.all()` — возвращает все новости.
    `News.objects.filter(created_at="2026-06-30")` — возвращает новости за конкретный день.
    `News.objects.exclude(...)` — исключает записи по условию.
    *Важный момент:* Эти методы возвращают коллекцию `QuerySet` (похожую на список Python). Но если нам нужен один конкретный объект по его уникальному `id`, мы пишем `News.objects.get(id=1)`. Метод `.get()` возвращает сам объект.
    *Предупреждение:* Если объекта с таким `id` не существует, возникнет критическая ошибка `DoesNotExist`. Если под условие попадет несколько объектов, упадет ошибка `MultipleObjectsReturned`. Поэтому используйте `.get()` только для уникальных полей!
    Для сложной фильтрации (Слайд 23) мы используем двойное подчеркивание `__`. Например, поиск подстроки без учета регистра: `title__icontains="физика"`. Сравнение: `classroom__gt=300` (номер кабинета больше 300).
    **Update (Обновление)** — Слайд 24. Мы можем получить один объект через `.get()`, изменить его атрибут и вызвать `.save()`. Либо сделать массовое обновление: `Schedule.objects.filter(classroom=101).update(classroom=202)`.
    **Delete (Удаление)** — Слайд 25. Метод `.delete()` удаляет записи. Помните: вызов `Event.objects.all().delete()` очистит всю таблицу. Будьте предельно осторожны!
    На Слайде 26 показана магия метода `__str__`. Переопределяя его, мы заставляем Django выводить понятное описание объекта (например, дату и заголовок новости) вместо стандартного `News object (1)` в консоли и админке. Это сильно упрощает отладку кода.»

### 2. Реализация моделей в `camp/models.py`
Полный листинг кода файла описания моделей:

```python
from django.db import models

class Event(models.Model):
    title = models.CharField(max_length=200, verbose_name="Название события")
    description = models.TextField(verbose_name="Описание события")
    date = models.DateField(verbose_name="Дата проведения")
    start_time = models.CharField(max_length=5, verbose_name="Время начала")
    cover = models.ImageField(upload_to='events/', blank=True, null=True, verbose_name="Обложка")

    def __str__(self):
        return f"{self.date} | {self.start_time} - {self.title}"

    class Meta:
        verbose_name = "Событие"
        verbose_name_plural = "События"
        ordering = ['date', 'start_time']


class News(models.Model):
    title = models.CharField(max_length=200, verbose_name="Заголовок новости")
    content = models.TextField(verbose_name="Текст новости")
    created_at = models.DateField(auto_now_add=True, verbose_name="Дата публикации")
    image = models.ImageField(upload_to='news/', blank=True, null=True, verbose_name="Изображение")

    def __str__(self):
        return f"{self.created_at} | {self.title}"

    class Meta:
        verbose_name = "Новость"
        verbose_name_plural = "Новости"
        ordering = ['-created_at']


class Schedule(models.Model):
    date = models.DateField(verbose_name="Дата занятий")
    time_slot = models.CharField(max_length=50, verbose_name="Временной интервал")
    classroom = models.IntegerField(verbose_name="Номер кабинета")

    def __str__(self):
        return f"{self.date} | {self.time_slot} (Каб. {self.classroom})"

    class Meta:
        verbose_name = "Занятие"
        verbose_name_plural = "Расписание занятий"
        ordering = ['date', 'time_slot']
```

#### Построчный разбор кода `camp/models.py`:
*   **Строка 1:** Импортируется базовый модуль `models` из состава Django ORM.
*   **Строки 3–14 (Модель `Event`):**
    *   `title`: строковое поле `CharField` с ограничением длины в 200 символов.
    *   `description`: неограниченное текстовое поле `TextField` для подробной программы мероприятия.
    *   `date`: поле даты `DateField`.
    *   `start_time`: строковое поле `CharField` длиной 5 символов для хранения времени в формате `ЧЧ:ММ` (например, `"10:00"`).
    *   `cover`: поле изображения `ImageField`. Указывает папку сохранения `events/` внутри медиа-директории. Параметры `blank=True` и `null=True` позволяют создавать события без обложки.
    *   Метод `__str__`: возвращает строку формата `ГГГГ-ММ-ДД | ЧЧ:ММ - Название` для удобства чтения в логах и админке.
    *   `class Meta`: определяет человекочитаемые названия модели в единственном и множественном числах, а также настраивает автоматическую сортировку по дате и времени.
*   **Строки 17–28 (Модель `News`):**
    *   `created_at`: поле даты с параметром `auto_now_add=True`, который заставляет Django автоматически фиксировать текущую дату сервера при создании новости.
    *   `class Meta` с `ordering = ['-created_at']`: сортирует новости в обратном порядке (самые свежие новости будут находиться в начале списка).

### Задание 2 (Базовое): Объявление моделей News и Schedule
**Описание задания:** Напишите в `camp/models.py` классы моделей `News` (Новости) и `Schedule` (Расписание занятий) в соответствии с требованиями проекта «Квант».
*   **Входные данные:** 
    *   `News`: заголовок `title` (до 200 символов), текст `content` (длинный текст), дата публикации `created_at` (заполняется автоматически), картинка `image` (загрузка в `news/`, может отсутствовать). Сортировка по убыванию даты публикации.
    *   `Schedule`: дата занятий `date` (дата), временной интервал `time_slot` (строка до 50 символов), кабинет `classroom` (целое число). Сортировка по дате, а затем по временному интервалу.
*   **Ожидаемый результат (Выходные данные):** Два готовых Python-класса в файле `models.py`.
*   **Подсказка:** Для автоматического проставления даты используйте параметр `auto_now_add=True`. Обратите внимание на правильный тип для кабинета — `IntegerField`.
*   **Решение:**
```python
class News(models.Model):
    title = models.CharField(max_length=200, verbose_name="Заголовок")
    content = models.TextField(verbose_name="Текст новости")
    created_at = models.DateField(auto_now_add=True, verbose_name="Дата публикации")
    image = models.ImageField(upload_to='news/', blank=True, null=True, verbose_name="Изображение")

    def __str__(self):
        return f"{self.created_at} | {self.title}"

    class Meta:
        verbose_name = "Новость"
        verbose_name_plural = "Новости"
        ordering = ['-created_at']

class Schedule(models.Model):
    date = models.DateField(verbose_name="Дата занятий")
    time_slot = models.CharField(max_length=50, verbose_name="Временной интервал")
    classroom = models.IntegerField(verbose_name="Номер кабинета")

    def __str__(self):
        return f"{self.date} | {self.time_slot} (Каб. {self.classroom})"

    class Meta:
        verbose_name = "Занятие"
        verbose_name_plural = "Расписание занятий"
        ordering = ['date', 'time_slot']
```
*   **Объяснение решения:** Для модели `News` параметр `ordering = ['-created_at']` обеспечивает отображение свежих новостей сверху благодаря знаку минус. ## 9. Часто задаваемые вопросы (FAQs)

### 1. Что произойдет, если я изменю файл models.py, но забуду выполнить makemigrations и migrate?
Вы получите ошибку `OperationalError` или `ProgrammingError` при первой же попытке Django обратиться к этой таблице (например, в админке или во view). Django будет пытаться запросить несуществующие колонки или таблицы, которых на самом деле нет в файле базы данных SQLite.

### 2. Почему Django требует указывать параметр max_length для CharField, но не требует для TextField?
`CharField` транслируется в SQL-тип `VARCHAR(N)`. Базам данных (таким как PostgreSQL, MySQL) необходимо заранее знать максимальную длину строки для эффективного выделения памяти на диске и построения индексов. `TextField` транслируется в тип `TEXT` (или `CLOB`), который хранит данные динамической длины в отдельных сегментах памяти, поэтому жесткий лимит для него на уровне БД не требуется.

### 3. В чем разница между null=True и blank=True?
*   `null=True` настраивает **базу данных**. Оно указывает СУБД, что колонка может принимать пустое значение `NULL` (отсутствие данных).
*   `blank=True` настраивает **валидацию форм Django**. Оно говорит интерфейсу админки или формам на сайте, что поле не является обязательным для заполнения, и пользователь может отправить пустую форму.
*   *Рекомендация:* Для строковых полей (`CharField`, `TextField`) в Django принято использовать `blank=True` без `null=True`, так как Django по умолчанию сохраняет пустые строки как пустые строки `""`, а не `NULL`.

### 4. Почему при запуске python manage.py shell обычные python-файлы не видят мои модели?
Обычный интерпретатор Python не знает, где находятся файлы конфигурации вашего Django-проекта (`settings.py`), и какие приложения подключены. Команда `python manage.py shell` считывает переменную окружения `DJANGO_SETTINGS_MODULE` и инициализирует все внутренние службы Django, подключаясь к базе данных.

### 5. Можно ли редактировать файлы миграций в папке migrations вручную?
Вручную редактировать файлы миграций крайне не рекомендуется, особенно новичкам. Django автоматически управляет ими. Неправильное изменение кода миграции может навсегда рассинхронизировать вашу базу данных с кодом моделей, из-за чего придется удалять файл БД и пересоздавать все миграции с нуля.

### 6. Где физически хранятся загружаемые файлы картинок для ImageField?
Картинки сохраняются в файловой системе сервера в папку, указанную в параметре `upload_to` (например, `media/news/`). В самой базе данных в соответствующей ячейке хранится только текстовый путь к файлу (например, `"news/my_photo.jpg"`). Путь к медиа-папке настраивается в файле `settings.py` с помощью переменных `MEDIA_URL` и `MEDIA_ROOT`.

### 7. Почему при поиске по __icontains с русскими буквами в SQLite регистр букв не игнорируется?
Это известное ограничение стандартной сборки СУБД SQLite. По умолчанию SQLite поддерживает нечувствительность к регистру (функции `UPPER`/`LOWER`) только для символов ASCII (латиницы). Для поддержки кириллицы требуются внешние расширения (например, ICU). В реальных проектах на продакшене используется СУБД PostgreSQL, в которой эта проблема отсутствует и `__icontains` отлично работает с любыми языками. На уроке мы можем продемонстрировать это на латинских названиях или объяснить это ограничение ученикам.

### 8. В чем разница между auto_now_add=True и auto_now=True?
*   `auto_now_add=True` сохраняет дату/время **только один раз** — в момент создания записи в базе данных. В дальнейшем при редактировании объекта это поле меняться не будет. Идеально для даты публикации новости или даты создания аккаунта.
*   `auto_now=True` обновляет дату/время **каждый раз**, когда объект сохраняется в базе данных (вызывается метод `save()`). Идеально подходит для отслеживания времени последнего изменения записи (например, "Новость отредактирована: 5 минут назад").

### 9. Что делать, если при вызове .get() возникает ошибка MultipleObjectsReturned?
Это означает, что по вашему запросу найдено более одного объекта, хотя метод `.get()` спроектирован так, чтобы возвращать строго одну запись.
*   *Решение:* Если вам нужны все подходящие объекты, замените `.get(...)` на `.filter(...)`. Если вам нужен только самый первый объект из списка, используйте `.filter(...).first()`.

### 10. Как отменить последнюю примененную миграцию?
Вы можете «откатить» базу данных к состоянию определенной миграции, указав её номер в команде `migrate`. Например, чтобы отменить все миграции приложения `camp` после первой миграции, выполните:
`python manage.py migrate camp 0001`
Для полной отмены всех миграций приложения `camp` введите:
`python manage.py migrate camp zero`

### 11. Можно ли переименовать поле в модели после того, как миграции уже применены?
Да. Вы меняете имя поля в файле `models.py` (например, с `classroom` на `room`). Затем запускаете `python manage.py makemigrations`. Django заметит изменение и интерактивно спросит вас в консоли: *"Did you rename schedule.classroom to schedule.room? [y/N]"*. Нажмите `y` (yes). Django сгенерирует файл миграции переименования, после чего примените его командой `python manage.py migrate`.

### 12. Зачем нужен менеджер objects?
Менеджер `objects` (экземпляр класса `django.db.models.Manager`) — это входная точка для любых запросов к базе данных из Python. Он отвечает за построение объектов `QuerySet` и предоставляет методы API (такие как `all()`, `filter()`, `create()`, `get()`). Вы можете переопределять менеджеры для создания кастомных фильтров по умолчанию.

### 13. Что такое ленивые запросы (Lazy QuerySets) в Django?
Django ORM выполняет запросы к базе данных лениво (Lazy Evaluation). Это означает, что строка `news = News.objects.all()` на самом деле **не делает** никаких запросов к базе данных SQLite. Запрос к БД выполнится только тогда, когда вам действительно понадобятся данные: например, при итерации в цикле `for item in news:`, при обращении по индексу `news[0]`, при вызове `len(news)` или при принудительном преобразовании в список `list(news)`. Это оптимизирует производительность веб-приложений.

### 14. Как отсортировать данные в обратном порядке при использовании order_by?
Для сортировки по убыванию добавьте символ минус перед именем поля.
Например, `Schedule.objects.order_by('-classroom')` отсортирует расписание от больших номеров кабинетов к меньшим.

### 15. Почему при вызове метода delete() на объекте удаляются связанные картинки с диска?
На самом деле, по умолчанию в Django 3.0+ метод `.delete()` на модели **не удаляет** физические файлы изображений с диска сервера (из соображений безопасности и предотвращения случайной потери данных). В базе данных строка с путем удаляется, но сам файл остается в папке `media/`. Чтобы физически удалять файлы при удалении объектов, разработчики используют сигналы (`post_delete`) или сторонние библиотеки, такие как `django-cleanup`.

## 10. Методические заметки (Pedagogical Notes)

### 1. Трудные концепции и барьеры для понимания
*   **Синхронизация кода и БД (Миграции):** Самая частая проблема учеников — непонимание того, почему изменения в `models.py` не появляются на сайте сразу. Ученики часто забывают запустить `makemigrations` или `migrate`. 
    *Методический прием:* Нарисуйте на доске схему: *«Код (Чертеж дома) &rarr; Файл миграции (Инструкция для строителей) &rarr; СУБД SQLite (Готовый построенный дом)»*. Покажите, что без команды `migrate` строители не начнут перестраивать стены.
*   **Разница между QuerySet и объектом:** Ученики путают типы данных и пытаются вызвать атрибуты конкретного объекта (например, `.title`) на коллекции `QuerySet`, получая ошибку `'QuerySet' object has no attribute 'title'`.
    *Методический прием:* Объясните, что `filter()` всегда возвращает «коробку» (QuerySet), даже если внутри лежит всего один объект или коробка пуста. Чтобы достать вещь из коробки, нужно обратиться по индексу `[0]`, использовать цикл `for` или применить метод `get()`, который сразу возвращает саму вещь без коробки.

### 2. Рекомендуемые аналогии
*   **ORM как Переводчик:** База данных разговаривает на SQL (китайском языке), а Python — на русском. ORM — это профессиональный переводчик-синхронист, который автоматически переводит наши Python-команды на язык понятный СУБД, избавляя нас от необходимости учить иностранный язык на первых порах.
*   **Таблица как класс, а строка как объект:** Проведите аналогию с формочкой для выпечки печенья. Класс модели в `models.py` — это формочка (определяет очертания, размер, узоры). Каждое готовое печенье, выпеченное по этой форме — это строка в базе данных (конкретный объект со своим вкусом, цветом, весом).

### 3. Стратегии дифференциации обучения

*   **Для слабых учеников:**
    *   Фокусироваться исключительно на втором способе создания записей: `objects.create()`, так как он более лаконичен и не требует помнить про `.save()`.
    *   Предоставить готовую шпаргалку по командам терминала и типам полей.
    *   При возникновении ошибок с миграциями разрешить им удалить файл `db.sqlite3` и папку `migrations` и запустить команды заново (это допустимо на этапе обучения, пока в БД нет ценных пользовательских данных).

*   **Для сильных учеников (физико-математический профиль):**
    *   Предложить задание со звездочкой по автоматическому импорту данных из JSON. Это развивает навыки интеграции систем и работы с файловой системой.
    *   Объяснить концепцию «ленивых запросов» (Lazy QuerySets) и продемонстрировать с помощью пакета `django-debug-toolbar` или логирования SQL-запросов, в какой именно момент Python отправляет запрос в SQLite.
    *   Познакомить с понятием ограничений базы данных (Database Constraints), например `unique=True` (уникальность значения поля) или `db_index=True` (индексация для ускорения O(log N) поиска).
