Проблема: Как хранить данные?

В реальных веб-приложениях данные пользователей, товаров, постов и настроек нужно где-то хранить. Почему не подходят обычные файлы (TXT, JSON)?

  • Медленно: Чтение файла в 1 ГБ целиком ради одной строки займет много секунд.
  • Небезопасно: При одновременной записи от двух пользователей файл может повредиться.
  • Сложно: Трудный поиск взаимосвязей (например, "найти комментарии пользователя №5").
Решение: СУБД (Системы управления базами данных)

Специальные программы для быстрого, безопасного и надежного хранения структурированной информации. Мы используем SQLite — легкую БД, которая хранит все данные в одном файле внутри проекта.

Что такое ORM?

Обычно для общения с реляционными базами данных используется язык SQL. Но в Django мы работаем через ORM.

ORM (Object-Relational Mapping) — технология, которая связывает таблицы базы данных с объектами в объектно-ориентированном языке программирования (в нашем случае — Python).
В Базе Данных (SQL) В Django (Python)
Таблица (Table) Класс модели (Class наследник models.Model)
Столбец / Колонка (Column) Поле модели (Атрибут класса, например CharField)
Строка таблицы / Запись (Row) Объект / Экземпляр класса модели (Instance)

Преимущества ORM

  • Не пишем SQL руками: Код пишется исключительно на чистом Python, что уменьшает количество ошибок и опечаток.
  • Безопасность (SQL Injection): Django ORM автоматически экранирует все входящие данные, защищая проект от хакерских атак через поля ввода.
  • Независимость от СУБД (Портативность): Код моделей одинаков для SQLite, PostgreSQL, MySQL или Oracle. Достаточно сменить настройки в settings.py!
Пример запроса:

# SQL:
SELECT * FROM articles WHERE status = 'published';

# Django ORM:
Article.objects.filter(status='published')

Создание модели в Django

Каждая модель описывается как класс Python в файле models.py вашего Django-приложения и наследуется от django.db.models.Model.

from django.db import models

class Article(models.Model):
    title = models.CharField(max_length=200)
    content = models.TextField()
    views_count = models.IntegerField(default=0)
    is_published = models.BooleanField(default=True)
    created_at = models.DateTimeField(auto_now_add=True)

Каждая переменная внутри класса определяет колонку таблицы базы данных. Типы полей определяют тип данных, которые могут там храниться.

Основные типы полей (Model Fields)

Django предоставляет десятки типов полей для разных видов данных. Вот самые частые:

  • CharField(max_length=...) — короткая строка (обязательно указывать лимит длины).
  • TextField() — длинный текст (для статей, комментариев, описаний).
  • IntegerField() и FloatField() — целые и вещественные числа.
  • BooleanField() — логическое значение (True/False). Удобно с параметром default.
  • DateTimeField() и DateField() — дата и время.
  • EmailField() — строка с автоматической валидацией формата email на уровне Django.

Параметры полей (Field Arguments)

Параметры полей позволяют гибко настраивать валидацию и структуру БД:

Параметр Описание Пример
default Значение по умолчанию для поля при создании записи default=0 или default='Черновик'
null Разрешает хранить пустое значение (NULL) на уровне базы данных null=True (по умолчанию False)
blank Разрешает оставлять поле пустым при валидации форм (например, в админке) blank=True (по умолчанию False)
verbose_name Человекочитаемое название поля (будет показано в админке) verbose_name="Заголовок статьи"

Что такое миграции?

Когда вы создаете класс в models.py или меняете его (добавляете/удаляете поле), база данных об этом ничего не знает. Нам нужно передать эти изменения в БД.

Миграции — это файлы-чертежи (инструкции), в которых зафиксирована история изменений ваших моделей. Они выполняют роль системы контроля версий для базы данных.

Создание миграций: makemigrations

После изменения моделей выполняем консольную команду:

python manage.py makemigrations

Django анализирует файлы models.py, сравнивает их с предыдущим состоянием и создает новый файл Python-скрипта в папке migrations/ внутри приложения (например, 0001_initial.py).

Что внутри файла миграции?
Декларативное описание изменений. Не редактируйте эти файлы вручную без крайней необходимости! Django сам полностью контролирует их генерацию.

Применение миграций: migrate

Чтобы изменения действительно применились и таблицы создались/изменились в базе данных, введите:

python manage.py migrate

Django считывает файлы миграций, которые еще не были применены, транслирует их в SQL-запросы к вашей СУБД и выполняет их.

Как Django помнит, что применено?
В вашей базе данных есть специальная системная таблица django_migrations. В ней Django отмечает названия файлов миграций, которые уже применены, чтобы не запускать их повторно.

База данных под капотом

Как Django преобразует имена моделей в имена таблиц?

  • Имя таблицы по умолчанию составляется как: имя_приложения_имя_модели_в_нижнем_регистре.
  • Например, если приложение называется blog, а модель — Article, то таблица в БД будет иметь имя blog_article.
  • Django автоматически добавляет автоинкрементное целочисленное поле id в качестве первичного ключа (Primary Key), если вы не указали другое поле с параметром primary_key=True.
Важно: При переименовании полей или моделей всегда делайте коммит в Git до и после выполнения миграций, чтобы не запутаться в версиях структуры БД!

Django Shell — интерактивная консоль

Чтобы быстро поработать с моделями, протестировать запросы или импортировать данные, обычный интерактивный Python REPL не подойдет, так как он не знает о настройках Django.

Для запуска консоли в контексте Django используйте специальную команду:

python manage.py shell
Перед началом работы с моделями в консоли их нужно импортировать:
from blog.models import Article

Любые CRUD-операции, сделанные здесь, мгновенно отражаются в реальной базе данных проекта.

CRUD: Create (Создание записей)

Есть два основных способа создать запись в базе данных:

Способ 1: Сначала в памяти, затем сохранение 
# Создаем экземпляр в памяти
art = Article(title="Привет!", content="Текст")
# Сохраняем в БД
art.save()
Способ 2: В одно действие (через Manager) 
# Сразу сохраняется в БД
art = Article.objects.create(
    title="Привет!", 
    content="Текст"
)
Метод create() возвращает уже сохраненный объект, у которого заполнен атрибут id.

CRUD: Read (Чтение данных) — Поиск и выборка

Для чтения записей используется специальный менеджер objects, который возвращает коллекцию QuerySet:

  • Получить все записи: 
    all_articles = Article.objects.all() # Возвращает QuerySet
  • Фильтрация (выборка по критерию): 
    pub_articles = Article.objects.filter(is_published=True)
  • Исключение (выбрать все, кроме): 
    not_pub_articles = Article.objects.exclude(is_published=True)

CRUD: Read — Получение одной записи и сортировка

Получение одного объекта: .get() 
# Возвращает конкретный объект, а не QuerySet
art = Article.objects.get(id=1)

Если объект не найден, выбрасывается исключение DoesNotExist. Если найдено больше одного — MultipleObjectsReturned.

Сортировка: .order_by() 
# По возрастанию даты
Article.objects.order_by('created_at')

# По убыванию (знак минус)
Article.objects.order_by('-views_count')

Field Lookups (Сложная фильтрация)

Для сравнения значений полей Django использует синтаксис с двойным подчеркиванием __:

  • Поиск подстроки (LIKE): __contains (чувствительно к регистру) и __icontains (нечувствительно к регистру) 
    Article.objects.filter(title__icontains="python")
  • Сравнения: __gt (больше), __gte (больше или равно), __lt (меньше), __lte (меньше или равно) 
    Article.objects.filter(views_count__gte=100)
  • Вхождение в список: __in 
    Article.objects.filter(id__in=[1, 3, 5])

CRUD: Update (Обновление записей)

Как и в случае с созданием, обновить данные можно двумя способами:

Способ 1: У одного объекта 
art = Article.objects.get(id=1)
art.views_count += 1
art.save() # Сохраняет только этот объект

Обратите внимание: вызывается метод save().

Способ 2: Массовое обновление (на QuerySet) 
# Обновит просмотры у ВСЕХ опубликованных
Article.objects.filter(
    is_published=True
).update(views_count=100)

Метод update() выполняется за один SQL-запрос UPDATE к БД.

CRUD: Delete (Удаление записей)

Удалить данные из базы можно как у одиночного объекта, так и у целой выборки (QuerySet):

Удаление одного объекта: 
art = Article.objects.get(id=1)
art.delete() # Удалит запись из БД
Массовое удаление (QuerySet): 
# Удалит все неопубликованные статьи
Article.objects.filter(
    is_published=False
).delete()
Будьте осторожны! Вызов метода .delete() на Article.objects.all().delete() удалит вообще все записи из таблицы. Это действие необратимо!

Магия метода __str__ и класс Meta

По умолчанию при печати объекта в консоли или отображении в админке Django вы увидите малоинформативное <Article: Article object (1)>.

Чтобы исправить это, переопределите метод __str__() и используйте внутренний класс Meta:

class Article(models.Model):
    title = models.CharField(max_length=200, verbose_name="Заголовок")
    
    def __str__(self):
        return f"{self.id} | {self.title}"

    class Meta:
        verbose_name = "Статья"
        verbose_name_plural = "Статьи"
        ordering = ['-created_at'] # Сортировка по умолчанию

Резюме и план практики

Чек-лист создания модели:

  1. Описать класс в models.py, унаследовать от models.Model.
  2. Добавить поля (CharField, TextField и др.) и настройки.
  3. Определить метод __str__ и `class Meta`.
  4. Выполнить makemigrations.
  5. Выполнить migrate.
